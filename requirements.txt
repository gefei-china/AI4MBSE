# ── 2026-09-21：OCR 兜底（扫描版 PDF / 图片），破铁律 4 的第 1 次例外 ──
# 背景：knowledge_pipeline/extract.py 对图片返回 46 字符占位串，该串非空 → 通过 ingest 的
#      空值守卫 → 照常分块入库**污染向量库**（且 parse_status='completed'，数据上查不出）；
#       扫描版 PDF 抽 0 字直接判 failed 且不给原因。前端 index.html 上传区已承诺「需 OCR」，
#       docs/需求符合性核查-20260921.md 将其定为 ★ 级需求缺口（FR-UI-1 图像输入未实现）。
# 选型：rapidocr-onnxruntime（PP-OCRv3 模型的 ONNX 版）——
#       · **模型内置包内**（det 2.4M + rec 11M + cls 0.57M），**零网络下载**，加载 0.28s
#       · 纯 ONNX Runtime CPU 推理，**无 torch / 无 paddle**（PaddleOCR 需 paddlepaddle，
#         对 Python 3.13 支持差、wheel 巨大，故不选）
#       · 授权 Apache-2.0（onnxruntime MIT / opencv Apache-2.0）→ 可商用私有化
#       · PDF→位图渲染复用**既有依赖** pypdfium2 + pillow，这部分零新增
# 实测（2026-09-21，本机）：中英数符号混排识别置信度 0.79~0.92；
#       OCR 1.4~4.7 s/页 vs 文本层 0.01~0.06 s/页 → **慢 50~200 倍**
#       → 故 extract.py 只对**文本层稀疏的页**补 OCR（extract.ocr_min_chars_per_page，默认 100），
#         **绝不可无差别全量 OCR**（691 页规范全跑要 30~50 分钟）。
# 体积：约 10 条 / 140 MB（已用 opencv-python-headless 替代 opencv-python，省约 70MB）。
# ⚠️ pip 会提示 "rapidocr-onnxruntime requires opencv-python>=4.5.1.48, which is not installed"
#    —— 这是**预期**的：我们用 headless 版替代，cv2 模块功能完整（仅缺 GUI 函数），
#    故 rapidocr 以 --no-deps 安装、其依赖手工显式列出。请勿为消警而改装完整版 opencv-python。
# 回退开关：config 的 extract.ocr_enabled=false → 完全回到改动前行为（A/B 对比用）。
