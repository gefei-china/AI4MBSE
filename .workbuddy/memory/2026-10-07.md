### 实施中实测发现并修掉的 4 个真问题（原方案未预见）
1. **`[:300]` 截断**：主 Agent prompt 补齐后 1354 B，300 字截断把规则 3（生成≠校验）/
   5（不虚构能力）/6（路由约束）整段切掉 —— 恰是最需要的那几条。
2. **通用词与专有词同价**：`生成需求视图` 中「需求」(2字) 与「需求视图」(4字) 同价 →
   top1 领先不足 60% → 白扔一次 LLM。改**按长度加权**（特异性加权）。
3. **词法强命中抢占编排**：`…参数变更影响分析，输出影响报告` 被抢先判为单成员直行
   （明显两交付物）→ 新增档⓪。
4. **多交付物正则误伤单一交付物**：`请生成一份…分析报告` 中「分析报告」是一个**词组**，
   被 `(设计|分析).{0,8}(报告|评审)` 误判 → 改 `(设计|分析)[^报评]{1,10}(报告|评审)`。

## 本次踩的坑（复用价值高）
1. **假 LLM 必须返回真实 `llm_client` 契约** `{'choices':[{'message':{'content':..}}]}`。
   第一版返回对象导致 `resp.get` 抛 AttributeError 被兜底吞掉，三条容错路径行为完全相同 ——
   探针没打到真实路径，差点得出"容错无效"的错误结论。
2. **变异自证断言方向**：应断言「变异后行为确实变了」，不是「变异后行为仍正确」。
   我第一版反了，变异生效反而判红。
3. **变异用的 query 必须只命中被变异那条正则**：`先做需求分析然后汇总输出` 同时命中
   `先.{0,8}(再|然后|接着)`，变异掉另一条仍命中 ⇒ 假不红。改用 `然后汇总输出`。
4. **断言查源码时先看真实写法**：`team_prompt=` 实际是 `_kw["team_prompt"]` + `**_kw`；
   `[:300]` 只存在于注释里（断言需先剥注释）。
