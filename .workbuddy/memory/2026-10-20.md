# Task #43 观测性 trace（span 树）落地完成（2026-10-20 晚）

## 五层结构
1. `database/schema.py`：新表 `orch_run_spans`（kind=run/plan/task/summary/
   reflection/views 六类，parent_id 父子链）+ 两索引。CREATE TABLE IF NOT EXISTS
   覆盖新老库，无补列迁移。
2. `services/orch_span.py`：SpanCollector（线程安全内存收集 → 流尾一次 flush，
   父先于子故 parent 映射成立；未闭合自动 error+note=unclosed_at_flush）+ run_trace
   （树形 + by_kind/tasks 成本聚合；空批次 200+note）。
3. `agent/pipeline_parts/stream.py`：六类插桩 + 包装层 `_stream_orchestrated_traced`。
   **body 保留原名 `_stream_orchestrated_flow`**（三门禁按名断言它，改名=一次破三门禁）；
   body 加 `_spans=None` 参数，None 时插桩全退化 no-op。
4. `routers/orchestration.py`：`GET /runs/{id}/trace`，过 `_own_run` 归属门。
5. 前端：编排卡「⏱ 执行轨迹」按钮 + orchTracePanel/orchTraceHtml 递归树渲染。

## 关键设计决策
- **内存收集→流尾 flush**：插桩点跨 worker/主线程，随开随写遇 sqlite 跨线程/写锁；
  代价是流尾前崩溃丢整树（与 stream_events 内存缓冲同款取舍）。
- **latency 口径**：time.monotonic() 差值（Python 侧算），不做 SQL julianday。
- **status vs meta**：span status=步骤是否正常完成；业务三态（agg_status/score/passed）
  进 meta_json。
- **观测旁路铁律**：所有 span 操作 try 包裹；总开关 core.config("orch_span","enabled")
  默认 True，关闭时全链路零开销。
