议题 1 · 资料库：从「平铺列表」到「目录树 + 元数据 + 智能视图」

现状（代码核实）

四个"没有"：没有层级、没有分页、没有搜索过滤、元数据全空（8 条真实文档分类/版本/块数均为空或 0）。文档量一过百，此页即失效。

目标 IA（双轨组织）

双轨分工：目录树回答"文件放在哪"（唯一归属），元数据回答"这类文件有哪些"（可多值），智能视图回答"现在有什么要处理"。

线框 A · 资料库主界面（目录树 + 列表 + 详情）

三处关键新增：① 列表新增「所属目录」列与面包屑（位置可见）② 顶部批量条（勾选后出现，搬 8 条文档比逐条拖拽快得多）③ 智能视图常驻（未归类/未入库/解析失败/未分类 → 待办收口）。

线框 B · 目录操作与上传落点

设计取舍（三条硬约束）

约束做法理由
物理存储不动目录只存数据库，`uploads/` 维持扁平命名不触发重解析/重向量化，零丢失风险，目录可随时重构
迁移零风险8 条存量文档 `folder_id = NULL` → 自动落入「未归类」不自动猜目录，避免制造新混乱
删除不级联删目录只回退位置，不删文档文档是重资产，目录只是视图
反模式预警：纯文件夹层级会让用户"不知道该放哪"（同一份"退换货流程"放客服还是售后？）。因此目录必须与元数据标签并行 —— 目录便于"人找"，元数据负责"机器过滤"。

线框 C · 导航侧工程入口 + 切换浮层

共用同一个切换浮层组件 —— 作用域在任意页面都可见、可切。 入口从「能力中心 → 工具与MCP → 智源连接器 → 检测连接」4 层深，提到 1 层直达。
形态选择：导航项常驻显示当前工程名（而非泛化的"项目"二字），点击即切换 —— 对齐 ChatGPT/Claude 的"作用域始终可见"原则。

线框 D · 工程中心页（管理面）+ 隔离策略

隔离策略：分层，不一刀切

资产策略理由
会话强隔离 P0串号是缺陷；且列已就绪
资料库文档/目录目录可挂工程，允许共享目录型号间引用同一份国标是常态
本体 / 术语词典默认共享，不隔离本体是组织级标准资产，按工程复制会产生多份"标准"
图谱实例 / 模型按工程隔离 P1型号专属产物
项目记忆接入现有 by-project 存储能力已存在
命名必须统一：代码与既有文案（当前工程 / 工程入库 / 检测连接）全用「工程」。今日导航口径审计暴露的 P1 问题正是双口径造成的——若选"项目"，必须一次性全量替换，严禁混用。
