# 本体模型页 · 中栏编辑与新增编辑整合优化方案

> 版本：v1.0（2026-09-08）　状态：**待拍板**
> 范围：`static/index.html`（kb-c 本体管理工作台）+ `routers/knowledge.py`
> 结论先行：**可以整合，且应该整合**——推荐 WebProtégé 的「中栏唯一编辑面」模式：新增退化为"创建+选中"两字段轻流程，全部字段编辑收敛到中栏 Description 即时写回；右侧滑窗表单退役。

---

## 1. 现状诊断：两套编辑范式并存

### 1.1 两套界面盘点

| 维度 | A. 中栏 Description（内联 chip） | B. 右侧滑窗表单（onttype） |
|---|---|---|
| 渲染 | `renderOntDesc()` (L11792) | `FORMS.onttype` (L1505) + `openOntSlide()` (L2076) |
| 保存 | **即时写回**：每次 chip 增删单独 `ontPutType()`，clone 当前 constraints 后改单键 | **整单替换**：`saveOntType()` (L13294) 构建**全新** constraints 一次 PUT |
| 范式 | Protégé Description 面板（等价类/Subclass Of/互斥/公理 chips） | 传统表单（section + select + checkbox） |
| 入口 | 选中左栏树节点自动展示 | ① 左栏树「＋」`ontAddByView()` ② 图谱双击空白 ③ 图谱 Ctrl+拖线 ④ 中栏「✏️ 编辑/✏️ 属性表」`ontEditTypeById()` |

### 1.2 字段归属现状（不整合的直接恶果）

| 字段 | 中栏 | 滑窗 | 整合问题 |
|---|---|---|---|
| 名称 / IRI / 种类 | 只读展示（IRI 可改 🔗） | ✏️ 可编辑 | 名称改动必须开滑窗 |
| 描述 description | ❌（挤在右栏 Annotations 只读） | ✏️ | 高频字段在中栏不可编辑 |
| 父类型 Subclass Of | ✏️ chip | ✏️ select | 两处可改，行为不一致 |
| 互斥 Disjoint With | ✏️ chip | ✏️ multi-select | 两处可改 |
| 等价类 equivalent_to | ✏️ chip | ❌ **无此字段** | ⚠️ 滑窗保存即清空 |
| 一般类公理 axioms | ✏️ chip | ❌ **无此字段** | ⚠️ 滑窗保存即清空 |
| 生命周期 status | ❌ | ✏️ | 中栏不可见 |
| 抽象类型 abstract | ❌ | ✏️ checkbox | 中栏不可见 |
| 属性引用+局部约束（required/unique/allowed） | 只读提示"复杂编辑走滑窗" | ✏️ ot-props-rows 行内勾选 | 高频操作被迫跳滑窗 |
| 关系 Domain/Range | ✏️ chip | ✏️ multi-select | 两处可改 |
| 关系特征 characteristics | ✏️ chips | ✏️ checkbox 组 | 两处可改 |
| 数据属性 XSD/允许值/适用类型/单位量纲 | 部分（Domain+XSD chip） | ✏️ | 允许值/单位量纲中栏缺失 |
| profile 外部映射 | ❌ | ✏️ | 中栏不可见 |

### 1.3 ⚠️ 已确认的数据丢失缺陷（P0 级论据）

**复现路径**：给"巡飞弹"在中栏添加等价类/公理 → 点中栏「✏️ 编辑」打开滑窗 → 保存。

- `saveOntType()` L13307：`const constraints = {}` 全新构建，**不收集** `equivalent_to` / `axioms`（表单 HTML L1505-1592 也无对应输入项）
- 后端 `knowledge.py` PUT L1565-1574：`constraints=json.dumps(body.constraints)` **整体替换**
- 结果：中栏维护的等价类与公理被**静默清空**（仅变更留痕里可见旧值）

## 2. 业界对标

| 工具 | 新增范式 | 编辑范式 | 启示 |
|---|---|---|---|
| **Protégé 桌面** | 菜单 Create class → 树上出现空节点 → Description 面板编辑 | Description 面板即唯一编辑面 | 新增=创建+选中，无独立表单 |
| **WebProtégé** | 左栏顶部 ➕ → 输入名字回车即建 → 中栏直接补全 | 中栏即编辑器，即时保存 | **本方案对标对象** |
| TopBraid Composer | Graph/Form 双视图但字段同源同份 | 表单与图共享一个模型 | 字段必须同源，忌两套表单 |

共同点：**没有"新增表单"这个概念**——新增是轻量创建动作，编辑集中在同一个面板。我们当前的滑窗是"把新增当表单填报"，把 Protégé 的 Description 能力又在中栏实现了一遍，于是分叉。

## 3. 目标方案

### 3.1 入口统一（四入口 → 一流程）

| 现状入口 | 方案后 |
|---|---|
| 左栏树「＋」`ontAddByView()` | **保留为唯一主动入口**，行为改为：弹出**两字段迷你创建框**（名称 + 种类，当前实体维度预选种类）→ 回车创建 → 自动选中 → 焦点落中栏名称输入框 |
| 图谱双击空白 | 保留，走同一迷你创建框（预选实体类型） |
| 图谱 Ctrl+拖线 | 保留，走迷你创建框（预选关系类型 + 预填 FROM=源节点） |
| 中栏「✏️ 编辑 / ✏️ 属性表」 | **移除**——中栏本身即编辑面，无"复杂编辑"概念 |

迷你创建框替代滑窗的依据：滑窗必填字段只有"名称"（`saveOntType` L13298 只校验名称）；种类在按维度新建时已确定；其余字段全部可在创建后于中栏补全——即创建所需信息 ≤ 2 字段。

### 3.2 字段整合（全字段上中栏，字段归属唯一化）

中栏 Description 重排为七个分区（顺序对标 Protégé 阅读习惯）：

```
① 头部区   名称(行内编辑✏) · owl:Class badge · 生命周期 badge(点击切换) · IRI(复制/修改)
② Equivalent To   等价类 chips + 一般类公理 chips（Protégé 将公理同置于此区，分区标签保留中文双语）
③ Subclass Of     父类 chip ＋ 抽象类型开关（chip 形式，点 × 取消）
④ 属性引用（实体）  每属性行：名称 · XSD 类型 · 必填☑ · 唯一☑ · 白名单（行内即时写回，能力从滑窗 ot-props-rows 平移）
⑤ Disjoint With   互斥 chips（保持现状）
⑥ 关系特征（关系）  Domain chips · Range chips · Characteristics chips（保持现状）
⑦ Range 约束（数据属性）XSD 类型 chip · 允许值 chips · 适用类型 chips · 单位/量纲 chips（补齐缺失两字段）
```

移入**右栏**（低频/注释性，Protégé 同样把 Annotations 放右栏）：

| 字段 | 去处 |
|---|---|
| 描述 description | 右栏 Annotations 区改为行内 textarea，失焦即存 |
| profile_source / profile_ref | 右栏新增「外部映射」小区块，行内编辑 |
| 生命周期 status | 头部 badge 点击循环 draft→review→released→deprecated（含确认提示） |

**原则：每个字段全局只有一个可编辑位置**——消灭"两处可改、行为不一致"。

### 3.3 保存机制统一：全量即时写回

- 所有编辑统一走现有 `ontPutType()` 路径：clone 当前 constraints → 改单键 → PUT → 局部刷新 + 「已写回」闪现
- **后端加一道兜底（P0，先行落地）**：PUT 增加 merge 语义或前端 saveOntType 收集 equivalent_to/axioms——在滑窗退役前先堵住数据丢失：
  ```python
  # knowledge.py PUT：滑窗整单替换改为保留未知键
  merged = dict(before_constraints); merged.update(body.constraints)
  ```
  （前端方案落地后此兜底可撤，改为纯整体替换+前端全量字段）

### 3.4 前端布局（三栏骨架不动，中栏内部重排）

**现状：**

```
┌────────┬────────────────────────────────┬────────────┐
│ 左栏    │ 中栏 [📝编辑|🕸图谱|OWL|📜历史]   │ 右栏        │
│ 类层次树 │  巡飞弹  owl:Class   [✏️编辑]───┼──→ 滑窗表单  │
│ ＋      │  IRI: ...                      │ (另一套字段，│
│ ·载荷   │  等价类 [chip]＋               │  整单保存)   │
│ ·系统   │  子类于 [chip]＋                │            │
│        │  属性表(N项)  [✏️ 编辑]─────────┼──→         │
└────────┴────────────────────────────────┴────────────┘
```

**方案：**

```
┌────────┬────────────────────────────────┬────────────┐
│ 左栏    │ 中栏 [📝编辑|🕸图谱|OWL|📜历史]   │ 右栏        │
│ 类层次树 │ ①巡飞弹✏ owl:Class [released]   │ Annotations │
│ ＋──────┼─→ IRI ⧉🔗                      │  描述 ✏     │
│ (迷你框: │ ②Equivalent To [chip]＋公理     │  外部映射 ✏ │
│  名称+   │ ③Subclass Of [chip] [抽象◻]     │ Usage       │
│  种类)   │ ④属性引用 ✏(必填☑ 唯一☑ 白名单)  │ 实例/别名    │
│        │ ⑤Disjoint With [chip]＋         │            │
│        │ ⑥Domain/Range/特征（关系态）      │            │
└────────┴────────────────────────────────┴────────────┘
新增/编辑全部在中栏完成，即时写回；滑窗退役。
```

关键布局参数：
- 中栏七分区沿用现有 `.ont-sec` 分区标题 + `.ont-chip` chip 视觉（延续 2026-09-07 WebProtégé 风格改造，不引入新组件体系）
- ④ 属性行采用紧凑单行：`名称(xsd:string) ☑必填 ☑唯一 [白名单: a,b,c ✏]`，行内编辑即存
- 迷你创建框：锚定左栏「＋」按钮下方 240px 浮层，两输入 + 回车创建，Esc 取消（交互同 GitHub 新建分支浮层 `ws-brDD`，站内有成熟先例）
- 滑窗 DOM（`#ont-slide`）与 `FORMS.onttype` 保留一个版本周期做降级开关（`?ont-slide=1` 可回退），稳定后删除

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 即时写回高频 PUT（属性行勾选连点） | 复用现有 ontPutType 节流模式；300ms debounce 合并 |
| 老用户习惯滑窗整单"一次性填完" | 新建后自动选中+焦点引导；降级开关保留一个版本 |
| 改名联动（词典迁移 confirm）在行内编辑也要触发 | 名称行内编辑复用 saveOntType 的 R3 迁移逻辑（抽公共函数） |
| 后端 merge 兜底与前端全量替换冲突 | 前端全量字段方案落地后撤兜底，避免双重语义 |

## 6. 待拍板决策点

1. **滑窗去留**：A. 彻底退役（推荐，交互最简） / B. 保留为"引导式新建向导"（关系类型 FROM/TO 多选有引导价值，但迷你框+图谱拖线已覆盖）
2. **生命周期 status 交互**：A. 头部 badge 点击循环切换（快，推荐） / B. 下拉选择（稳）
3. **P0 兜底方式**：A. 后端 PUT merge（影响所有调用方，最稳） / B. 仅前端补收集（改动最小）
4. **属性引用④的编辑位置**：A. 全部上中栏（推荐，一步到位） / B. 中栏只读+右栏编辑（折中）
