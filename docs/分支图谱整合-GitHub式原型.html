④ 设计要点与现状映射

GitHub 元素本系统落位改动量
分支下拉选择器（筛选/默认标记/新建分支）替换页头原生 <select>：搜索过滤 + 分支类型分组（main/release 默认标记、personal 显示"← 自父分支"）+ 底部新建分支（预填父分支）纯前端，全局选择器一处改造全页生效
Code / Commits / Pull requests 三 Tab图谱数据页加「内容 / 历史 / 合并请求」Tab：内容=现三栏；历史=提交列表行内展开快照明细；合并请求=MR 列表 + 行内处理（差异预览/冲突解决/评审操作）纯前端，MR 端点与处理函数全部现成
分支上下文（ahead/behind + PR 入口）保留现有 kb-branch-ctx 条，置于分支选择器下一行已完成
Compare 页「比较 dev…release」链接 + 上下文条 ↑↓ 徽章 → 现有对比抽屉（统计/清单/叠加图谱）已完成，仅加入口
PR 队列合并队列独立页取消：分支列表→选择器、KPI→Tab 头计数、MR 全流程→合并请求 Tab、发布日志→Tab 工具栏；导航项移除，站内跳转改指 kb-d纯前端搬运，函数零改动
设计原则：分支是「内容」的唯一上下文——切分支 = 切换图谱/历史/MR 的整份数据投影（git checkout 心智）；分支的浏览、提交、对比、合并全生命周期在一个页面闭环，不再跨页跳转。
