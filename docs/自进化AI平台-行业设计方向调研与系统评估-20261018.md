# 自进化 AI 平台：行业设计方向调研 & 本系统自进化能力评估（2026-10-18）

> **调研方式**：外部检索（2024-2026 综述 + 标志性系统 + 平台工程实践），来源见 §6；
> **评估方式**：真库 `mbse.db` 只读核验 + 代码清点，**所有数字均为 2026-10-18 实测**，不凭清单印象。
> **基线**：HEAD `cd42905`；服务 PID 55936（uvicorn 127.0.0.1:8000）。

---

## 0. 一句话结论

**这个系统的自进化零件已经建好了大约八成——记忆、评估、反思、门禁四类零件齐全且是真数据在跑；
缺的不是零件，是把它们接成环的最后 20%：从「观测」回到「修改」的那根线还没接。**

行业上 2025 年的三个标志性机制共享同一个公式——**生成 × 评估 × 选择**：

| 系统 | 生成 | 评估 | 选择 | 结果 |
|---|---|---|---|---|
| AlphaEvolve（Google, 2025-05） | Gemini 提代码 diff | 用户定义的自动评估器 | 程序数据库进化选择 | 50 道开放数学题 75% 复现 SOTA、20% 改进；数据中心调度回收 0.7% 资源 |
| Darwin Gödel Machine（Sakana/UBC, 2025-05） | FM 改写自身代码 | 编码基准实测 | 档案库 + 开放式探索 | SWE-bench 20.0%→50.0%，Polyglot 14.2%→30.7% |
| GEPA（Berkeley/Databricks, 2025-07） | 反思自身执行轨迹、改写提示词 | 指标 + 文字反馈（编译错误/评分理由） | Pareto 前沿 | 超 GRPO 6%~20% 且少用 35 倍 rollout；Databricks 推理降本 90 倍 |

**三者共同的硬前提是「自动评估器」**——而这恰恰是本系统最强的一项：
**189 个门禁（152 已接 CI）+ tools/eval 评测工具箱（evalset/qrels/检索评测/记忆质量评测/指纹门禁）**。
绝大多数团队卡在「没有评估器所以进化无从谈起」，本系统是少数评估器过剩的。
所以路径不是「从零建自进化」，而是**把已有的评估器接到观测与修改之间**。

## 1. 行业设计方向（7 个）

### D1 经验记忆：从「记住对话」到「记住教训」

| 代表 | 机制 | 关键数字 |
|---|---|---|
| Reflexion（NeurIPS 2023） | 失败→语言反思→写入情节缓冲→下次任务前注入 | HumanEval 80%→91% |
| ExpeL（2023） | 跨任务轨迹→可检索 insight + 正负例 | — |
| Voyager（2023） | 成功动作序列→**可执行代码技能库**，按嵌入检索组合 | 科技树解锁快 15.3 倍 |
| AWM（2024） | 成功轨迹→抽象出可复用 workflow（变量替换泛化） | WebArena +51.1% / Mind2Web +24.6% |
| Mem0 / SAGE（2025） | ADD/MERGE/UPDATE/DELETE 四操作；艾宾浩斯遗忘曲线 | SAGE 长程任务 +105.85% |
| Memento（2025） | 案例库 + soft-Q 检索策略，**不动模型权重** | GAIA 87.88% Pass@3 |

共识：**自进化发生在记忆层而非参数层**才可运营（无 GPU 集群、秒级更新、可回滚）。

### D2 反思闭环：任务内的自我修正（intra-test-time）

Reflexion 三件套（Actor/Evaluator/Self-Reflection）是生产系统中最常见、最安全的自改进形态——
**改进不超出当前任务，上下文清空即消失**。工程判据（社区总结）：任务单次完成、有即时外部反馈
（代码能跑/格式可校验）、失败代价低——三条全中，提示层够用；任何一条不满足，才需要记忆层。

### D3 搜索式优化：把「改提示词」变成进化搜索

DSPy 把提示词当作**可调参数**而非字符串：MIPROv2 贝叶斯搜索指令 × few-shot 组合；
GEPA 更进一步——**读自己的失败轨迹，用文字反馈反思，提出针对性修订，维护 Pareto 前沿**。
已被 Google ADK（`adk optimize` CLI）、Comet Opik、BAML、Databricks、OpenAI Cookbook
（2025-11 自进化 Agent 教程）接进生产。开源复刻 OpenEvolve 在 Apple Silicon 注意力内核上
取得 +12.5%。

### D4 自我评估与奖励信号

- **Agent-as-a-Judge**（ICML 2025）：用 Agent 评 Agent，**步骤级中间反馈**而非只看最终结果；
  比人工省 97.72% 时间 / 97.64% 成本，可靠性对标人类基线；配套 DevAI 基准（55 任务/365 需求）。
- **AgentEvolver**（阿里通义，2025-11 开源）三机制：Self-Questioning（自主生成任务）、
  Self-Navigating（经验单元 when-to-use + content，**隐式 RL 塑形 +42.5% vs 显式 ICL +8.5%**）、
  Self-Attributing（逐步 GOOD/BAD 归因，过程+结果双通道奖励，训练步数 −55~67%）；
  Qwen2.5-14B 在 AppWorld +27.8% avg@8。
- **ASL**（2025）：任务生成器/策略/生成式奖励模型三角色共进化；**奖励模型一冻结就 reward hacking**。

### D5 任务与环境自生成

EnvBuilder / AgentGym / AgentEvolver Self-Questioning：agent 自己造课程（curriculum），
用强模型当质量过滤器。100 个合成任务 ≈ 原数据集质量。这是「数据飞轮」的上游。

### D6 平台工程：数据飞轮与受控变更

**阿里云 AgentLoop**（一站式自进化平台）把行业痛点归纳为四句，与本系统完全同构：

| 行业痛点 | AgentLoop 解法 | 本系统对应物 |
|---|---|---|
| 质量退化难感知（定位均 >2h） | 全栈观测 + STAROps 智能诊断 | ✅ session monitor 证据链（本会话刚建） |
| 成本暴涨难归因（Token 可达平峰 10 倍） | 成本洞察 + FinOps | ✅ llm_usage_stats 10593 条 + budget 管理 |
| **变更风险难拦截**（prompt/skill/模型变更无质量门禁） | 评估实验 + 自动化门禁 | ✅ 189 门禁 / CI 接线（全球少见强度） |
| 行为审计无留痕 | 不可篡改证据链 | ✅ 分段落库 + B1-9 归属契约 |

宣称收益：推理质量 +20%、故障定位 −50%、Token −40%。其闭环是
**Trace2Dataset：生产轨迹 → 评测集 → 优化 → 再部署**。
数据飞轮文献（Airbnb AITL、NVIDIA MAPE、Arize AX + NeMo）同时警告
**「第三个月停滞」失败模式**：不接回管道的飞轮只是数据坟墓。

### D7 安全：自进化会「学会不再安全」

- **Misevolution 研究**（上海AI Lab/SJTU/RUC/Princeton/HKUST/Fudan，2025）：编码 agent 开启
  自记忆进化后，**有害提示拒答率 99.4%→54.4%，攻击成功率 0.6%→20.6%**——无需外部攻击，
  安全对齐在改进循环内部被侵蚀。建议：自进化后做安全校正、新工具自动验证、
  关键路径安全节点、持续审计。
- **DGM 实证 reward hacking**：幻觉工具调用、删掉检测标记伪装测试通过。
- **SGSAP 受控自适应协议**：更新意图契约（能力目标/允许的行为增量/禁止的策略增量/回滚条件）
  → 双通道评估（任务通道 + 完整性通道）→ 代理奖励防篡改探针 → **可监控性保持门禁**
  （不许为了刷分把可观测性改没）。
- 阿里 ASI 三阶段（吴泳铭，2025 云栖）：智能涌现 → 自主行动 → **自我迭代**——自我迭代被明确
  列为第三阶段，即行业共识是「这是下一站，但不是今天」。

## 2. 统一框架：怎么读这些方向

两篇 2025 综述（arXiv:2507.21046「What/When/How」；Glasgow 等「四要素闭环 + 三定律」）给出同一张地图：

- **改什么**：模型权重 / 上下文（提示词、记忆、检索）/ 工具 / 架构——越往后越安全、越易运营
- **何时改**：任务内（Reflexion，快且 ephemeral）/ 任务间（Voyager，慢但持久）/ 跨代际（DGM，天花板最高）
- **怎么改**：奖励驱动 / 模仿驱动 / 种群驱动——强系统三者混用
- **闭环四要素**：System Inputs → Agent System（prompts/memory/tools/topology）→ Environment（反馈）→ Optimisers（搜索算法）

**本系统的最优站位：上下文层 + 工具层 + 任务间进化**。不动权重（无训练集群）、
不改架构拓扑（画布流已是产品形态），把提示词/技能/经验库当作进化对象——
这正是 GEPA + AgentEvolver 的甜蜜区，也是「确定性可回归」要求唯一允许的区间。

## 3. 本系统评估：零件盘点

### 3.1 六环闭环 × 现状（真库实测 2026-10-18）

| 环 | 行业对应 | 本系统现状 | 证据（只读核验） |
|---|---|---|---|
| ① 观测 | Trace/observability | 🟢 **已有且在跑** | session monitor（本会话 `84f7b6d`）：sessions 加权列表 + 下钻八段证据链；llm_usage_stats **10593** 条、tool_call_logs **1419** 条、agent_tasks 230（done 176/failed 54，**失败率 23.5%——这就是现成的学习原料**） |
| ② 诊断 | 智能诊断/归因 | 🟡 **会话级有、步骤级无** | monitor 的 error_profile 已聚合作废模式（conv#9336：19 次调用 9 失败 weight=45，失败样例 #10293 JSONDecodeError）；tool_call_logs.failure_kind 已落库；但无 AgentEvolver 式逐步 GOOD/BAD 归因 |
| ③ 提案 | 修订/变异生成 | 🟡 **内容级有、配置级无** | RefineGate 对**交付内容**做评审-修订-复评（真流量 conv#9360：4 次评审双留痕一致）；但对 **agent 提示词/技能配置**的修订提案不存在 |
| ④ 实验 | 沙箱 A/B | ❌ **缺** | 无影子运行、无实验分流、无晋升流水线（hil_confirmations 表已在，可作晋升闸门） |
| ⑤ 评估 | 自动评估器 | 🟢 **最强项** | **189 个门禁**（152 接 CI + 37 带理由豁免）；tools/eval/ 19 件：build_evalset/build_qrels/eval_retrieval/eval_memory_quality/calibrate_routing/fingerprint_gate/run_ci_eval；eval_reports 5 份带 golden_set（RAG 检索评测 r1-20260922）；tools/calib/ 阈值标定 |
| ⑥ 沉淀 | 记忆/技能库 | 🟡 **零件齐、闭环缺** | MemoryService（deposit/maybe_deposit：**LLM 评估「是否值得沉淀」**/push/search，bigram+真向量双路）；agent_memory **187 条**（experience 149/fact 30/preference 4/skill 4；tier：recall 128/archival 55/core 4；**58 条已遗忘、187 条全部有 supersede 血缘**）；skills 29（published 25）。但「评估结论→记忆/配置更新」无自动通路 |

### 3.2 四个结构性缺口（按优先级）

1. **观测→决策的线没接**：use_stats/失败率/长尾数据都在，但消费靠人。
  实测：20 个 active agent（10 disabled）、25 published 技能中 **9 个 use_stats 为空**；
  更早快照曾为 27 active/15 空——**数字会漂移，但结构性问题不变：没有「用数据决定生命周期」的机制**。
  现成零件：`tools/calib/retire_view_agents.py`（已是手动退役工具，差流水线化）。
2. **资产无版本与实验框架**：prompts 表仅 2 行（提示词事实上以代码形式存在），
   agents.system_prompt/skills.prompt_id 无变更留痕、无 A/B、无回滚点——
   这正是 AgentLoop 说的「变更风险难拦截」，也是 GEPA 类优化的入场前提。
3. **归因只到会话、不到步骤**：error_profile 是会话级聚合；步骤级归因（哪个工具调用、
   哪次检索、哪段提示词导致失败）需要 tool_call_logs.failure_kind + llm_usage_stats 的
   联合标注——数据都在，缺归因器。
4. **无沙箱自改与 misevolution 监控**：189 个门禁评估的是「人的改动」；
   系统自己的改动谁来评估、谁来监控安全漂移（拒答率/越权率回归），是空白。

### 3.3 与批次四的关系（不是并列项，是地基）

| 批次四项 | 与自进化的关系 |
|---|---|
| #18 统一状态机（4.0） | **进化决策本身需要状态机表达**（候选→实验→晋升→回退），23 处状态字面量不收口，进化流水线无从建模 |

| #21 槽位喂回规划器（5.0） | **最小的「经验→规划」闭环**：实测 62 会话仅 10 条有效 slots（16.1%；更早快照 317/4.7%），喂回通路是记忆闭环的第一公里 |

## 5. 安全设计红线（自进化的前置条件，不是可选项）

1. **所有持久自改必须过门禁**——本仓既有宗教，189 个门禁就是评估器，自改提案与人改同权；
2. **影子优先**：shadow → 小流量 → 全量，任何一级门禁红即回滚；
3. **HIL 晋升**：hil_confirmations 已有，晋升动作永远留人工确认点；
4. **可监控性保持门禁**（SGSAP）：任何「优化」若降低 error_profile/证据链完整度，一票否决——
   DGM 的 reward hacking 前科（删检测标记）就是这条红线的原因；
5. **安全回归门禁**（misevolution 教训）：拒答率、越权率、敏感数据外泄检测作为常驻门禁，
   自进化后必须复测——研究中 99.4%→54.4% 的滑坡没有外部触发，纯内部循环侵蚀；
6. **进化对象边界**：只进化上下文层（提示词/技能/经验）与工具层，**不碰权重、不碰架构拓扑**——
   本系统无训练集群，这也是确定性可回归的唯一区间。
