# Fuseki 图库：可写 + 持久化 通用方案

> 结论先行：**「可写」与「持久化」不是二选一**。Fuseki 的
> `--update --loc=<绝对路径>` 同时满足两者。
> 本文档所有结论均在本机实测（2026-10-12，Fuseki 6.x / jena-fuseki-server.jar
> / JDK 25 / Windows + Git Bash），每条都附验证方式。

---

## 0. 一句话根因

`fuseki_start.py` 的 `--persistent` 分支**只加了 `--loc` 没加 `--update`**。
Fuseki 的 `--loc` **默认以只读方式打开数据集**，于是
`POST /mbse/update` 直接返回 **HTTP 405**，表现为「图库能查、但永远写不进去」。

官方口径（Fuseki 文档原文）：

> Load a TDB2 database, and expose, **read-only**:
> `fuseki --loc databases/DB2 /ds`
> **To allow update on the database, add `--update`. Updates are persisted.**

⚠️ **历史注释纠错**：代码里曾写「实测 `--loc`(TDB2) 是只读的」。
这个观察是对的，但**结论错了** —— 那不是 TDB2 的限制，是漏加 `--update`。
TDB2 本身完整支持事务写入。若据此把架构设计成「持久化只能只读」，
会白丢一个能力。

## 1. 启动参数（推荐配置）

```
java -Xmx1g -jar jena-fuseki-server.jar \
     --update \
     --loc=<绝对路径>/tmp/fuseki_tdb2 \
     --port 3030 /mbse
```

| 参数 | 作用 | 不加的后果 |
|---|---|---|
| `--update` | 允许 SPARQL Update / GSP 写入 | `POST /update` **405**；数据只进内存，重启即丢 |
| `--loc=<dir>` | TDB2 持久化目录 | 数据只在内存（等同 `--mem`） |
| `--port` / 数据集名 | 端口 + 数据集路径 | — |

### 1.1 三条不可省的约束

1. **`--loc` 必须是绝对路径 + 正斜杠**。相对路径在 Git Bash 下会被 MSYS 改写。
   用 `os.path.abspath()` 后 `.replace(os.sep, "/")`，**不要把路径交给 shell 拼**。
2. **数据集名 `/mbse` 必须直传给 `java` 进程，不经 shell**。经 shell 时 MSYS2 会把
   `/mbse` 转成 `C:/…/PortableGit/mbse`，数据集名被污染，端点返回 404/405。
   ⇒ **用 Python `subprocess.Popen([...])` 传参数数组，不要用字符串命令**。
3. **同一时刻只能有一个进程开这个 TDB2 目录**。TDB2 用 `tdb.lock` 做进程锁，
   第二个进程会报 `Failed to get a lock: … held by process <pid>`。
   ⇒ 批量装载必须**先停服**。

## 2. 写入契约（最容易踩的一环）

服务侧写入器是 `graph_db.FusekiWriter`（`graph_db.py:416`），
底层就一条 SPARQL Update：

```
POST {endpoint}/update     Content-Type: application/sparql-update
INSERT DATA { GRAPH <图IRI> { <s> <p> <o> . } ... }
```

**所有三元组都写进命名图（named graph），不用默认图。**
查询侧也一律 `GRAPH ?g { … }`，因此 **不依赖 `unionDefaultGraph`** ——
这是本方案"通用稳定"的关键：无论 union 开或关，读写口径都一致。

### 2.1 输入字典的 key 是不对称的（血泪）

| 位置 | 接受的 key | 不认的 key |
|---|---|---|
| 主语 `_subj` | `s`、`s_id` | — |
| 谓语 `_pred` | `p`、`o_type` | — |
| **客体 `_obj`** `o_type='literal'`（默认） | **`o_value` 仅此一个** | ⚠️ **`o`** |
| 客体 `_obj` `o_type='entity'` | `o`、`o_value`、`o_id` | — |
| 客体 `_obj` `o_type='class'` | `o_value`、`o` | — |

⚠️ **literal 分支只读 `o_value`**。若照 entity 的习惯传 `o='文本'`，
写入**照样返回 `{'written': 1}`（不报错）**，但宾语会变成**空字符串 `""`** ——
典型的「返回成功码但数据是错的」。实测：

```python
# ✗ 错：宾语落成 ""
w.write_triples([{'s':'A','p':'B','o':'文本'}])
# ✓ 对：
w.write_triples([{'s':'A','p':'B','o_value':'文本','o_type':'literal'}])
```

### 2.2 IRI 会被规范化

`ent_uri()` / `pred_uri()` 会把名字规范化：连字符 `-` → 下划线 `_`。
实测 `PROBE-SUBJ` 落库为 `http://www.xingwang.mbse/ent/PROBE_SUBJ`。

### 2.3 ⚠️ 删除必须传**规范化后**的名字

`delete_subjects()` 用传入值原样构造 IRI，**不做与写入相同的规范化**：

```python
w.delete_subjects(['PROBE-SUBJ'])   # ✗ deleted: 0（图里删不掉）
w.delete_subjects(['PROBE_SUBJ'])   # ✓ deleted: 1
```

⇒ **待删除对象的 id 本身已含连字符时，删除会静默失效**。
批量删除前请先 `SELECT ?s WHERE { GRAPH ?g { ?s ?p ?o } }` 取出**真实 IRI** 再删。

### 2.4 可选附加字段

`write_triples` 每条三元组还支持：

- `s_label`：额外写一条 `<rdfs:label> "名称"`（按名检索走它）
- `meta`：键值对写成 `<…/meta/{k}> "v"`（**空串/None 的值会被跳过**）

## 3. 命名图 IRI 与分支的对应

图 IRI = `graph_uri(branch)`，当前为
`http://www.xingwang.mbse/graph/{branch}`（`dev` / `release` / …）。

⚠️ 与 SQLite 主库的分支模型是两套东西，别混：

| 层 | 位置 | 谁写 |
|---|---|---|
| 主数据（权威） | SQLite `entities` / `relations`（带 `branch` 列） | 业务写入 / MR 合并 |
| 图库（镜像） | Fuseki 命名图 `…/graph/{branch}` | `graph_db.sync_pending_triples` 等 |

⇒ **Fuseki 是派生副本**。清库重建的正确姿势是从 SQLite 重新灌，
而不是在图库里手工补数据。

## 4. 两种写入路径，各管一段

| 场景 | 手段 | 要点 |
|---|---|---|
| 业务增量 | HTTP `POST /mbse/update`（SPARQL Update） | 服务已在用，无需改造 |
| 批量首灌 / 全量重建 | `tdb2.tdbloader --loc <dir> <数据文件>` | ⚠️ **必须先停 Fuseki**（`tdb.lock`）；在服务运行时加载会拿不到锁 |

`tdb2.tdbloader` 用法（离线）：
```
java -cp jena-fuseki-server.jar tdb2.tdbloader --loc <dir> data.ttl
```
首次装载时目录会被创建并建索引；之后如需再灌，**先清空目录**避免残留。

## 5. 验证清单（每条都应实际执行，不看日志推测）

```bash
# ① 实例活着
curl -s http://127.0.0.1:3030/$/ping

# ② 可写 —— 这一条是「--update 有没有生效」的唯一判据
curl -s -o /dev/null -w "%{http_code}\n" -X POST \
  -H "Content-Type: application/sparql-update" \
  --data-binary 'INSERT DATA { GRAPH <urn:g:probe> { <urn:s> <urn:p> <urn:o> } }' \
  http://127.0.0.1:3030/mbse/update          # 必须 204；405 ⇒ 漏了 --update

# ③ 写进去了
curl -s -H "Content-Type: application/sparql-query" \
  --data-binary 'SELECT (COUNT(*) AS ?n) WHERE { GRAPH ?g { ?s ?p ?o } }' \
  http://127.0.0.1:3030/mbse/query

# ④ 持久 —— 停服后重启，再跑 ③，条数应不变
```

⚠️ 清理探针：`DROP GRAPH <urn:g:probe>`（同样走 `/update`）。

## 6. 故障速查

| 现象 | 真实原因 | 处置 |
|---|---|---|
| `POST /update` 返回 **405** | 缺 `--update` | 加参数重启 |
| `POST /update` 返回 **400 Unknown parameter 'data'` | 用了 GSP 表单参数名不对 | 改用 SPARQL Update（推荐）或 GSP 的 `data` 裸 body |
| 查询恒 0 条，但确认写过 | ① 按原始名查而实际已规范化；② 写入没带 `GRAPH` | 按 §2.2/2.3 用真实 IRI 查 |
| 写入返回 `written:1` 但宾语是 `""` | literal 客体传了 `o` 而非 `o_value` | 见 §2.1 |
| `Failed to get a lock: … held by process` | 同目录已有进程占用 TDB2 | 停掉旧进程（`fuseki_start.py --stop`） |
| `401/403` 而 ping 正常 | 该服务以只读方式起 | 同第一条 |
| 端点 404/405 且数据集名可疑 | `/mbse` 被 MSYS2 转成路径 | 见 §1.1 第 2 条 |
