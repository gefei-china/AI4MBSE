| 数据库                     | 模型                          | 查询               | 推理                            | 评分（2026）  |
| ----------------------- | --------------------------- | ---------------- | ----------------------------- | --------- |

| **AllegroGraph 8**      | RDF + Graph Neural          | SPARQL + Prolog  | 强（联邦 + NNet）                  | 7.5 ⭐⭐⭐   |

**mbse_system 现状**：

- 后端：SQLite（治理权威源）+ pyoxigraph（图库查询镜像）+ Jena Fuseki/Neo4j（可切换 Adapter）
- 推理：自研 `ontology_reasoning.py`，5 项能力——`classify / transitive_closure / symmetric_inference / reflexive_check / consistency_check`
- 三元组：`triples` 原子表 + `triple_store.py` + 审核工作流（已具备）
- **缺口**：UI 层无三元组视图、无推理执行入口、无推理结果可视化

### 0.3 渲染库对标（画布性能）

| 库                         | 渲染                          | 性能（万级节点）                                   | 适用场景       | 与 mbse 适配  |
| ------------------------- | --------------------------- | ------------------------------------------ | ---------- | ---------- |
| **Reagraph (WebGL)**      | InstancedMesh + Edge shader | 5k 节点 110 FPS / 2k 节点 12 FPS 远超 React Flow | 知识图谱 / 血缘  | ⭐⭐⭐⭐⭐      |
| **Cytoscape.js (Canvas)** | 中等规模                        | 2k 节点流畅，5k+ 渐卡                             | 网络分析 + 图算法 | ⭐⭐⭐⭐       |
| **Sigma.js (WebGL)**      | graphology + WebGL          | 10 万级节点                                    | 超大规模图      | ⭐⭐⭐（杀鸡用牛刀） |
| **React Flow (SVG)**      | DOM 节点                      | 1k+ 节点掉帧                                   | 流程图 / 编辑器  | ⭐⭐（当前规模超限） |
| **D3.js (SVG/Canvas)**    | 灵活可控                        | ~2k 节点流畅                                   | 自定义可视化     | ⭐⭐⭐        |
| **vis-network**           | Canvas + 物理引擎               | 中等                                         | 快速原型       | ⭐⭐         |
| **当前 SVG+DOM**            | 每节点一个 DOM                   | 几百节点尚可，千级明显卡                               | ——         | **需替换**    |

**结论**：mbse_system 当前画布（SVG+DOM）在骨架模式 L2/L3 邻域下钻时会卡到不可用。**升级到 Reagraph（WebGL）是性价比最高的路径**，且零外部 SaaS 依赖、私有化离线部署友好。

### 0.4 推理器对标

| 推理器           | 表达力           | 性能（1k 类）   | 性能（10w 类） | 适用                      |
| ------------- | ------------- | ---------- | --------- | ----------------------- |
| **HermiT**    | Full OWL 2 DL | 中          | 不适用       | 研究 / 验证                 |
| **Pellet**    | Full OWL 2 DL | 中          | 不适用       | 复杂本体                    |
| **ELK**       | EL++ only     | 极快（毫秒级）    | 5-15 min  | 大规模生产                   |
| **JFact**     | Full OWL 2 DL | 快          | 不适用       | 折中                      |
| **owlready2** | CWA + 部分 PCWA | 0.3-1.2 ms | 适用        | **mbse_system 已具备轻量规则** |

**mbse_system 推理现状**（`ontology_reasoning.py`）：

- ✅ 分类推理（classify）—— 子类实例亦属父类
- ✅ 传递闭包（transitive_closure）—— BFS
- ✅ 对称推理（symmetric_inference）—— OWL 公理读取
- ✅ 自反检查（reflexive_check）—— OWL 公理读取
- ✅ 一致性检查（consistency_check）—— 类型合法 + 必填 + domain/range

**缺口**：UI 无入口、无结果可视化（仅后端函数）、无 SPARQL 推理桥接（无 Jena/ELK 调用链）。

## 1. 设计原则（对齐米爸两阶段法）

| 原则            | 落地                                      |
| ------------- | --------------------------------------- |
| **先调研后落地**    | 调研产物 0.1-0.4 → 实施章节 4-6                 |
| **结构化 + 优先级** | P0 / P1 / P2 三级，全方案可量化                  |
| **私有化离线部署**   | 渲染库本地化到 `static/vendor/`（已有目录）          |
| **零外部依赖**     | 不引入 SaaS 化工具，仅本地 Reagraph + ELK（可选）     |
| **本体驱动**      | 所有视图 / 筛选 / 校验走 `ontology_*` 模块，禁止硬编码类型 |
| **数据驱动决策**    | 每条功能附验收点（AC-N）                          |

| -------------- | ------------------------------------------------------- |

| 状态        | `triples.status`                             | pending/approved/rejected/raw_chunk 四态色标 |
| 操作        | `triples.triple_id`                          | ✅审核 / 🚫驳回 / 🔍追溯 / 📋复制 IRI             |

## 5. 三元组呈现方案（用户明确要求）

### 5.1 三元组数据契约

```typescript
interface Triple {
  triple_id: string;        // 唯一键
  subject: { 
    id: string;             // IRI
    name: string;           // 显示名
    type?: string;          // 实体类型
  };
  predicate: string;        // 谓词 IRI（rdf:type / 自造）
  object: {
    id?: string;            // 实体 IRI（关系/类型引用）
    value: string;          // 字面量值
    type: 'literal' | 'entity' | 'type_ref' | 'relation';
    datatype?: string;      // xsd:string / xsd:int 等
    lang?: string;          // 语言标签
  };
  graph: string;            // 命名图（branch）
  confidence: number;       // 置信度
  status: 'pending' | 'approved' | 'rejected' | 'raw_chunk' | 'inferred';
  source: {
    doc: string;
    chunk?: string;         // P0-5 原文溯源
    operator: string;
    created_at: string;
  };
  inferred?: {              // 推理结果专用
    kind: 'classify' | 'transitive' | 'symmetric' | 'reflexive';
    via?: string;
    path?: string[];
  };
}
```

### 5.2 三元组呈现维度

| 维度            | 方案                                            |
| ------------- | --------------------------------------------- |
| **行内紧凑呈现**    | `S ──P──→ O` 文本（如 `部件A ──connectedTo──→ 部件B`） |
| **表格呈现**      | 4-7 列（见 3.2 表）；默认视图                           |
| **图形化呈现**     | 嵌入 Tab 1 画布（每个三元组即一条边）                        |
| **JSON 原始呈现** | N-Quads / JSON-LD 切换                          |
| **推理叠加呈现**    | Tab 3 画布，原始（灰）+ 推断（橙）双层                       |

## 13. 决策点（请米爸拍板）

| ------- | ------------ | ----------------------------------------------- |
| **D-1** | Tab 顺序       | \[图谱\]\[三元组\]\[推理\]\[模型\]\[时序]（推理放第 3 位，与模型分离）  |

| **D-5** | 节点右键菜单       | **启用**（推荐）/ 维持简洁                                |
| **D-6** | 三元组 Tab 视图切换 | **列表 + SPARQL + 矩阵** 三视图（推荐）                    |

---

**总结**：以"5 Tab + 3 浮层 + 2 抽屉"重构图谱工作区，**核心新增 Tab 2（三元组）+ Tab 3（推理）** 满足用户的明确要求；画布从 SVG 升级到 Reagraph WebGL 解决骨架模式卡顿；跨 Tab 联动把"图谱-三元组-推理"形成完整闭环。所有推理 / 三元组能力均复用现有后端（`ontology_reasoning.py` + `triple_store.py`），实施风险低、落地快。
