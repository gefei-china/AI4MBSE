## 2. 建议新增：哪些可以人工触发（按价值排序）

### T1「立即跑批」按钮（P0，收益最大）

- **位置**：评测管理页页头（"现在什么状态"段旁）。
- **通道**：`POST /api/jobs {kind: "eval_nightly", job_key: "eval-nightly-<日期>"}` ——
  复用 jobs 系统的进度上报/失败重试/幂等去重，**不在 web 请求里裸跑 subprocess**
  （评测 4~8 分钟，同步请求必超时）。
- **后端缺口**：job_handlers.py 注册 4 个新 handler（每个就是调一个 CLI 脚本，
  worker 里已有 timeout/lease 机制可复用）：

| 新 kind | 执行 | 预估耗时 |
|---|---|---|
| `eval_nightly` | run_nightly_local.py（全批 5 步 + 3 门禁） | 4~8 min |
| `eval_trace` | eval_trace_consistency.py --no-llm --save | ~15 s |
| `eval_gen` | eval_generation_quality.py --llm-judge --save | ~80 s |
| `build_evalset` | build_evalset.py（重建评测集 + 发布 datasets/） | ~40 s |

- **防呆**：同 kind 幂等键带日期（一天只允一列队）；跑批进行中按钮置灰显示进度。

### T2 门禁阈值"就地编辑"（P1）

- **位置**：评测管理页"什么在拦着我"段，每个门禁行加 ✎。
- **通道**：`PUT /api/system/config/static {updates: {"eval_gates.trace_min_agreement": 0.8}}`
  —— **端点已存在**，CONFIG_SCHEMA 的 eval_gates 组自带类型/描述元数据，
  值域校验与即时 reload 都是现成的；改动落 config_history 台账。
- **安全边界**：只允许改 eval_gates 组的**值**（schema 校验兜底）；改动后
  页面顶部显示"阈值已变更，下一轮跑批生效"（历史三色不受影响——O3 快照
  表已把旧阈值冻结在行里，这正是 O3 的直接收益）。
- **展示配套**：每行显示当前阈值 + 最近一次修改时间（读 config_history）。

### T3 Trace 错例"改判"入口（P1）

- **位置**：下钻面板 Trace 错例行（问句·人工裁决·当前路由）加"改判"。
- **通道**：`PUT /api/intent-samples/{source_id}` —— **端点已存在**（42 页在用）。
- **设计判断**：**不直接改 trace_evalset.json**。那是派生物 + 内容寻址
  （O2 dataset_id），手改派生物会让"分数↔题库版本"的对应关系撒谎。正道是
  改源头 intent_samples → 触发 build_evalset 作业 → dataset_id 如实变化
  → 下轮 Trace 评测自动反映。前端做的是"改源头 + 一键重建"的串联。

### T4 负样本有效性复核（P2）

- **位置**：下钻面板 RAG 报告 suspect_answerable 行。
- **形态**：只读展示 top-1 证据（来源/片段/重叠度）+ "仍算负样本/换问句"标记
  （标记存 manifest 的 reviewer_notes，进 git 可评审）。**不做自动剔除**
  （硬剔除会因检索噪声误杀真负样本——既有纪律）。

### 明确不做（及为什么）

| 不做 | 原因 |
|---|---|
| 前端直接编辑 datasets/*.json | 派生物 + 内容寻址；手改让版本对应关系失效。改源头（intent_samples/语料）再重建 |
| 在线增删 CONFIG_SCHEMA 结构 | schema 是代码的一部分；在线改结构 = 绕过 review |
| 前端直跑门禁脚本 | 门禁毫秒级但 worker 阻塞风险 + 权限面扩大；门禁已在 nightly/CI 自动跑 |
| 免登录触发评测 | 沿用 jobs 现有 `Depends(current_user)`；评测触发消耗 LLM 配额，不能匿名 |

## 3. 实施顺序建议

1. **T1**（半天）：注册 4 个 job kinds + 评测页"立即跑批"按钮 + 进度显示。
   jobs/kinds 端点动态渲染，前端零硬编码。
2. **T2**（半天）：门禁行就地编辑（端点已存在，纯前端 + 一层值域校验）。
3. **T3**（1 天）：错例改判串联（复用 42 页端点 + build_evalset 作业）。
4. **T4**（可选）：负样本复核标记。

每步的验收判据：对应门禁扩充（eval_management 的 A/B/C/D 段各加断言），
手工触发一次真实作业走通"提交 → 进度 → 报告刷新 → dataset_id 变化"。
