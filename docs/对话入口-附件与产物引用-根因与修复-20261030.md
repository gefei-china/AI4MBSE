# 对话入口三个问题：根因与修复（2026-10-30）

> 用户反馈：
> 1. 通过「+」选「当前会话文件」，列表为空，但产物里明明有代码文件，为啥无法查看
> 2. 从产物列表添加文件到会话后，加上用户输入发送 → 异常，附件不见了、用户输入还在输入框、会话没发起
> 3. 「+」里其他几个操作是否走得通

## 问题 2（先讲，因为它是硬故障）：`const msg` 被重新赋值

`static/js/mods/12-chatsend.js`：

```js
async function sendChat() {
  const input = document.getElementById('chat-input');
  const msg = input.value.trim();        // ← const
  ...
  const _refs = (chatRefs||[]).splice(0, chatRefs.length);   // 引用被清空
  renderRefBar();
  if(_refs.length){ msg = _refs.map(...) + '\n\n' + msg; }   // ← 对 const 赋值 ⇒ TypeError
  input.value = '';                                          // ← 永远不会执行
```

`TypeError: Assignment to constant variable` 的抛点**正好夹在两行之间**，所以三个症状一一对应：

| 用户看到 | 对应哪一行没执行 |
|---|---|
| 附件（引用 chip）不见了 | `splice(0, len)` **在抛点之前**，已经清空 |
| 用户输入还在输入框 | `input.value = ''` **在抛点之后** |
| 会话没发起 | `pumpStream(...)` 在更后面 |

**证据**：修复前用真实浏览器跑同一路径 → `thrown = "TypeError: Assignment to constant variable"`；
修复后同一路径 → `thrown = null`，且库里落下的 user 消息正文是
`【引用 · 文件 · 测试产物 · SYSML_MARKER …】SYSML_MARKER part def Foo; 【引用结束】请检查这段模型`
—— 说明引用正文**确实随消息发出去了**（这是"能不能用"的最终判据，不是"没报错"）。

修法：`const msg` → `let msg`。

## 问题 1：「当前会话文件」列表为空

该面板（`10-chatinput.js: loadAttachProjectFiles`）此前**只扫一个数据源**：

```js
const mr = await api(`/api/conversations/${id}/messages?limit=50`);
// 从 messages[].attachments 提取
```

而本平台有**两个互不相通的"会话文件"数据源**：

| 数据源 | 存什么 | 谁写入 |
|---|---|---|
| `messages.attachments` | **用户上传**的附件 | `/api/upload` |
| `artifacts` | **AI 产出**的代码 / 文档 / SysML 视图 | 每轮收尾时登记 |

实测 conv 9779：`messages.attachments` 命中 **0 条**，`artifacts` 有 **9 条**（3 个代码文件 + 6 个 SysML 视图）
⇒ 面板显示「当前会话还没有文件」。用户的理解完全正确：产物里有代码文件，但入口看不到。

**现在合并两个数据源**，并在列表里标明来源（会话产物 · 代码 / SysML；会话附件 · 已入库）。

### 产物为什么不能塞进附件栏

后端 `_load_attachment_text` 只认两种附件来源：

- `doc_id`（文档库已解析 chunk）
- `url` 以 `/static/` 开头（上传文件）

而 `artifacts` 行的 `file_url` 实测是**空串**、也没有 `doc_id` ⇒ 硬塞进附件栏会被判
「不支持的地址」并进 `skipped`（模型会说"没收到附件"，这正是 B5-9 记录过的老坑）。
所以产物走**正文引用通道**（`artAddToChat` → `chatRefs`），内容和代码一起进 prompt。

### 「无法查看」：清单加了 👁 预览

原来清单只有「添加」一个动作 —— 想确认"这是不是我那个代码文件"必须先加进会话（会改上下文）。
现在每行右侧多一个 👁：产物打开预览面板，附件（有 url/doc_id）新标签页打开。

## 顺带修掉的两个隐患

1. **列表索引错位**：列表渲染用过滤后的下标调 `attachConvFile(i)`，
   而它取的是**全量**数组 ⇒ 搜索后点第一条，实际添加的是未过滤的第一条。
   现在用 `_attachProjectDocs.indexOf(d)` 取回真实索引。
2. **只加附件不打字时点发送毫无反应**：原 `if(!msg) return;` 静默返回。
   现在只要有附件/引用就允许发送（补一句「请查看我附加的材料」并提示），
   且该补语放在**主 Agent 校验之后**，避免"未选主 Agent"时先弹误导提示。

## 门禁：`tools/verify/verify_chat_entry_contract.py`（9 项 + 4 变异，已接 CI）

为什么必须有：这三处失效**全都"错了也不报错"** ——

- `const` 重赋值是**运行时**错误，`node --check` 实测 **exit 0**（抓不到）；
- 少扫一个数据源，页面表现是"空列表"，看起来像"本来就没有"。

| 断言 | 内容 |
|---|---|
| C1 | `sendChat` 的 `msg` 用 `let`，且存在「引用前置」赋值 |
| C2 | 无裸 `if(!msg) return`（只有附件时也要能发） |
| C3 | 清单同时消费 messages 与 artifacts |
| C4 | 点击索引回到全量数组（`indexOf`） |
| C5 | 产物走正文引用通道（`artAddToChat`），不进附件栏 |
| M1–M4 | 变异自证：改回 `const` / 复原裸 return / 去掉 artifacts / 索引退回过滤下标 ⇒ 各自必须判红 |

函数切分用「从 `function NAME(` 到**下一行列首的 `}`**」，不用括号配平 ——
后者在 `function f({a, b})` 这种**解构参数**上会把参数的 `}` 当函数体结束
（本轮试写通用扫描器时两条误报全部来自这里，已写进注释）。

## 诚实说明

- 浏览器验证时我自己踩了一个**测试错**：用 `#chat-area .msg.user` 数用户气泡，
  而实际 class 是 `.msg.u` ⇒ `userDelta=0` 被我误读成"用户消息没上屏"。
  复核后 `.msg.u` = 8、`.msg.user` = 0，产品无此问题。测试选择器已改正。
- 测试产生的临时会话（9843）与测试上传（doc 849/850 及其文件）已清理，未留在你的数据里。
- 预览对 **SysML 视图产物**依赖 `meta.sysml_views` 转结构化文本；若某条视图产物 `meta` 为空，
  预览会提示"没有可预览内容"（而不是空白面板）。
