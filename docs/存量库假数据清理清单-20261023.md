## 三、C 类：审计归属改写（2399 行，不删行）

**为什么改写而不是删**：`audit_logs` 带哈希链（NIST AU-9 / SOC2 CC2），删行会断链 ⇒ 反而制造"审计链被篡改"的更严重合规问题。

**为什么必须重算哈希链**：`core.audit._row_hash(prev_hash, user_name, event_type, detail, result, branch, ip, ua, request_id)` —— **`user_name` 是摘要入参之一**。裸改 `user_name` 会让该行 `hash` 与内容不匹配 ⇒ `verify_chain()` 立刻报「内容与摘要不符（行被篡改）」。实测本库 **4613 行全部已入链**（未入链 0 行）⇒ 这个坑必然会踩到。

脚本已实现 `_rebuild_audit_chain()`：按 id 升序逐行重算，首行 prev 取 `GENESIS`（64 个 0），口径与 `core.audit.audit()` 完全一致。
