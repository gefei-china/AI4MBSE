## 3. 为什么不能只删库行（核心发现）

`data/bootstrap/pipeline_assets.json` 是随代码走的配置快照，`database/bootstrap_assets.py::
_bootstrap_tables()` 在 `init_db()` 末尾按 `name` UPSERT。

关键在 `SPEC["agents"]["exclude"]` **刻意排除了 `status`**（模块头原话：「管理员停用某 agent
不该被自举重新打开」）⇒ **快照的 agents 记录里根本没有 `status` 列**。于是：

- 库里有该行 → 走 `UPDATE`，不覆盖 status（disable 状态得以保留）；
- **库里删掉该行 → 走 `INSERT` 分支**，`INSERT INTO agents (name, …)` 不含 `status`
  ⇒ 落 `database/schema.py` 的 DDL 默认 **`status='active'`**。

⇒ 只删库行，8 个视图 Agent 会在下次启动**以 active 复活**，重新进入语义索引与路由，
把 2026-10 已修掉的「细粒度视图 Agent 抢占主意图」错例全部带回来。

**这条不是读代码推的，是变异实证**：`verify_d1_view_agents_removed.py` 的 M1 把一条视图 Agent
塞回快照副本 → 用真实 `bootstrap_assets()` 灌进最小库 → 实测重建行
`('需求视图生成', 'active')`。M2/M2b 同时证明门禁判据能抓住它、且删掉该行后立刻转绿。

## 4. 快照为什么用「结构块行级删除」

快照 782,166 B / 6,129 行 / **纯 CRLF** / 无 BOM。实测
`json.dumps(ensure_ascii=False, indent=1/2/4/None)` 输出分别是
534,479 / 558,014 / 605,084 / 509,990 B，**没有一种能无损 round-trip**（原文是 `indent=2`
风格但含额外内容差异）。整体重排会制造约 17 万字节的假 diff，把「删 8 条」彻底淹没。

故采用**字节级结构块删除**：按 `      {` … `      },` 切块，只删含目标 name 的块，
其余行逐字节不动；删除后若有段末逗号则修正。落盘前 12 条硬自证：

- 格式：原/新快照均纯 CRLF、无 BOM、`json.loads` 合法；
- 结构：块切分数 == 5 个 JSON list 长度之和（33/260/22 等）；
- 语义：三个目标 list 与「原 list 减去目标记录」**逐项相等**；除这三个 list 外整份快照语义不变；
- 范围：删除块数恰为 **8 / 30 / 1**；8 个名字在 tables/relations 中 0 命中；保留项 `system_mgmt` 仍在。

段边界实测：`agents` L4–896、`tools` L897–3582、`skills` L3583–4451、
`agent_tools` L4454–6015、`agent_team_members` L6016–6127。

### 6.2 一处「假回归」的定性（如实披露解析口径缺陷）

用**严格 A/B** 定性（不是口头解释）：该脚本支持 `MBSE_DB_PATH` 重定向，
分别指向「D1 前备份库」与「D1 后当前库」跑同一脚本 —— 两份 stdout
**逐字节 IDENTICAL**（都是 `候选 Agent: 24 个` / `D1 只中 4/8` / `常态 35 通过 2 失败`）。

published 技能 35→35 逐字不变 ⇒ 标定分数不可能因 D1 变化。

## 7. 回滚

```bash
python -X utf8 tools/_p0_d1_remove_view_agents.py --rollback
```

`--rollback` 从留痕精确重插 8 + 30 + 1 行（**保留原 id 与所有列**），并用快照备份恢复快照；
恢复前断言当前快照 `sha256 == after_sha256`，若已被后续改动则**拒绝并提示人工 diff**，
绝不覆盖他人改动。全库备份只作极端情况参考，**不用于常规回滚**（会抹掉 D1 之后的其它写入）。
