## 3. 「检索段未接线」的接线形态（CI 文案已改）

`.github/workflows/ci.yml:1894` 原步骤名是「⚠ 检索段未接线」。这是**设计事实**
（`mbse.db` 约 378 MB 且含用户会话/附件，不入 git，干净 checkout 无语料），不是能靠改 CI 修好的故障。
P0-3 把它改成可验证的接线形态：

- **主路径**：本机 `tools/eval/run_nightly_local.py`（5 步 + 3 门禁，报告 checked-in 到 `docs/评测/nightly/`）；
- **常驻门禁**：`tools/verify/verify_eval_freshness.py` —— 硬判
  `eval_reports` 新鲜度 ≤7 天 / 存在 `is_golden=1` / `online_eval_queue.pending=0` /
  Golden Set 基线未漂移；软告警 `nightly/latest.json` 陈旧（实测 `updated_at=2026-10-23T10:31:56`，
  **23.21 天**）并提示人工触发本机跑批器；
- 门禁写 `docs/评测/eval_freshness_latest.json`（checked-in 快照）供 PR 侧消费，不写业务库、不调 LLM；
- CI 步骤名改为「检索段由本机跑批器承接（CI 不含语料库）」，三行 `::warning::` 改为指明主路径。
  ⚠️ **CI 侧仍未加执行步**：干净 checkout 没有 `mbse.db`，该门禁登记为 `tier=local`（非 pr）。

改 CI 用字节级替换（3 处命中数断言 = 1/1/1）+ `yaml.safe_load` 终检（3 个 job）+ CRLF 一致性对拍
（1982/1982），未产生孤 LF。
