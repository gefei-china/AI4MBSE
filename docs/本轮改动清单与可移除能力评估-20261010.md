## 4. 哪些不需要的能力可以移除

### 4.1 ✅ 建议移除：`ragflow-main`（67MB）

**实测依据**（已跑验证，非推断）：
```
sdk_available() : True → False        （把 sdk/python 改名后实测）
ragflow_chunk() : mode=skip reason=未启用  ← 安全降级，不抛异常
```

**移除影响**：
- `ragflow_adapter.py` 自动 `sdk_available()=False` → `mode=skip`
- **入库主链路零影响**（本来就是默认关闭）
- `chunking_deepdoc.py` **完全不依赖它**（纯本地重写）⇒ L1 不受影响

**建议做法**：**移出仓库**（不要删）到 `tmp/` 或工程外的参考目录，
保留 1 个文件 `qa.go` 作为算法出处凭证即可。

### 4.2 ⚠️ 可选移除：`ragflow_adapter.py`（368 行）+ 6 项配置

**移除代价与收益**：

| | 说明 |
|---|---|
| 收益 | 少368 行代码 + 6 项配置（含 2 项含 API Key 的敏感项） |
| 代价 | 若将来部署 RAGFlow，要重写适配层（但**算法知识已在 `chunking_deepdoc.py` 里，不会丢**） |
| 风险 | **零** —— 现在就没启用，删了行为完全不变 |

**我的建议**：
- 如果**确定不部署 RAGFlow** ⇒ 可以移除（`ragflow_enabled=False` 已保持好几个版本）
- 如果**可能将来要用** ⇒ 保留但**移到 `tools/` 或标 experimental**，
  别让它混在生产链路里（`knowledge_pipeline/` 是主链路目录）

### 4.3 ❌ 建议保留：L2 二进制缓存

- 27MB 磁盘（`tmp/vec_cache/`，**可随时删、秒级重建**）
- 换来 **399×** 检索加速
- 判据证明：删缓存后结果完全一致

### 4.4 ❌ 建议保留：`chunking_deepdoc.py`（L1）

零依赖、零 import 代价、**不依赖 ragflow-main**，且治的是实测发现的真缺陷
（60.4% 重复率 + 1261 种脏标记）。

⚠️ 但它**现在是关闭的**（`hyde_heading_enabled=False`）——
**要不要开，这是待你拍板的独立决策**（开关一开，新入库文档的问句质量立刻改善）。
