# 多工程数据体现设计方案 — AI4MBSE 平台

> 作者视角：AI 产品经理 × MBSE 领域专家
> 日期：2026-08-31
> 适用范围：mbse_system（AI4MBSE 知识流水线）—— 对接多建模工具、管理多工程项目的 AI 平台

---

## 一、结论先行

**核心判断：系统已具备工程的数据层（`projects` 表 79 个工程 + `conversations.project_id` + 工程图谱/记忆 API），但前端交互层完全没有工程感知——工程维度在建模入口"隐身"了。**

用户进入 AI 建模页的现状：顶栏一个**只读**「当前工程：星网宽带通信系统」标签（不可点、不可切换）、会话侧栏 14 个会话**平铺混排**、新建对话不感知工程、生成产物不标注归属、写回工具不带工程参数。

**一句话方案：把"工程"从数据层属性提升为产品层的顶层上下文（Top-level Context）——建模入口以「工程切换器」为锚点，工程上下文级联贯穿 会话/文档/图谱/产物/写回 五条链路，做到"切工程 = 切工作区"。**

| 维度 | 现状 | 目标 |
|------|------|------|
| 工程感知 | 顶栏只读标签 | 可交互工程切换器（全局级联） |
| 会话组织 | 平铺混排 | 按工程分组，当前工程置顶展开 |
| 数据隔离 | 无（全量混在一起） | 工程上下文过滤（文档/图谱/集成/记忆） |
| 产物归属 | 无标注 | 产物卡带工程徽标，可跳转工程 |
| 工具写回 | 无工程参数 | 写回 API 带 `project_id`，写入对工程模型 |
| 工程管理 | 无前端入口（仅 API） | 工程列表页 + 工程详情 + 工具绑定 |

| 能力 | 实现 | 证据 |
|------|------|------|

### 2.2 交互层——工程维度隐身（核心矛盾）

| 入口 | 现状 | 代码证据 |

### 2.3 判断

- **数据层就绪度 ~70%**：工程实体、默认工程、工程图谱、工程记忆都有后端
- **交互层就绪度 ~10%**：唯一体现是只读标签
- **缺的关键件**：① 工程切换器（前端）② 会话-工程分组 ③ 工程上下文注入（创建/查询/过滤）④ 工程-工具绑定表 ⑤ 工程管理页

## 三、行业范式借鉴

| 产品 | 工程/项目模型 | 对本次设计的借鉴 |
|------|--------------|------------------|
| **SysML v2 API**（OMG 标准） | `Project` 是一级资源（`POST /projects`），Namespace 挂工程下；库与模型分命名空间 | **工程 = 模型容器 + 库引用**；写回 API 以 Project 为根 |
| **Cameo + Teamwork Cloud** | 中央服务器项目库，项目卡片（名称/图标/权限），模型分区（Model Sections） | 工程卡片式列表 + 工程级权限 |
| **Rhapsody + Model Manager** | Model 浏览器：每 Model 独立工程，基线/签出签入 | 工程级版本/基线（对接现有 branches） |
| **智源平台**（米爸对接） | `projectId + branchId`，`project_list`/`tree` 工具选择工程树 | **工程树 + 分支两级**，会话工具带工程上下文 |
| **GitHub / Git** | 仓库 = 工程，仓库选择器 + 分支切换 | 切换器交互范式：搜索 + 最近 + 星标 |
| **Notion / 语雀** | 空间切换器（工作区概念） | 全局级联：切空间 = 切全部内容 |

**提炼 3 条设计原则**：

1. **工程是一级上下文，不是字段**——切工程要像切 IDE 项目/切仓库一样，全局级联
2. **工程 = 模型容器**（SysML v2 语义）——写回工具、图谱、产物都以工程为根
3. **全局共享 vs 工程私有分层**——本体/术语词典（Schema 主数据）默认全局共享，工程内可 override（呼应既有 D-3 决策：知识库分支为单一事实源）

## 四、目标工程数据模型

```
┌─────────────────────────────────────────────────┐
│  Project（工程）= 顶层上下文                       │
│  id / name / code / domain(领域) / status         │
│  ontology_profile_id(本体Profile)                 │
│  scenario_template_id(场景模板)                   │
├─────────────────────────────────────────────────┤
│  工程内数据（全部挂 project_id）：                 │
│  ├── Conversation 会话      ← 建模入口核心载体     │
│  ├── Document 文档          （branch: global/dev）│
│  ├── Triple / Graph 三元组  （工程图谱 API 已备）  │
│  ├── Artifact 产物          （SysML/报告/代码）    │
│  ├── ProjectMemory 工程记忆 （API 已备）           │
│  └── Branch 分支            （版本/基线）          │
├─────────────────────────────────────────────────┤
│  工程-工具绑定（新增 model_tools 表）：            │
│  project_id │ tool_type(MagicDraw/SysMLv2API/…)   │
│  │ endpoint │ auth │ default_target │ status      │
├─────────────────────────────────────────────────┤
│  全局共享（不挂工程）：                            │
│  本体模型 / 术语词典 / 场景模板 / 技能 / 工作流    │
└─────────────────────────────────────────────────┘
```

**新增 1 张表 `model_tools`**（工程↔工具绑定，写回通道的数据基础）：

```sql
CREATE TABLE model_tools (
  id INTEGER PRIMARY KEY,
  project_id TEXT NOT NULL,          -- 归属工程
  tool_type TEXT NOT NULL,           -- magicdraw / sysmlv2_api / cameo / ...
  name TEXT,                         -- 工具实例名（如「星网-开发模型」）
  endpoint TEXT,                     -- 连接地址（API 通道）
  auth TEXT DEFAULT '',              -- 凭据引用
  default_target INTEGER DEFAULT 1,  -- 是否默认写回目标
  status TEXT DEFAULT 'active',      -- active / offline
  UNIQUE(project_id, tool_type, name)
);
```

## 五、建模入口设计方案（核心）

### 5.1 全局工程切换器（顶栏 tag 升级为交互控件）

**现状**：`ai-project-tag` 只读 → **目标**：可点击下拉（仿 GitHub 仓库切换器）

```
[● 当前工程：星网宽带通信系统 ▾]        ← 顶栏，点击展开下拉
┌────────────────────────────────┐
│ 🔍 搜索工程…                    │
│ ── 最近使用 ──                  │
│ ● 星网宽带通信系统  satnet  卫星通信 │
│   TMS 热管理(20260828)  tms   汽车  │
│ ── 全部工程（按领域分组）──       │
│ 卫星通信 (3)                    │
│   📡 星网宽带通信系统  14 会话    │
│   📡 星网窄带通信系统  0 会话    │
│ 汽车热管理 (12)                 │
│   🚗 TMS-1785914453    0 会话   │
│ …                              │
│ ───────────────               │
│ ＋ 新建工程  ·  ⚙ 工程管理       │
└────────────────────────────────┘
```

**交互规格**：
- 点击 tag 展开下拉；显示**当前工程徽标 + 会话数 + 领域**
- 支持搜索（名称/code/领域）；最近使用置顶；领域分组折叠
- 切换 → 调 `POST /api/projects/default` + 本地缓存 → 触发全局级联（见 5.4）
- 未匹配工程 → 红色警示态 +「新建工程」引导（承接现有 `nomatch` 态）

### 5.2 会话侧栏按工程分组

**现状**：14 会话平铺 → **目标**：

```
▾ 💬 星网宽带通信系统（当前）     14
    ├ 宽带通信需求分析       D12意图增强
    ├ 图谱消费验证           SysML版本入库…
    └ …（仅显示本工程会话）
▸ 📦 其他工程会话           3
    ├ 星网导航增强系统      1
    └ TMS 热管理            2
```

**交互规格**：
- 当前工程会话**置顶展开**（`GET /api/conversations?project_id=当前`）
- 其他工程会话收进折叠组（避免丢失，不删除）
- 新建对话：`POST /api/conversations` body 增加 `project_id`（当前工程）——后端已支持字段
- 会话条目加工程色点（按领域配色），鼠标悬停显示归属

### 5.3 工程上下文注入（建模入口的隐性体现）

| 交互点 | 体现方式 |
|--------|----------|
| `@ 选择会话文件` | 只列**当前工程**关联文件（会话附件 + 文档库按 branch/工程过滤） |
| `# 引用知识库文件` | 默认过滤到当前工程文档（可切"全部工程"） |
| 输入框 placeholder | 增加工程提示：「在 [星网宽带] 中… 输入建模需求」 |
| 生成产物卡 | SysML 整合卡头部加工程徽标 `[📡 星网宽带]`，可点击跳工程详情 |
| 写回弹窗 | 默认目标 = 当前工程绑定的 `model_tools`；写回 API 带 `project_id` |
| 一致性校验/归一报告 | 报告头部标注工程上下文 |

### 5.4 工程切换级联（数据流）

```
切换工程（选 project-satnet-narrowband）
        │
        ▼
┌─ POST /api/projects/default ─┐
│ 顶栏徽标刷新                   │
│ 会话侧栏重载（按新工程过滤）    │
│ 文档库重载（branch/工程过滤）   │
│ 实例图谱重载（project_graph）  │
│ 数据集成入图目标切换            │
│ 写回默认工具刷新（model_tools）│
│ 工程记忆上下文刷新              │
└──────────────────────────────┘
```

**关键设计**：切换是**软隔离**（不销毁当前页面数据，仅重载上下文），避免切工程导致已打开内容丢失。

### 5.5 工程内资产概览（建模页上下文底座）

当前工程信息条（会话侧栏顶部 or 建模页顶部第二行）：

```
[📡 星网宽带通信系统] 领域:卫星通信 · 实体 237 · 三元组 1.2k · 文档 8 · 会话 14 · 分支 dev
[🔄 同步状态] 模型同步: 3 次 · 上次 2026-08-30 22:14 · 工具: MagicDraw(在线) / SysMLv2API(离线)
```

## 八、落地路径

### P0 — 工程上下文闭环（建模入口，2-3 天）
1. **G1 工程切换器**：`ai-project-tag` 升级为下拉组件（搜索/分组/切换），切换调 `POST /api/projects/default`
2. **G3 会话绑定**：`createConversation` 带 `project_id`；`GET /api/conversations` 支持 `?project_id=` 过滤
3. **G2 会话分组**：`loadConversations()` 按当前工程分组渲染
4. **G5 写回带工程**：`model_tools` 表 + 写回弹窗默认目标读当前工程绑定
5. **G4 产物徽标**：SysML 整合卡头部工程徽标
6. **G6 图谱接入**：实例图谱页加工程筛选，走 `project_graph`

### P1 — 工程管理（4-5 天）
7. **G7 工程列表页**：卡片/表格 + 资产统计（实体/三元组/文档/会话）
8. **G8 工程详情页**：概览 + 图谱缩略 + `model_tools` 绑定管理 + 工程记忆 tab
9. **G10 用户级默认工程**：`settings` 表按 user 存 `default_project_id`
10. **G9 工程 RBAC**：`project_members` 表（user × project × role）

### P2 — 工程协作与治理（后续）
11. **G11 版本矩阵**：branches 加 `project_id`，工程×分支视图
12. **G12 Schema 分层**：本体/术语词典 全局共享 + 工程级 override（对齐 D-3 决策）
13. 工程间数据比对/复用（对比两个工程的图谱差异）
