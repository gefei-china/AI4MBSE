# 意图识别优化调研与方案（2026-10-23）

> 触发：米爸实测反馈——"AI 执行任务时，每次提示的意图识别与推荐的不一致，
> 感觉很不好。主流 agent 平台会基于用户输入与上下文精准识别意图，这是我们的
> 不足。认真调研分析，怎么优化意图识别实现方案。"
> 本文 = 案例复盘 → 现状解剖（实测）→ 行业对标（带来源）→ 根因 → 分级方案。

---

## 0. 结论（先看这个）

**判词：不是"识别算法不行"，而是"识别的架构性位置错了"。**

1. 当前 LLM 只是**高门槛兜底**（自报置信 <0.85 一律不采纳，落到 chat），
   而主力是关键词 + bigram 余弦——对"没有命中关键词表的实质问题"天然无力；
2. **chat 一个桶装了两个语义**（真闲聊 vs 判不了），歧义输入全部落 chat 且直接展示；
3. **两个裁判互不通气**：路由层小模型说 chat，执行层大模型结合上下文说 knowledge_qa，
   两句话同时打在思考过程里给用户看——"不一致"是必然产物；
4. 主流平台（Coze / Dify / LangGraph 生态）的共识做法是：**LLM 主裁判 + 枚举约束
   结构化输出 + 每意图 few-shot 示例 + 带最近 3 轮上下文 + 显式 unsure 出口 → 澄清**，
   我们四项都缺或有严格限制。

推荐路线（三步，P0 一天内可落地）：**P0 和解与降噪（先让用户看不到自相矛盾）→
P1 LLM 主裁判改造（试点一个开关，A/B 对照）→ P2 校准与数据飞轮**。
每一项都有验收判据，且现有评测基建（29 例意图评测 / Trace 228 条 / neg 30 条）
可直接复用为回归网。

## 1. 案例复盘（截图会话）

用户显式选择执行主体"智源对接agent"，输入一道实质性问题，观察到的三句话：

| 来源 | 说的什么 |
|---|---|
| 路由层（IntentRouter） | 语义识别结果为 **chat** |
| 显式定向提示 | "（意图定向）已按显式选择执行：智源对接agent；语义识别结果为 chat，两者不一致…" |
| 执行层 LLM（思考过程） | "结合上下文判断你的事情已明确（**knowledge_qa**）…本次未触发知识检索（询问容/无 # 标签）" |

三重问题叠加：
① 路由层把实质问题判成 chat（识别弱）；② 执行层又判成 knowledge_qa（两裁判打架）；
③ 执行层还以"无 # 标签"为由**没触发知识检索**（识别结果被用于检索门控，错判有下游代价，
不只是展示问题）。

## 2. 现状解剖（基于 agent/intent.py 实读 + 评测数据）

### 2.1 现行五层瀑布（agent/intent.py detect）

```
explain 特例(0.80) → 缓存(默认关) → 多意图切分
→ 规则关键词层：打分融合（规则∩语义一致 0.92 / 冲突 0.60）或首中 0.95
→ 语义层（bigram 余弦，零外部依赖）：≥0.70 采纳；<0.70 有 prev_intent 则继承(0.55)
→ LLM 兜底：JSON {intent, confidence}；conf<0.85 → 继承 prev；弱猜测→chat@≤0.5
→ 会话继承 prev_intent → chat@0.0
```

实测水平：干净库 29 例意图评测 **0.931**；Trace 一致率 **0.881**（42 条生产人工裁决）；
weak 样本路由分布 **chat 占 44%**——大量真实流量被归入 chat。

### 2.2 防御性补丁史（值得尊重，但已到收益边界）

代码里布满真实误路由换来的防线：V2.6（requirement_quality 仅词法触发）、
缓存毒化双防线、`_sanitize_history`（历史强特异词以 0.95 劫持路由 → 历史只喂 LLM
且仅限"确认"语义）、噪声上文实验（把 LLM 推到 0.90 的错误结论 → "无 prev_intent
不带上下文"）。**这些防线全部正确**，但它们共同把架构锁死在：
"规则/词法为主、LLM 为奴、上下文饿死"——每一层单独看都对，合起来就是
"判不出 → chat"。

### 2.3 五个结构性根因

| # | 根因 | 证据 |
|---|---|---|
| **R1** | **LLM 是兜底不是主裁判**：采纳门槛 0.85，且仅在规则+语义全部无信号时才被调用 | detect 流程；LLM 弱猜测一律 chat |
| **R2** | **上下文被刻意饿死**：无 prev_intent 不带任何历史；带历史也只许"确认"不许"改判" | P0-5 v2 注释（噪声实验） |
| **R3** | **chat 双语义**：真闲聊 与 "判不了" 共用一个桶，歧义输入全落 chat 且对用户可见 | weak 44% chat；本案例 |
| **R4** | **双裁判无和解**：路由层与执行层各判各的，差异以原始技术文案直出（"两者不一致…请去掉指定后重发"——把系统内部矛盾推给用户） | stream.py:3539 |
| **R5** | **无 few-shot、无 unsure 一等出口、无校准**：detect_llm 提示词只有意图名列表，每个意图没有示例；自报 confidence 从未用标注数据校准 | detect_llm 提示词实读 |

### 2.4 一个必须澄清的边界

显式选择主 Agent 后"仍要跑识别"本身是**对的**（V2.7 决策：目标/槽位/澄清/
多意图都依赖识别结果）——不该退回"选了 Agent 就跳过识别"。要修的是识别质量
与两裁判和解，不是砍掉识别。

## 3. 行业对标（来源见文末）

| 平台/实践 | 做法 | 对我们的启示 |
|---|---|---|
| **Coze 意图识别节点**（官方文档） | LLM 分类器**默认带最近 3 轮会话历史**；每个意图配**典型示例描述**（few-shot）；极速/完整两档模型；未匹配任何意图 → **兜底分支** | 上下文默认开启而不是默认关闭；每意图给示例；unsure 是一等出口 |
| **Dify 分类器节点 + 客服实践** | 分类器做粗分流，子流程内再做精细条件；置信度低于阈值 → 转人工/兜底流程 | 粗粒度 LLM + 细粒度规则的**分层**是对的，我们缺的是粗层用 LLM |
| **LangGraph 生态（2026 生产指南）** | 分类用**小而快的模型 + 枚举约束结构化输出**；"always include a fallback route；a router without unsure is a misrouting machine"；**记录每次路由决策，误判样本变成下一批 few-shot** | unsure 必须显式存在；路由日志即训练数据（对应我们的 trace2dataset） |
| **弃权与校准实践**（structured-control 资料集） | 把 "unknown" 做成 schema 里的一等枚举值；自报置信度**普遍过自信**，需用标注数据重映射（calibration） | 我们从不校准——0.85 门槛是拍的，不是标定的 |
| **中文 LangGraph 实践（CSDN 166047693）** | 两步走：顶层意图分类（候选 ≤10 个"选择题"）+ 槽位填充；conf<0.6 → 澄清模式回问 | "把作文题变成选择题"+澄清闭环，比提高门槛更有效 |

**共识画像**：LLM 主裁判（小模型即可）、枚举约束输出、few-shot、上下文默认开启、
显式 unsure → 澄清而非静默 chat、路由日志喂 few-shot 的飞轮。**我们没有一项是
不可实现的**——detect_llm 已经在输出 JSON，差的只是位置与待遇。

## 4. 优化方案（三步，可独立验收）

### P0 和解与降噪（不动识别内核，一天内）

1. **单一事实源展示**：显式定向时，思考过程不再直出"语义识别结果为 X，两者不一致
   …请去掉指定后重发"这种把矛盾推给用户的话；改为一句中性说明
   "已按你选择的「智源对接agent」执行（识别意见：knowledge_qa，仅供编排参考）"。
   两裁判分歧**照常记录进 meta/日志**（可观测不减），只是不再用技术措辞刷屏。
2. **识别意见供检索门控参考**：执行层以"无 # 标签"跳过知识检索的判据，
   增加"路由层非 chat 或执行层判为知识类"的或分支——错判不再直接丢检索。
3. **chat 桶拆分（观测侧先行）**：`_last_meta` 增加 `verdict: chat_real |
   unsure`（判据：走到第几层 + 置信），前端与日志可区分"真闲聊"与"没判出"。
   只加观测不改路由，零回归风险。

验收：截图场景三句话不再互相打架；意图评测 29 例 + Trace 回归全绿。

### P1 LLM 主裁判改造（试点开关，一周量级）

新增 `intent.llm_first`（默认 false，A/B 对照）：
1. **LLM 提前为主**：规则层打分融合仍在（强信号快路径保留，0.92/0.95 不动），
   但**规则无信号时直接 LLM 为主裁判**，采纳门槛降为 0.60（待标定），并带：
   - **上下文默认开启**：最近 3 轮用户话 + prev_intent，提示词明确
     "上文用于补全省略与指代，并允许据此改判"——Coze 同款；`_sanitize_history`
     保留（防劫持的教训仍适用），但限制从"只许确认"放宽为"允许改判 + 要求给出依据"。
   - **每意图 few-shot 3 例**：从意图样本池 confirmed 样本自动挑选（初始手工配，
     后续由 P2 飞轮补充）——Coze/结构化路由资料集同款。
   - **unsure 一等出口**：枚举加 `unsure`，替代"置信低就塞 chat"——
     unsure 触发**澄清卡**（复用现有意图确认机制），绝不静默落 chat。
2. **双人裁判和解**：LLM 主裁判意见与规则/语义意见不一致时，取 LLM（试点期），
   但把双方与依据写进 meta（trace 可见）——为 P2 校准积累对照数据。
3. **回归网**：29 例意图评测 + Trace 一致率 + neg 30 条（chat 误报）三套门禁
   全绿才可开默认开关；llm_first 开/关各跑一轮意图评测出对比表。

验收：llm_first 下 29 例 ≥ 旧口径（0.931 不回退）；weak 样本 chat 占比显著下降
（44% → 目标 <25%）；截图场景语义识别不再是 chat。

### P2 校准与数据飞轮（持续）

1. **置信度校准**：用 confirmed 样本池（生产人工裁决）测自报置信的可靠性，
   重映射门槛（弃权实践：自报分普遍过自信，须标定）——把"0.85 是拍的"变成
   "0.65 是标定的"。
2. **误判 → few-shot 飞轮**：路由决策已全量落 trace；bad_cases/Trace 错例经
   人工改判后（T3 改判入口已就绪）自动成为该意图的 few-shot 候选——
   "misroutes become your next few-shot examples"。
3. **槽位化**（可选，后置）：多意图切分已有；若澄清率高再上两步走
   （顶层分类 + 槽位填充），不预做。

## 5. 风险与代价

| 风险 | 对策 |
|---|---|
| LLM 主裁判增加时延（~1 次调用） | 小快模型 + 仅规则无信号时调用（多数实质问题本来就走不到 LLM 就错完了）；缓存已备 |
| 上下文改判的噪声风险（历史教训） | `_sanitize_history` 保留；提示词强制"给出依据"；试点期 A/B 对照；trace 全量可回放 |
| 误开检索的代价 | P1 与检索门控或分支联动，neg 30 条门禁盯 chat 误报 |
| 评测集覆盖不足 | 29 例是干净库口径；llm_first 上线前用 trace 228 条（含 42 条人工裁决）做第二回归网 |
