## 1. 开工先量了一次幂等性，问题比那条例子大得多

上一轮只看到「`SysML v2` 会变成 `SysML_SysML_V2`」这一个样本。这轮先做了一件
更基础的事：**对存量 query 做"再归一化一次"检验**（`normalize(normalize(x))`）。

| 范围 | 结果 |
|---|---|
| 3000 条样本 | **699 条（23.3%）再归一化还会变** |
| 6572 条全量 | 1030 条（15.7%）old/new 结果不同，其中 **1012 条是旧串更长** |

一个 23% 的 query 都不满足幂等性的函数，不是"个别串有毛病"，是算法结构有问题。

## 2. 真因：12 条词条的 canonical 自己包含自己的 user_term

不是 `v2` 一条规则的事。词表（概念层 124 + 路由层 10）里有 12 条 entry 属于
「规范词包含原词」：

```
宽带     → 宽带通信              巡飞   → 巡飞待机
v2       → SysML_V2              ibd    → 内部块图_IBD
语法规范 → SysML_V2 语法规范       v波段 → V波段_卫星通信频段
bdd      → 块定义图_BDD          tms    → 热管理系统_TMS
```

而原实现是**多轮** `re.sub`：

```python
for r in sorted(hits, key=len, reverse=True):
    out = pat.sub(r["canonical_term"], out)      # 后一轮作用于前一轮的结果
```

⇒ 替换产物被下一轮再次扫描，每轮把串撑长一截：

| 原文 | 旧输出 | 新输出 |
|---|---|---|
| `宽带通信` | `宽带通信通信` | `宽带通信` |
| `巡飞待机弹` | `巡飞待机待机弹` | `巡飞待机弹` |
| `SysML v2` | `SysML_SysML_V2` | `SysML_V2` |
| `内部块图_IBD` | `内部块图_内部块图_IBD` | `内部块图_IBD` |

**第二个独立缺陷**：词边界是 `[A-Za-z0-9]`、不含 `_`。而规范词普遍带下划线
（`SysML_V2` / `内部块图_IBD` / `热管理系统_TMS`）⇒ 规范词内部的 `V2` / `IBD`
会被 `v2` / `ibd` 规则重新命中。两条缺陷叠加，才产出 `SysML_SysML_V2`。

## 3. 为什么必须修：召回不可复现

同一条 query 因为**被归一化的次数**不同而得到不同检索串：

- 一次 → `宽带通信载荷`（能召回）
- 两次 → `宽带通信通信载荷`（召不回原文能命中的 chunk）

而"被归一化几次"取决于调用链（`retrieve` 直调 / pipeline 拼装后再调 / 复跑评测）。
⇒ 同一个问题、同一个库，召回结果不可复现。这与上一轮 `query_raw` 是同一族问题：
**送进检索的那个串，来源必须是确定的**。

## 4. 修法：回到原文做单遍替换（三条规则，缺一条都有反例）

```python
def _span_replace(text, hits):
    # 1) 在**原文**上定位所有候选（长词优先的排序在收集后统一做）
    cands = [...]
    # 2) 长词优先 + 区间互斥：重叠时只取长的
    cands.sort(key=lambda t: (-t[3], t[0]))
    # 3) 拼接输出：canonical 只写进 out，绝不再参与扫描
```

三条规则各自不可省：

| # | 规则 | 去掉会怎样（门禁实测） |
|---|---|---|
| 1 | 原文单遍 + 区间互斥 + 长优先 | 短词打碎长词产物（M1 翻红） |
| 2 | 边界集含 `_` | `A_V2_C` → `A_A_V2_B_C`（M2 翻红） |
| 3 | 「原文该处已是完整规范形态」则跳过 | `宽带通信` → `宽带通信通信`（M3 翻红） |

第 3 条容易被漏掉：它**不是扫描问题，是膨胀问题**，光做单遍修不掉 ——
`宽带`→`宽带通信` 这条映射对已规范的 `宽带通信` 依然会命中。判据取**对称**形式
（canonical = `prefix + 命中片段 + suffix`，前后都在原文里才算已规范），
因为两种形态都存在：

- suffix 型 `宽带`→`宽带通信`：要看命中片段**之后**是不是已经是 `通信`
- prefix 型 `语法规范`→`SysML_V2 语法规范`：要看**之前**是不是已经是 `SysML_V2 `

只判前向或只判后向，另一种就会在二次归一化时叠加成
`SysML_V2 SysML_V2 语法规范`。

顺带保留一个既有行为：`ibd` → `IBD` 的大小写归一（等值但大小写不同仍要替换）。
第一版写成了"等值即跳过"，门禁 N5 当场抓出来。

## 8. 门禁设计：为什么核心判据是「幂等性」

`verify_glossary_normalize_idempotent.py` 的主判据是
`normalize(normalize(x)) == normalize(x)`，而不是逐条比对期望输出。

理由：逐条比对只能覆盖写进用例的那几个串，而这类缺陷的形态随词表增长而变
（今天 12 条 entry 触发，明天加一条 `雷达→雷达系统` 又多一类）。幂等性是
**性质**，不是**样本**：它等价于"替换不自我放大"，对任何词表内容都成立。

配套的 6 条合成反例（长优先 / 区间互斥 / `_` 边界 / suffix 型 / prefix 型 / 等值）
负责在性质之外钉住"为什么幂等"的具体机制。

**变异自证踩过的坑**（第一版就中招）：M2（去掉 `_` 边界）最初用
`SYSML_V2` 做用例，结果它被 `_already_canonical` 先一步跳过 ⇒ 变异不翻红；
而当时 N5 恰有一条恒红的判据 ⇒ M2 被"假翻红"判成 PASS。换成 `A_V2_C`
（canonical 不是原文的 `pre+命中+suf`，只有边界能挡）后才真红。
**判据翻红的原因必须能指着说清是哪一条**。

另一个刻意的取舍：N13 写成「**不新增**膨胀模式」而不是「输出无膨胀」。
存量 394 条 query 本身就是旧实现的污染产物（`宽带通信通信载荷…`），
已无法区分"原文两处宽带"与"一次膨胀"—— 拿它判红等于要求代码修复历史数据，
门禁会长期恒红、失去信号。
