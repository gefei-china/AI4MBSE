# 第 24 轮：术语边界与门禁清理（2026-11-08）

指令：「继续」。承接上一轮报告「未做」清单中的第 ③ 条（`match()` 与 `normalize()`
口径不一致）与第 ② 条（两条既有红门禁）。

## 一、这条"口径不整齐"是有案底的

上一轮把它记成"hits 宽、替换严，当前不影响正确性"。实际查下来，
**宽的那一侧恰好是下游用来定路由的**：

| 消费点 | 用途 |
|---|---|
| `agent/rag.py:231` | `resolve()` → `force_domain` → `hybrid_search(domain=…)` 强制域过滤 |
| `agent/intent.py:95` | `bool(hits)` ⇒ 判「是不是知识问题」 |
| `agent/intent.py:1047` | `force_intent` ⇒ 直接路由到 `knowledge_qa`（置信 0.95） |

而 `match()` 当时是 `user_term.lower() in text.lower()`（纯子串）。真库 6579 条
query 实测被污染的规模：

| 假命中 | 出现位置 | 条数 | 被钉到的域 |
|---|---|---|---|
| `PA` | `part` / `Part` | 452 | satellite_comms |
| `SA` | `satisfy` | 248 | satellite_comms |
| `CEP` | `accept` | 57 | loitering_munition |
| `LM` | `AI/LLM` | 50 | loitering_munition |
| `tms` | `EVTMS` | 5 | thermal_mgmt |
| `Antenna` | `AntennaInterfaceUnit` | 5 | satellite_comms |

`part` / `satisfy` 都是 **SysML 语法自身的词** —— 越是在问 SysML 的问题，
越容易被钉到卫星通信域。这与 `_domain_usable` 里记的 60+ 条空域术语、
`ref part` 的 20→0→20 抖动是同一个根因；`_domain_usable` 只是**事后**兜住
空域（satellite_comms / loitering_munition 库内 0 chunk ⇒ 跳过），
假命中本身仍在（`force_intent` 照样被强制、前端照样显示 PA）。

## 二、边界规则：按 term 自身首尾字符决定

三个方向都试过，只有这一个同时成立：

| 规则 | 反例（实测） |
|---|---|
| 一律不加边界（旧 `match`） | `PA` 命中 `part`、`SA` 命中 `satisfy` |
| 一律加边界 | `转发器EIRP` 里 `转发器` 被漏掉（`_span_replace` 旧行为） |
| **ASCII 边缘加、CJK 边缘不加** | 两侧反例都消失 |

`_` 不算词内字符（标识符分段符）。上一轮为防膨胀把 `_` 算作词内字符，虽有效
但用错了层：蛇形标识符整串当 token ⇒ `sysml_v2_validate` 里 `SysML_V2`/
`sysml`/`v2` 一个都命中不了。实测 intent 翻转 470 条里 **360 条**是这类信号丢失。
真正的膨胀防护是「原文该处已是规范形态则跳过」（`_already_canonical`）——
`_` 不参与边界后，存量 6579 条**非幂等仍为 0、新增膨胀仍为 0**。

实现上抽成 `_term_pattern()` + `_term_in()`，`match()` / `match_concepts()` /
`_span_replace()` **三处共用一份定义**（带编译缓存，避免每条 query 134 次 compile）。

## 四、两条既有红门禁：根因都不是"环境问题"

### 4.1 `verify_entity_resolver` 74/77 → 77/77

`fcaeba2`（10-30，修「非拉丁连写串 fuzzy 恒 0」）删掉了 `_LATIN_ONLY` 守卫，
条件只剩 `len(tok) > 2` ⇒ **中文 token 也被拆字符**：

```
转发器a  → bigram {转发, 发器, 器a}  ← "器a" 是跨界 bigram
```

于是 `转发器A ⇄ 转发器B` 由 0.6667 掉到 0.5000，同时 M9/M12 的变异锚点
（含 `_LATIN_ONLY`）一起失效 —— 门禁"红"其实是两件事叠在一起。

`fcaeba2` 要解决的是「**中文之外**的非拉丁文字」（日文假名 / 西里尔等）整串
只算 1 个元素；中文本来就有 `zh` bigram 通道。故守卫应写成「**不含中文**」：

| 用例 | 改前 | 改后 |
|---|---|---|
| `转发器A ⇄ 转发器B` | 0.5000 | **0.6667**（基线恢复） |
| `宽带载荷 ⊂ 宽带载荷分系统` | 0.75 | 0.75 |
| `VehiclePowerManagement ⇄ …Req` | 0.9545 | 0.9545 |
| `ПриемникА ⇄ ПриемникБ`（西里尔） | 0.7778 | 0.7778（`fcaeba2` 意图保留） |

M12 现在变异出**的正是** `fcaeba2` 之后、本轮修复之前那段代码 ⇒ E43 必然翻红。

### 4.2 `verify_norm_summary` 9/12 → 14/14

端点后来加了归属校验（B1-9 `_own_conv`），夹具却一直传 `user={}` ⇒
`conv_visible_to` 把它当成 `id=0` ⇒ 样本会话一旦有归属人，D2/D4 整体 404。
修夹具（按会话归属人身份调用），并**补 D2c**：非归属人必须 404 —— 否则
"只读性"可能只是在"看不见的资源"上跑。M1 变异体同样按归属人调用
（否则变异体 404、M1 变成"无输出"，看起来像产品坏了）。
