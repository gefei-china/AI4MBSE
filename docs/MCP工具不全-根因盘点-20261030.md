# 「MCP 工具不全 / 老是走不通」根因盘点（2026-10-30 19:00）

## 0. 先说结论

不是网络、不是模型，也**不是 MCP 服务挂了**（`zhiyuan-dev-mcp` 状态 online、71 个工具、schema 全在）。
是**三处数据被"看起来完全正常的保存动作"悄悄改坏了**，而且都没有任何报错：

| # | 被改坏的东西 | 怎么坏的 | 后果 |
|---|---|---|---|
| 1 | `agents.intent_keywords`（7 个 Agent） | 工作室保存 Agent 时，表单没带这个字段，后端缺省写成 `[]` | 关键词路由对该 Agent 失效 |
| 2 | `design` 这个**标识名** | 在工作室把标识名改成「工程建模方案设计Agent」 | 意图 `design` 从此没有 Agent |
| 3 | `agent.team_member_inherit_mcp` = false | 配置被关掉（默认 true） | 团队定向到 chat 时，主 Agent 的 MCP 能力不继承 |

叠加效果就是你看到的那句话：**"我明明给子 agent 绑了 zhiyuan_dev_mcp，它却说工具不全"**。

## 1. 证据链（都能复核）

### 1.1 关键词被清空：`asset_change_logs` 有字段级 diff

```
field='intent_keywords'  old_value=[...真词表...] → new_value=[]
2026-10-30 02:31:55  agent 735 智源对接agent    31 个词 → []
2026-10-30 02:45:17  agent 6   knowledge_qa      15 个词 → []
2026-10-30 02:47:44  agent 5   report_generation  8 个词 → []

2026-10-29 03:43:01  agent 568 requirement_quality 5 个词 → []
2026-10-29 03:49:08  agent 7   chat               1 个词 → []
```

代码原因（`repositories/agent_repo.py`）：

```python
"intent_keywords": json.dumps(data.get("intent_keywords", []) or [], ...)
#                          ↑ 调用方没传 ⇒ 默认 [] ⇒ 覆盖掉真值
```

**「没传」与「要清空」被折叠成同一件事** —— 和之前修过的 `hil_level`（缺省 None=保留）是同一类缺陷。

### 1.2 `design` 意图被改名抹掉

本工程「意图名 == Agent 标识名」（`agent/intent.py` 的 `_db_intents` 按 `agents.name` 建）。
`asset_change_logs` 记录：`2026-10-30 10:07:03 agent#2 field='name' design → 工程建模方案设计Agent`。

改完后实测：

```
_db_intents = [... 没有 design ...]
detect("生成通信子系统的IBD视图") → "design"      # 路由器判得出
registry.get("design")            → None          # 但找不到执行主体
```

### 1.3 团队 MCP 继承被关

`~/.workbuddy/mbse_config.json`：`"team_member_inherit_mcp": false`（代码默认 `true`）。
该开关是 2026-10-29 专门为这个场景加的：*"用户选主 Agent 就是选了它的平台对接能力，
定向只该改谁思考"*。关掉之后，团队把请求定向给 `chat` ⇒ `chat` 自身没绑 MCP ⇒ 工具全丢。

### 1.4 工具注入侧还有一刀（即使前三项都好了）

`pick_for_injection(meta, user_input, min_keep=8)` 按**用户原话的语义分**取前 8 个。
而技能「智源平台管理」的 `allowed_tools` 明写 19 个（含 `query_data_tree` /
`search_model_elements` / `import_sysml_text`）——**技能命中是显式授权，却被"按原话猜"剪掉**。

实测（修复前，`intent=design`）：只注入 `query_projects / query_branches / query_model_versions`，
浏览包树与按名检索的工具全没了 ⇒ 模型只能说"工具不全"。

## 5. 教训（值得写进纪律）

1. **"缺省值"必须区分「没传」与「传了空」**。本仓已栽两次：
   `hil_level`（L1/L2 被静默降级）、`intent_keywords`（关键词被清空）。
   统一判据：*省略 = 不改；显式空 = 清空*。
2. **标识名承载了语义**。`agents.name` 同时是意图键，改名就不是"改个称呼"，
   而是"删掉一个意图"。要么把展示名与意图键拆开，要么在改名时校验核心意图。
3. **"绑定"不等于"注入"**。绑了 71 个工具，运行时可能只给 8 个；
   「显式授权」必须压过「按原话猜相关性」，否则用户会觉得绑定按钮是摆设。
4. **静默覆盖是最贵的缺陷**：三条都无异常、无日志、无告警，
   只在"下一次路由变差 / 模型说没工具"时显形 —— 只能靠**数据审计 + 源码形态门禁**兜住。
