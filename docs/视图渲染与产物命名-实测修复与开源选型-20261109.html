一、视图「元素」：三个真实缺陷，按影响排序

1.1 中文标识符被编码毁掉（最隐蔽，连带毁掉层级）

最小复现：package '通信子系统时序图' { part def A; } → 导出的节点名是 ͨ����ϵͳʱ��ͼ。码位核对：原名的 GBK 字节 CD A8 恰好是合法的 UTF-8 两字节序列 （U+0368），所以 decode("utf-8","replace") 连替换符都不产生 —— 乱码静默流进视图标签。

环节事实
根因JVM 在 Windows 按系统代码页（GBK/MS936）写 stdout，Python 侧按 UTF-8 解码。两端编码不一致
连带损伤视图投影用「名称 → id」映射接包含边。名字一乱，所有包含边对不上被丢弃 ⇒ 同一份代码 parent 从 47 掉到 0
修法① Java 胶水类把 System.out 钉成 UTF-8；② 调用加 -Dfile.encoding/-Dstdout.encoding=UTF-8；③ Python 侧三级解码（utf-8 严格 → 系统代码页严格 → 兜底），严格解不含替换符才采用
判据verify_view_hierarchy.py [7]：CJK 包名/元素名解析正确 + 无 U+FFFD（3 条断言）

1.2 同一节点在一张图里出现 5 次

conv 9736 的 634 行代码里有 5 份一模一样的 package '通信子系统时序图'（模型整块重复输出）。 解析器如实产出 90 个节点，视图投影拿 45 个，唯一 id 只有 9 个。Cytoscape 的 id 必须唯一， 重复项要么被静默合并、要么把布局撑成 5 层重叠方块。已在 _finalize 入口加 _dedupe_view： 同 id 节点保留首条并补齐后续项携带的字段（parent/attrs），同 (source,target,kind) 边去重。

1.3 「包包含」从未提升为父子层级

全库 332 个视图（BDD 54 + PKG 30 等）、84 个 BDD/PKG 的节点里，parent 字段一个都没有。 渲染层的包框样式（Cytoscape 的 node:parent）因此从未生效，层级视图一律平铺。 根因在投影层：解析器已产出「包 → 成员」的包含边，投影却把它当普通组合连线输出。

改动位置要点
提升层级view_generator._attach_package_hierarchy只有 package 能当父（part 之间的组合是连线语义，画成嵌套会改变模型含义）；包可嵌包；防环
BDD 节点集view_generator._project把 package 纳入（否则层级无处承载）

坐标回写static/js/mods/25-graphview.js父节点坐标不回写（否则与 Cytoscape 自动包围盒打架）
开关core/config.py :: sysml.view_package_nesting默认开；关掉逐字节回到改动前（有断言）

二、布局量化：把「好看」变成三个可复现指标

用真实数据（库里 8 个真实版本的 code_text 重新生成 BDD/PKG，共 20 个视图）跑 ELK， 对同一份数据比较四种建图口径。指标定义：交叉＝线心连线两两穿越的次数；重叠＝两个叶子节点矩形相交； 套错＝按子节点包围盒算出的包框，套住了不属于该包的元素（或包框互插）。
