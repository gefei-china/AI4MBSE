# 词典管理页面：标杆调研与优化方案

> 2026-09-09 · 现状盘点 → 国内外标杆 → 差距分析 → 优化方案（P0/P1/P2）

## 一、现状盘点（代码事实）

**已具备的能力（底子比预期好）：**
- 概念/术语双层模型（`glossary_concepts` 18 概念 / `glossary_terms` 42 术语），符合 ISO 704 概念导向；
- 完整状态机：`candidate → approved → deprecated → retired`，状态流转按钮 + 缺定义拦截审批；
- 术语类型：preferred/synonym/abbr/alias/hidden（禁用词）；同形异义 🔴 检测；
- 弃用影响分析（图库中仍在使用的实体/关系清单）；本体映射（class/prop/inst）；
- 字段：intent（意图路由）、boost、domain、broader/related、context、note、source、version——ISO 1087/25964 元数据框架在；
- 交互：列表+详情抽屉、行内约束编辑（必填/唯一/白名单）、批量加术语、概念合并、别名同步、CSV/SKOS 导入导出、归一确认卡回写词库。

**字段利用率问题**（18 概念的实际填充）：`maps_to_prop/inst`、`replaced_by`、`related` 全空；`context/note/broader` 各只有 2 条——元数据框架在但治理习惯未建立。

**核心缺口**：无审批队列看板（candidate 散在列表）、无变更留痕、弃用不强制 `replaced_by`、无层级/可视化浏览、无批量操作、无 TBX 交换、无使用统计。

## 二、标杆调研

### 国际：PoolParty Semantic Suite（商业知识图谱/词库标杆，Graphwise）

| 能力 | 说明 | 对我们的启示 |
|---|---|---|
| **Taxonomy Advisor** | LLM 驱动的建库建议引擎：推荐新概念、上位词、相关词，带上下文说明 | 我们有归一校验的"未命中"数据，天然是建议来源 |
| **跨层级批量操作**（2025 R2） | SKOS 树多选（不再限同级）→ 拖拽换父 / 合并 / 删除 | 列表多选 + 批量域/状态/合并 |
| **概念建议工作流看板** | 建议的概念集中看板，知识工程师逐个批准，流程化推进 | candidate 队列看板（我们已有状态字段，缺集中入口） |
| **Visual Mapper** | 气泡图展示概念的全部关系（broader/related/custom），点气泡导航 | 复用现有图谱画布画 broader/related |
| **质量管理 + 修复** | 自动一致性检查 + 一键修复报告 | 同形异义/缺定义/未映射已有检测，缺"一键修复"聚合 |
| **历史 + 快照回滚** | 变更可追溯，快照可恢复 | 概念级 changelog（可复用本体 changelog 模式） |
| Excel 导入 / SKOS-XL | 表格批量建库 | 已有 CSV/SKOS，缺 Excel 多 sheet 与 TBX |

### 国内：术语在线（全国科技名词审定委员会，国家级术语平台）

| 能力 | 说明 | 对我们的启示 |
|---|---|---|
| 新词征集 → 审定流程 | 用户提交新词 → 进入名词委审定管线 | 我们归一确认的"新增建议"就是等价物，缺**提交→审定**的显式队列 |
| 术语纠错 | 用户报告错误术语 | 缺纠错/反馈入口 |
| 智能标注 | PDF 文档术语识别标注 | 已有（归一校验/文档抽取）——**这是我们领先项** |
| 术语图谱 | 概念关系可视化 | 缺（broader/related 有字段无可视化） |
| 学科分类筛选 | 按学科维度过滤 | domain 筛选已有，缺层级化浏览 |

### 行业最佳实践（TBX/ISO 30042 术语管理体系）

| 实践 | 要点 | 我们 |
|---|---|---|
| 概念条目 = 一概念一entry | 已符合 ✅ | ✅ |
| 生命周期元数据：status + 作者 + 审者 + 日期 | status/created_by/updated_at 有；**审者/变更理由缺失** | ⚠️ |
| 审批工作流 + 变更日志 | approved 术语变更须记录理由与版本 | ❌ 无留痕 |
| 角色四分 | owner / steward / approver(SME) / maintainer | ⚠️ 仅权限体系，词典未细分 |
| **TBX (ISO 30042) 交换格式** | 与 CAT/LLM/QA 工具互通的硬要求 | ❌ 只有 CSV/SKOS |
| Retirement policy | 18 个月未使用 → 下轮审校自动提示弃用 | ❌ |
| **LLM 约束注入** | 批准词表作为生成约束（我们已经在做：归一校验写回 + 意图路由） | ✅ **领先项** |
| KPI：覆盖率 / 合规率 / 批准时长 | 术语治理健康度量化 | ❌ |
| Strict vs advisory enforcement | 关键术语硬阻断、一般术语建议——**我们归一卡片的"⛔ 未决阻断"正是这个范式** | ✅ 领先项 |

## 三、差距分析（结论：治理闭环缺三块，AI 协同是差异化强项）

```
已有优势（保持并强化）：归一校验闭环、意图/域路由、本体映射、SKOS 交换、ISO 标准字段
三大缺口：
  ① 治理流程弱 —— candidate 无看板、变更无留痕、弃用无强制替代、无批量操作
  ② 浏览维度少 —— 平铺列表，无层级树/关系可视化、无使用统计
  ③ 交换格式窄 —— 无 TBX，跨工具互通受限
```

## 四、优化方案（三阶段）

### P0：治理闭环补齐（建议先做，1 个迭代量级）

| # | 优化项 | 设计要点 | 对标 |
|---|---|---|---|
| 1 | **概念审批看板** | 「待审定」页签：candidate 概念集中队列（缺定义/缺英文/未映射标记为拦截项），支持批量批准/驳回（驳回填理由）；对标 PoolParty 建议看板 + 术语在线新词征集审定 | PoolParty / 术语在线 |
| 2 | **概念变更留痕** | 复用 ontology changelog 模式：`glossary_changelog` 表（action/before/after/operator/理由），详情抽屉加「变更历史」区；approved 概念修改必填变更理由 | TBX 变更控制 |
| 3 | **弃用强制替代** | `deprecated` 流转时 `replaced_by` 必填（选择替代概念，联动弃用影响分析展示迁移清单） | retirement policy |
| 4 | **批量操作** | 列表多选 → 批量改域 / 批量状态流转 / 批量合并（进 merge 向导） | PoolParty bulk ops |

### P1：浏览与交换增强（第二个迭代）

| # | 优化项 | 设计要点 |
|---|---|---|
| 5 | **层级树视图** | broader 关系 → 概念树（复用本体左树组件），列表/树双模式切换 |
| 6 | **概念关系可视化** | 复用图谱画布画选中概念的 broader/related/mapped-to 邻域（对标 Visual Mapper，1-hop + 角标） |
| 7 | **TBX 导出** | ISO 30042 基础版（termEntry/langSet/descrip），补齐跨工具互通 |
| 8 | **检索增强** | 拼音/首字母检索（对标术语在线）；术语命中高亮；「禁用词」命中警告 |
| 9 | **字段利用率治理** | 列表增加"完整度"指示（定义/英文/映射/broader 四项缺项计数），点击筛选缺项概念——治理习惯的抓手 |

### P2：AI 协同差异化（我们的领先项继续放大）

| # | 优化项 | 设计要点 |
|---|---|---|
| 10 | **Taxonomy Advisor 式建议流** | 归一校验"未命中"批次一键转 candidate 概念（预填定义/域/来源版本）；LLM 建议上位词/相关词/英文对照，人工确认后写入 |
| 11 | **使用统计 KPI** | 覆盖率（实体命名命中规范词比例）、合规率、各概念引用次数（entities.properties/文档 chunk 命中统计）；18 个月未使用 → 弃用提醒 |
| 12 | **术语纠错反馈** | 归一确认卡加"词典有误"反馈入口 → 进域评审队列（`domain_review_queue` 已有） |

### 建议节奏
P0 四项全是治理硬缺口且改动集中（列表页+详情抽屉+一个 changelog 表），先做；P1 视使用规模（概念数破百后树/批量价值陡增）；P2 的 10/12 与归一链路天然衔接，可与 P0 同批做第 10 项。
