# 工程维度入库（工程归档 → 三元组 → 个人分支图库）流程设计

> 2026-09-09 · 状态：待拍板（决策点 D1~D5 见文末）· 结论先行

## 0. 背景与结论

新流程下 AI 建模代码不再单次入库（生成 → 版本链 → 归一确认 → 写回建模软件），因此：
- **移除**：版本历史的「💾 入库」按钮、消息卡片「入库」入口、`/api/knowledge/sysml/import` 直连导入、`sysml_imports` 表及其记录展示；
- **新增**：「工程入库」——工程建模完成后，将该工程**全部已确认版本**一次性转化为三元组，存入个人分支图库；
- **入口建议：混合式（D1 推荐 C）**——界面硬编码为主入口（治理动作需人工确认向导），agent skill 为辅助入口（只读查询 + 发起预览，不直接提交写库）。

## 2. 新流程设计（工程入库五步）

```
工程详情/版本历史 → [📦 工程入库] 按钮
   │
   ▼
① 聚合：按 project_id 聚合该工程全部 sysml_versions
   （口径 D3：status∈{current,committed} 且归一确认已完成；向导内可勾选排除）
   ▼
② 预览（向导第一屏，只读）：
   版本数 / 实体数 / 关系数 / 预计三元组数 / 与图库已有的重合预估
   ▼
③ 转换：逐版本 sysml_to_candidates → 候选集（batch_id=N 个，或合并为 1 个工程级批次）
   ▼
④ 治理闸：staging_fuse 融合 + quality_gate
   （自动合并批内重复 / 悬空引用进人工队列 / 质量分驳回可回退）
   ▼
⑤ 提交（二次确认）：
   a. 候选 → entities/relations（branch=personal/<user>，project_id=工程）
   b. 实体/关系 → triples（subject-predicate-object，带 confidence/source=工程批次）
   c. knowledge_commits 写快照（可回滚）
   d. project_ingest_logs 写批次记录（统计信息，见 §4）
```

关键口径：
- **幂等**：同一工程重复入库 → 按图库已有实体名+branch 去重合并（复用 fuse 的消歧），不产生重复节点；批次记录标注 incremental；
- **失败安全**：单版本候选化失败不阻断整批，统计里记 failed_versions；提交前整批校验，失败整体回退（事务内）；
- **权限**：写个人分支无需审批；写共享分支（dev/release）超出本设计（走既有治理）。

## 3. 入口设计（决策点 D1）

| 方案 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| A. 界面硬编码 | 工程详情页/版本历史放「📦 工程入库」按钮 → 向导（预览→确认→回执） | 治理动作可视化、参数可控、与 HIL 理念一致、审计清晰 | 需开发向导 UI |
| B. agent skill | 对话"把星网宽带工程入库"，skill 编排执行 | 自然语言、可组合 | **写库确认敏感操作交给 LLM 自主执行风险高**；统计预览在对话流展示差；目标分支/范围参数对话传递易错 |
| C. 混合（推荐） | 界面为唯一**写入口**；agent skill 提供**只读能力**：查入库历史、统计对比、"哪些工程还没入库"，并可引导跳转向导 | 交互各得其所，风险可控 | skill 与界面各一块小工作量 |

**推荐 C**。理由：入库是低频、重量级、需拍板的治理动作（选范围、看统计、确认写库），符合本项目一贯的 HIL 闸门范式；agent 在这条链路里的正确角色是"管家"（回答：上次入库是什么时候、这次会新增多少、哪些版本还没入库），不是"执行者"。

## 4. 入库记录与统计展示（决策点 D4）

新表 `project_ingest_logs`：

```
id, batch_id, project_id, target_branch, operator,
version_ids TEXT(json), stats_json TEXT(json), status(running/success/failed/partial),
error_msg, created_at, finished_at
```

`stats_json` 每次入库的统计信息（回执卡与历史列表共用）：
```
versions_total / versions_failed        版本数（含失败明细）
entities_new / entities_merged          实体：新增 / 与图库合并
relations_new / relations_dangling      关系：新增 / 悬空进人工队列
triples_generated                       三元组数
auto_merged / review_queue / quality    融合闸：自动合并 / 人工队列 / 质量闸结果
elapsed_ms                              耗时
```

展示位置（两处）：
1. **回执卡**（向导完成页 / 对话流内联）：统计摘要徽标行 +「查看图谱」「查看三元组」跳转；
2. **知识库·图谱区 →「工程入库历史」面板**：批次列表（时间 · 工程 · 操作人 · 目标分支 · 状态徽标 · 统计摘要），点开批次 → 完整统计 + 版本清单 + 图谱 diff（复用 knowledge_commits 快照 diff）。agent skill 也可查询同一张表对话式回答。

## 5. 决策点（拍板后实施）

| # | 决策 | 选项 | 建议 |
|---|---|---|---|
| D1 | 入口方式 | A 界面硬编码 / B agent skill / C 混合 | **C：界面写入口 + skill 只读查询** |
| D2 | 触发时机 | 手动按钮 / 工程状态变更自动 | **手动**（建模完成与否由人判断） |
| D3 | 数据范围 | 工程全部已确认版本（可排除）/ 手工勾选 | **默认全部+向导内可排除** |
| D4 | 目标分支 | 固定 personal/<user> / 向导可选 | **固定个人分支**（首次自动建分支） |
| D5 | 旧入口处置 | 立即移除 / 隐藏保留一个迭代 | **立即移除**（sysml_imports 数据保留不删） |

实施预估：后端 1 个服务方法（聚合+编排现有管线）+ 2 个 API（预览/提交）+ 1 张表；前端 1 个向导（复用归一向导范式）+ 历史面板；agent skill 1 个只读查询技能。
