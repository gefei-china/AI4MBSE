## 1. 先确认这条到底有多深：它不止是"日志不好看"

顺着消费侧查了两处，都比"标注员看着别扭"严重得多。

| 消费点 | 拿到的是什么 | 后果 |
|---|---|---|
| `core/online_eval._query_of` → `qrels.jsonl` / `intent_samples` | 归一化 + **上游拼装**过的串 | **评测集里的"标准问法"是另一句话** |

第一条是硬伤：用户问「宽带载荷」，评测集存「宽带通信载荷」，日后召回率涨跌
与真实提问无关；而**这种失真在数据里看不出来** —— 它长得跟"用户就是这么问的"一样。
（与「0 违规」和「门禁没跑」在日志上不可区分同族：**失真长得像正常数据**。）

## 2. 原话是在两个地方丢的，不是一处

```
user_input「宽带载荷」
  → pipeline(execute.py / stream.py)：
        retrieve_query = user_input + kb_hint + 槽位实体 + 附件前 600 字
  → agent/rag.py：
        query = Glossary 归一化(query)          # 宽带载荷 → 宽带通信载荷
  → query_trace.query = 上面这个串
```

所以在 `retrieve()` 内部**无论怎么改都还原不出原话** —— 信息在入口前就没了。
这也是为什么修法必须带一个形参，而不是"在 retrieve 里再拆一次"。

## 3. 关键决策：不改 `query` 的语义，新增 `query_raw`

| 方案 | 问题 |
|---|---|
| A 把 `query` 改成原话 | 存量 6561 行**不可转换**（原话没存过）⇒ 同一列在新旧行上含义不同，而表里没有任何东西标出分界 |
| B 新增 `query_raw`（采纳） | 新旧行口径各自清楚；`query_raw IS NULL` 精确表示"本列存在之前写入，原话不可恢复" |

配套的三条纪律：

1. **NULL 有确切含义**，且 `query_raw` **刻意不给 DEFAULT**：给 `''` 会让
   "没记录"与"记了个空串"混为一谈。
2. **新行不得写 NULL**：`glossary.trace_query` 把「键缺失 / None / 空白」三种输入
   统一回退成本次检索串 —— 否则"调用方漏传"会伪装成"历史行"，两种不同原因
   挤进一个取值，线上再也分不清"这批样本太老"和"这段代码没接上"。
3. **就地更正 `query` 的列注释**（原写"原始用户输入"，与实现不符），
   把它实际是什么写清楚 —— 注释说谎比没注释更坏。

## 5. 门禁：`verify_trace_raw_query.py`（28 项 + 3 变异）

最值钱的两条判据：

- **P5 判的是顺序，不是存在**：断言 `_query_raw =` 的行号
  **早于** `query = _glossary_res["normalized"]` 且早于 `conn = get_db()`。
  只判"这行代码存在"的话，把它挪到归一化之后就完全拦不住（原话照样被覆盖），
  而门禁全绿。M2 用源码文本变换把捕获点挪到覆盖之后 → P5 必须红，证明它有牙齿。
- **P10 判的是转正源头**，不是展示层。`_query_of` 若仍读 `query`，
  失真会直接写进 `qrels.jsonl`；历史行退回 `query` 时必须标 `src='retrieval'`，
  否则将来无法区分"数据集里本来就是归一化串"和"有人又把链路改回去了"。

变异自证三条都各自翻红：M1 复刻旧写入（不写 `query_raw`）、M2 挪动捕获点、
M3 复刻旧 `_query_of`（只读 `query`）。
