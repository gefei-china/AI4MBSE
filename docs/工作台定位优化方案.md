# 工作台定位优化方案（调研需求 + 行业方案 + 优化设计）

> 编写日期：2026-08-11 ｜ 适用范围：AI 赋能 MBSE 设计工具「工作台」（`/` 首页）
> 关联需求：工作台定位不够完整，需要调研需求与行业方案并输出优化方案

---

## 一、现状与问题诊断

### 1.1 当前工作台构成（`static/index.html` pg-home）

| 模块 | 内容 | 说明 |
| --- | --- | --- |
| KPI 卡片 ×4 | 待确认 AI 生成项 / 进行中对话 / 待处理冲突告警 / 最近预评审评分 | 只读数字，不可点击下钻 |
| 知识库统计 | 已评审元素 / 候选元素 / 总实体数 | 只读 |
| 快捷入口 ×4 | AI 建模 / 知识库 / AI 设计工坊 / 用户与权限 | 纯跳转 |

### 1.2 定位不完整的具体表现

1. **无角色视角定位**：页面描述固定写死「角色：设计师」，未随当前登录用户角色/部门动态渲染，不同角色（设计师 / 知识工程师 / 系统管理员）看到的是同一张页，缺少「我的」概念。
2. **无任务闭环入口**：KPI 数字（待确认 / 冲突）无法点击进入对应处理页（生成与反馈 / 分支管理），"待办"停留在计数而非任务。
3. **无项目/分支上下文**：工作台未展示当前工程、当前分支，用户进入后不知道自己在哪个项目、哪个分支干活（全局分支选择器在顶栏，但工作台缺少可视化提示）。
4. **无资产入口**：AI 建模产出的**报告**（变更影响分析 / 预评审）无处进入，工作台也未聚合展示最近报告。
5. **无协同动作区**：合并请求待评审数、知识评审待办、最近活跃成员等协同信息缺失。
6. **无个性化**：快捷入口固定四个，不能按角色/最近使用动态推荐。

## 二、用户需求调研（角色×场景）

| 角色 | 核心诉求 | 对应工作台能力 |
| --- | --- | --- |
| 设计师 | 快速进入建模、看到待我确认的 AI 产物、冲突告警 | 待办中心 + 快捷入口 |
| 知识工程师 | 知识评审队列、候选实体审核量、本体维护入口 | 知识治理待办 + 统计 |
| 评审专家 | 待评审的合并请求、预评审报告、变更影响报告 | 协同评审区 + 报告中心 |
| 系统管理员 | 系统运行状态、用户/角色管理入口、审计入口 | 系统管理入口 + 运行摘要 |

通用高频场景：
- 「我上次干到哪了」→ 最近对话 / 最近报告 / 最近操作轨迹。
- 「现在有哪些事要我处理」→ 我的待办（确认 / 评审 / 冲突）。
- 「当前项目/分支是什么、模型资产多少」→ 项目与分支上下文。
- 「我要去某功能」→ 智能快捷入口（按角色预置 + 最近使用）。

## 三、行业方案调研（2026 年）

### 3.1 B 端工作台通用设计法则

- **模块化 + 分层**：功能按「待办 / 数据概览 / 快捷入口 / 通知」分区，重要信息置顶，次要收进二级菜单；适当留白（来源：B 端工作台页面设计黄金法则）。
- **数据可视化**：用数字卡片/趋势/占比呈现状态，一屏掌握全局，减少跳转。
- **导航与上下文**：面包屑 + 侧边栏主导航，顶部聚合搜索、通知、个人中心。

### 3.2 主流 MBSE / 工程研发平台实践

| 平台 | 工作台定位 | 可借鉴点 |
| --- | --- | --- |
| 华为元图工坊 / 硬件开发工具链 | 「一站式作业入口」：数据统一管理 + 低码应用编排 + 流程自动化 + 业务智能联动 | ①统一数据/资产入口；②流程自动化联动（任务 → 工具 → 数据闭环）；③AI+流程自动化做智能联动 |
| Sparx EA（MBSE 指南） | 提供 Perspective/Workspace 按角色切换工作区；项目看板（Kanban）+ 日历 + 评审中心；模型评审（Model Review） | ①按角色/视角定制工作台；②评审待办成为一等公民；③模型库/资产复用入口 |
| Cameo / Rhapsody | 工程工作台围绕「模型浏览器 + 视图 + 仿真」展开，首页展示项目状态与最近活动 | 项目上下文 + 最近活动列表 |
| Visual Paradigm SysML v2 Studio | 强调「验证前置」：早验证、频繁验证；AI 作为协作者 | 工作台应露出质量/校验状态（预评审评分、语法校验通过率） |
| 华为云硬件开发工具链方案价值 | 基于模型+数据驱动的公共底座，24 类数据模型模板库，连接人员/业务/数据/知识 | 知识资产（模型模板/术语/知识库）应在工作台可见可进入 |

### 3.3 行业共识

1. 工作台是**作业入口**而非统计页：以「待办 + 上下文 + 入口」为核心，统计为辅。
2. **角色化**：不同角色看到不同的工作台布局与入口（Perspective 模式）。
3. **任务闭环**：数字可点 → 进入处理页；处理后回刷计数。
4. **资产可见**：模型、报告、知识等资产在工作台聚合露出。
5. **AI 增强**：AI 生成的产物/报告/告警在工作台按优先级聚合，支持一键进入。

## 四、优化方案（目标架构）

### 4.1 总体定位

> **工作台 = 角色化作业入口**：我的待办（任务闭环）→ 我的上下文（项目/分支/资产）→ 快捷入口（角色预置+最近使用）→ 数据概览（一屏掌握）。

### 4.2 页面结构（自上而下）

```
┌─────────────────────────────────────────────────────────┐
│ 问候区：你好，{姓名}（{角色} · {部门}） ｜ 当前工程 {项目} · 分支 {branch}  │
├───────────────┬─────────────────────────────────────────┤
│ 我的待办       │ 数据概览（KPI 卡片，可点击下钻）          │
│ · 待确认 AI 生成│ · 待确认 / 对话中 / 冲突 / 预评审评分     │
│ · 待评审合并请求│                                           │
│ · 冲突告警     │                                           │
├───────────────┴─────────────────────────────────────────┤
│ 近期报告（报告中心前 5 条）→ 查看全部进报告中心             │
├─────────────────────────────────────────────────────────┤
│ 快捷入口（角色预置 + 最近使用）                             │
│ 知识库统计 / 最近对话 / 最近分支活动                        │
└─────────────────────────────────────────────────────────┘
```

### 4.3 分阶段落地清单

| 阶段 | 优化项 | 说明 | 涉及改动 | 状态 |
| --- | --- | --- | --- | --- |
| P0 | ① 角色化问候 + 上下文展示 | 按当前用户动态渲染姓名/角色/部门/当前分支 | `loadHome` 前端 + `current_user` | ✅ 已落地 |
| P0 | ② 近期报告模块 | 聚合报告中心前 5 条，点击进报告中心 | 前端调 `/api/reports` | ✅ 已落地 |
| P0 | ③ 快捷入口补充 | 新增「报告中心」「模型参数设置」入口 | 前端 | ✅ 已落地 |
| P1 | ④ 待办可点击下钻 | KPI/待办点击进入生成与反馈/分支管理并自动定位 | 前端 | ✅ 已落地 |
| P1 | ⑤ 合并请求待评审计数 | dashboard 聚合 merge_requests pending 数 | dashboard_repo | ✅ 已落地 |
| P1 | ⑥ 知识评审待办 | domain_review_queue / v2g_candidates pending 计数 | dashboard_repo | ✅ 已落地 |
| P1 | ⑨ 最近对话模块 | dashboard 返回最近 5 条对话，点击一键进入 AI 建模 | dashboard_repo + 前端 | ✅ 已落地 |
| P1 | ⑩ 资产概览 | 实体/关系/文档/模型统计卡片 | dashboard_repo + 前端 | ✅ 已落地 |
| P2 | ⑦ 角色化工作台布局 | 按角色渲染不同模块（Perspective） | 前端 + 权限域 | ✅ 已落地 |
| P2 | ⑧ 最近使用/最近活动 | 最近对话、最近操作轨迹 | 前端 localStorage + 后端 | ✅ 已落地 |

### 4.4 指标（验收标准）

1. 工作台问候区显示当前用户角色与部门（非写死）。
2. 工作台显示最近报告且可跳转报告中心。
3. 快捷入口覆盖全部主导航模块。
4. （P1）所有 KPI 数字可点击进入对应处理页。
5. 不同角色登录后工作台模块有差异（P2）。

## 五、已落地内容（随本次需求一并交付）

- 报告中心模块上线（导航「报告中心」+ 台账/详情/导出/删除/定稿）→ 工作台「近期报告」可直接引用。
- 模型参数设置独立为主导航页 → 工作台快捷入口可直达。
- 部门设置模块上线 → 工作台问候区可展示部门（来自用户档案）。
- 知识库控制台 / AI 设计工坊二级页提升为一级导航入口（知识浏览/文档管道/标注审核/本体管理/图谱可视化 + 提示词实验室/Skill 模板库/工具与 MCP/Agent 管理/流程编排），页内原 subtab 已移除。
- 工作台 V2（P1 落地）：「我的待办」（待确认生成/合并评审/冲突/知识评审，可点击直达处理页）+「最近对话」（一键进入 AI 建模并选中）+「资产概览」（实体/关系/文档/模型）+ 工程与分支上下文 + KPI 可点击下钻。`/api/dashboard` 一次聚合 KPI/todo/assets/recent_conversations。
- 工作台 V2（P2 落地）：⑦ 角色化工作台布局 —— 按权限域强特征判定角色视角（系统管理员>知识工程师>设计师>通用），「🎯 角色专属入口」按角色推荐入口（设计师：建模/变更影响/报告/分支；知识工程师：文档管道/标注审核/本体管理/图谱可视化；系统管理员：用户权限/审计/集成/运维）。⑧ 最近使用/最近活动 —— 「🕘 最近操作轨迹」取当前用户 audit_logs 最近 5 条；「🕘 最近访问」基于 localStorage（`mbse_recent_pages`）记录最近 5 个页面，`go()` 自动记录、工作台标签点击可回跳。后端 `/api/users/me` 返回 permissions 供角色判定，`/api/dashboard` 聚合 recent_activities。
- 工作台 V3（2026-08-13 布局收敛）：① 移除工作台「当前工程/当前分支」上下文行（顶栏全局项目/分支选择器已承担上下文职责，工作台不再重复展示）。② 「角色专属入口」与「快捷入口」内容重叠（新建建模对话/报告中心/分支管理/知识浏览在两侧重复，且快捷入口固定 6 按钮与主导航完全重复）→ 合并为单一「🚀 快捷入口」面板（**角色预置 + 最近使用**，回归方案 4.1「智能快捷入口（按角色预置 + 最近使用）」定位）：顶部「最近访问」标签 + 下方按视角推荐的角色入口按钮，删除固定按钮。「最近操作轨迹」上移并入第 4 行第 3 列，页面由 5 行收敛为 4 行（问候 / KPI / 待办·对话·资产 / 快捷入口·近期报告·操作轨迹）。

> P0/P1/P2 全部按本方案落地完成。
