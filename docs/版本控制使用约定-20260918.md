## 3. 日常操作（本仓库是单人本地仓库，无远程）

```powershell
$b = "C:\Users\gefei\WorkBuddy\2026-08-04-19-05-52\mbse_system"

# 看状态 / 差异
git -C $b status --short
git -C $b diff --strip-metrics -- <file>          # 单文件差异

# 提交（小而频，一次一件事）
git -C $b add -A
git -C $b commit -m "fix(前端): 修 xx 逻辑"

# 回滚单个文件到最近提交（最常用）
git -C $b checkout -- static/js/mods/21-ontology.js

# 回滚到基线标签（查看）
git -C $b diff baseline-20260918 --stat
git -C $b show baseline-20260918:static/js/mods/01-core.js > 旧版副本.js

# 在基线上开分支做高风险改动（推荐给 S6）
git -C $b switch -c refactor/s6-inline-extract
# 出问题就回到主分支
git -C $b switch master
```

## 4. 高风险改动的安全流程（S6 起强制）

1. **先提交**当前干净状态（工作区必须 0 变更），再动刀。
2. **开分支**：`git switch -c refactor/s6-xxx`。
3. 每完成一小步就 `git add -A && git commit`，提交信息写清"改了什么、验证了什么"。
4. 验证（本项目固定两件套）：
   - 前端：浏览器冒烟 —— `node tmp/smoke_s5.js <tag>`（22 条路由 + 导航 + 双 Tab + 能力中心 + 本体装载）
   - 后端：`.venv\Scripts\python.exe -m pytest` + 相关 `tools/verify/*.py`
5. 全绿再 `git switch master && git merge --no-ff refactor/s6-xxx`；有问题直接 `git switch master` 丢弃分支。

### 回滚验尸（已实测通过）
```
原始 5554 字节 sha256=DE4B3C32… → 追加一行（5602 字节，git status 显示 M）
→ git checkout -- 该文件 → 5554 字节 sha256=DE4B3C32… 完全一致，工作区回到 0 变更
```
