# 本体建模页面布局与交互优化方案

> 模块：本体管理（KB-C「🧬 本体管理」→ 本体类型约束图谱面板 `#ont-pane-graph`）
> 依据：以 `static/index.html` 与 `routers/knowledge.py` 现有实现为基线的可行改造；本文档对用户反馈的 6 项问题逐一核实，并给分级优化方案与验收口径。

---

## 0. 现状信息架构

本体管理 KBC-C 的本体建模工作区是三栏布局（`index.html` L1088-1127）：

```
┌──────────┬──────────────────────────┬──────────────┐
│ 左栏 300px│ 中栏 约束图谱(自适应)      │ 右栏 340px    │
│ #ont-    │ #ont-graph（分层/分组/力   │ #ont-detail  │
│ types-list│ 导向/环形 + 缩放平移）      │ 类型/关系详情 │
└──────────┴──────────────────────────┴──────────────┘
```

- 左栏头部：`实体 / 关系` 类别切换 + `＋ Add`（L1091-1096）；列表由 `renderOntLeft()`（L8166）渲染。
- 中栏：约束图谱 + 布局切换/缩放（L1099-1117）。
- 右栏：详情 `renderOntDetail()`（L8265），含属性表/关系约束/变更历史与底部操作条。
- 数据源：`ontData`（类型+binding），实例统计来自 `/api/knowledge/ontology/binding`。

## 1. 六项问题逐条核实

### 问题 1｜左侧列表不支持收起与展开 ⭐ 属实
- **证据**：左栏固定 `width:300px`（L1090），无任何折叠/展开控件；`renderOntLeft()` 只做列表渲染，不管理左栏可见性。
- **影响**：小屏或专注图谱时，左栏挤占空间；图谱视窗被压缩，无法在"只看图谱"与"列表+图谱"间切换。

### 问题 2｜没有筛选与搜索，难以快速定位 ⭐ 属实
- **证据**：左栏头部只有 `实体/关系` 类别切换 + `＋ Add`（L1091-1095），`renderOntLeft()` 全量渲染（实体按 `ontTypeTree` 树、关系按 `ontRelationRows` 全展开），无搜索框、无按"属性数/实例数/是否实例化"过滤。
- **影响**：类型几十上百时，需肉眼滚动定位；"未实例化类型""含某属性类型"无法速查。本体 Schema 随建模演进会持续增长，这是最影响效率的一项。

### 问题 3｜关系列表看不全数据，也没有 hover 效果 ⭐ 属实
- **证据**：关系行（L8185-8189）把 `源 → 关系 → 目标` 三段的 `<span>` 均设 `max-width:70px` + `text-overflow:ellipsis` 截断，且**未挂 `title`/tooltip**；行只有 `cursor:pointer`，无 `:hover` 高亮。长名称（如 `星载Ka频段宽带透明转发器`）只能看到开头几个字。
- **影响**：三元组内容被截断（无 tooltip 补全），无法悬停预览；选中体验靠颜色高亮，没有 hover 反馈，弱于通用产品（多数数据面板 hover 显示 outline/浅底色 + title）。

### 问题 4｜不支持批量操作（如批量删除）⭐ 属实
- **证据**：左栏每行只有单条 `✏️`/`🗑`（L8191-8192、L8219-8220），都带 `event.stopPropagation()`；`deleteOntType(id)`（L8363）仅单条删除并二次确认。无复选框、无表头全选、无批量删除/批量设状态入口。右栏底部也是单条 `🗑 删除`（L8356）。
- **影响**：清理废弃类型或整组归并时只能逐条点删，低效且易漏。

### 问题 5｜右侧详情"编辑 / 编辑属性"两个入口内容重复 ⭐ 属实（且函数体完全相同）
- **证据**：
  - `ontEditTypeById`（L8412）→ `ontologyEditType(t.id, t.name, t.type_kind, JSON.stringify(t.constraints||{}))`
  - `ontologyEditProps`（L8426）→ 调**同一行** `ontologyEditType(t.id, t.name, t.type_kind, JSON.stringify(t.constraints||{}))`
  - 两者函数体完全一致（后者注释虽写"S3：并入编辑表单"），即右栏 `✏️ 编辑` 与 `📌 编辑属性`（L8354-8355）打开的是**同一个滑窗**。
- **影响**：入口重复误导，"编辑属性"并未只编辑属性，用户在"想看属性"时却进入全量编辑表单。

### 问题 6｜实体中的"实例数量"是面向哪些数据、哪个分支 ⭐ 属实（数据口径需澄清）
- **证据**：实例数来自 `ontData.binding`，前端左栏用 `b.total`（L8206）、右栏展示 `total / (已评 reviewed / 待审 candidate)`（L8328）。此后端统计在 `routers/knowledge.py` `ontology_binding`（L1213-1233）：
  ```
  SELECT e.entity_type, COUNT(*) AS total,
         SUM(CASE e.status='reviewed'...) AS reviewed,
         SUM(CASE e.status='candidate'...) AS candidate,
         COUNT(DISTINCT e.source_doc) AS source_docs,
         COUNT(DISTINCT e.branch) AS branches
  FROM entities e WHERE e.status!='deprecated' GROUP BY e.entity_type
  ```
- **结论**：实例数是 **`entities` 表中实体类型=该类型、且 status≠deprecated 的「全分支合计」**（未按工作分支过滤；`branches` 字段只是统计命中了多少个不同分支）。即：
  - 不是"当前工作分支"的实例数，而是 **personal + dev + release 等所有非废弃分支的总和**；
  - `total` 含 reviewed、candidate，以及除 deprecated 外的其它中间态；
  - 这里**与页面右上角 `global-branch` 工作分支切换语义不一致**——本体类型为全局共享，但"实例数"却是跨分支总和，用户在某一分支下看到的是一个"全局口径"数字，容易误读。
- **需要产品决策**：实例数应表达"该类型在权威基线(release/dev)里有多少实例"还是"全分支工作总量"。当前实现是后者且未标注，属于语义含糊。

## 2. 优化方案（分 P0/P1/P2 三级，改造前可测）

### P0 · 近期（纯前端为主，风险低，直接改善核心效率）

**P0-1 左栏：支持收起/展开 + 最小可用的定位搜索**
- 左栏头部分栏条右侧加"「 」收起/展开"按钮：
  - 收起时左栏折叠为窄条（保留类别图标+一个展开箭头），中栏图谱占满；再次点击展开回 300px。
  - 用 CSS transition 控制宽度，`renderOntLeft()` 不需改主逻辑，仅切换容器宽度。
- 左栏头部 `<div>` 与"＋ Add"之间插入搜索框 `<input id="ont-filter">`：
  - 实体类别：按名称子串匹配 `t.name`（并顺带匹配属性名，命中属性也展示），配合 `ontTypeTree` 树保留父子。
  - 关系类别：按 `源/关系/目标` 任一端子串匹配 `ontRelationRows()`。
  - 输入即过滤（防抖 200ms），空则回退全量；命中高亮关键词。
- **验收**：左栏可一键收起/展开；输入"卫星"能筛出名称/关系含"卫星"的类型；清空恢复全量。

**P0-2 左栏：关系行"完整数据 + hover"**
- 关系行三段不再用 `max-width:70px` 硬截断，改为 `flex` 收缩 + 行内 `title="${源} —[关系]→ ${目标}"`（悬停显完整字符串）；另加 hover 样式（淡底色 + 左栏蓝边框），选中保持不变。
- 可为三段各自加 `title`（长名称悬停分别看全名）。
- **验收**：悬停任一行可见完整三元组；鼠标悬停有浅色高亮反馈；选中态仍为蓝。

**P0-3 右栏：合并重复编辑入口**
- 删除 `📌 编辑属性` 按钮，保留单一 `✏️ 编辑`；把滑窗标题在编辑时区分"编辑类型/编辑属性"两种模式，但当前函数本就全量编辑，故仅保一个入口最清晰。
- 若仍想保留"只看属性"快捷入口，则新增只读属性抽屉（非编辑），与"编辑"职责彻底分开。
- **验收**：右栏只剩一个编辑按钮；无重复入口；原 `ontologyEditProps` 不再被引用（或删除）。

### P1 · 中期

**P1-1 批量操作（批量删除/批量设状态）**
- 左栏列表每行加复选框；类别头显示"全选 n / 已选 k" + `批量删除`、`批量设为待审/已废弃` 等操作条。
- 后端新增批量接口（一次 `DELETE`/原子更新 + 事务），支持二段确认（先提示影响实例数），失败回滚。
- 与 `deleteOntType` 一致记录 `type_change_log`，批量删除逐条落审计。
- **验收**：可勾选多行批量删除/改状态；删除前提示受影响实例数；事务失败不回写。

**P1-2 左栏数据维度过滤**
- 在搜索框旁加维度下拉：`全部 / 已实例化 / 未实例化 / 含 ≥n 属性 / 子类`，与搜索叠加。
- **验收**：可按"未实例化"快速定位空壳类型，健全 Schema。

**P1-3 实例数量口径：按分支 + 状态上限位（解决问题 6）**
- 后端 `ontology_binding` 增加可选 `branch` 参数：缺省按当前工作分支、`global` 显式表示全分支合计。
- 前端把实例数标签改为 `b.total` 后标注来源，如 `全分支 · 已评 x / 待审 y`（当绑定取自全分支时），避免与右上角分支切换混淆；右栏同样展示分支来源徽章。
- **验收**：切换工作分支时实例数随之变化（或一致时明确标注"全分支合计"）；页面无歧义。

### P2 · 远期 / 增强

**P2-1 左栏虚拟滚动 + 类型统计角标**
- 类型/关系行数大时引入虚拟滚动；行尾加小徽章（属性数/实例数/未实例化红点），一眼概览。

**P2-2 hover 语义预览（右栏联动）**
- 左栏/图谱 hover 某类型时，右栏顶部显示精简预览卡（父子/属性数/实例数/涉及关系），无需点选即可浏览，点选再聚焦完整详情。

**P2-3 与图谱端到联动**
- 左栏搜索命中的类型在约束图谱上同步高亮/居中，实现"列表定位 → 图谱锚定"双通道联动。

## 3. 落地优先级建议

| 优先级 | 项目 | 对应问题 | 改动面 | 风险 |
| --- | --- | --- | --- | --- |
| P0-1 | 左栏收起/展开 + 搜索 | 1、2 | 前端 `index.html`（左栏容器+头部+过滤逻辑） | 低 |
| P0-2 | 关系行完整数据 + hover | 3 | 前端 `index.html`（`renderOntLeft` 关系行模板） | 低 |
| P0-3 | 右栏合并编辑入口 | 5 | 前端 `index.html`（剔除一按钮） | 低 |
| P1-1 | 批量删除/状态 | 4 | 前端 + 后端批量接口 | 中 |
| P1-2 | 数据维度过滤 | 2（深化） | 前端 | 低 |
| P1-3 | 实例数分支口径 | 6 | 前端 + `routers/knowledge.py` `ontology_binding` | 中 |
| P2 | 虚拟滚动/联动/预览 | — | 前端 | 低 |

**建议先做 P0-1/P0-2/P0-3（三项均为纯前端、低风险、直接回应反馈点），再推进 P1-1 批量操作与 P1-3 口径澄清。**

> 说明：P1-3（实例数口径）虽是问题的"澄清"而非纯布局类，但它直接决定后续交互是否给用户错误预期，建议在批量操作上游补上；业务口径需产品确认（权威基线 vs 全分支总量）。

---

## 4. 验收要点（全量跑通后）

1. 左栏可收起/展开，展开后搜索可对实体/关系定位，清空恢复全量。
2. 关系行 hover 显完整三元组并有高亮；选中态清晰。
3. 右栏仅一个编辑入口；重复按钮移除。
4. 批量删除/改状态可用、事务安全、审计留痕。
5. 实例数在后端/前端均带分支来源标注，切换工作分支行为符合口径定义。
6. 本体约束图谱三栏在当前分支下布局无回归（中栏图谱缩放/布局/拖线、右键详情不受影响）。
