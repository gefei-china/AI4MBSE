## 二、为什么这样排（三个反直觉的点）

### ① 第1 名是"清垃圾"，不是"修架构"

`tmp` 7.7 GB + `backups` 1.8 GB = **9.5 GB**，而 `data`（真实业务库）只有 **63 MB**。
也就是说**开发产物的体积是真实数据的 150 倍**。其中 `tmp` 里 34 个 `.db/.bak`
占了 6.8 GB —— 它们是历次验证脚本留下的库快照（`p01_m2.db`、`p02_verify.db`、
`mt_ctx/*.bak`…），**没有任何运行时价值**。

成本 10 分钟（一条 `find -delete`），收益是整个工作目录瘦身 **~75%**。
按"每小时投入换来的价值"算，这是全场最高性价比，没有任何代码改动能比得上。

⚠️ 执行前必须确认 `tmp/` 与 `backups/` 已在 `.gitignore`（已验证：是），
且 `backups/` 里**最新的那份要留**（`mbse.db.bak-p1-3` 是今天 P1-3 迁移的热备）。

### ② 第 2 名是"把已有资产用起来"，不是"开发新功能"

`audit_dup_defs.py` 已经写好了（针对 P1-6「1118 个全局函数、无命名空间约定」，
**这是本项目最大的前端技术债**），但它**没进 CI** ⇒
这个门禁一次都没在合并请求上跑过 ⇒ 它的存在等于不存在。

⚠️ 路径是 `tools/verify/audit_dup_defs.py`（我第一次写成了 `tools/audit_dup_defs.py`，
核实后发现不存在 —— **文档里写"已有某脚本"之前必须 `ls` 一次**，不然会把没做的事说成做完了）。
本地实测：**269 个文件、0 条重复、exit 0** ⇒ 可以直接接进 CI，不需要先修存量。

**成本 = 1 行 YAML，收益 = 把一份已完成的防御接进流水线。** 这种"临门一脚"的项
永远排在最前面。

### ③ 第 3 名是运维动作，不是代码任务

P0-2 的代码侧已闭合（配额耗尽 ⇒ 失败而非静默降级）。但**当前状态是"新文档一律入库失败"**
——因为 block 策略在额度耗尽时是正确地挡住了。

⇒ **充值是当前唯一能恢复业务的动作**，且**不需要任何代码**。
这也是为什么它排在第3 而不排在第 8：它不是"优化"，是"解锁"。

## 三、每一项的具体做法

### 1️⃣ 清理磁盘（P2-3）

```bash
# ① tmp 下的验证库快照（34 个，6.8 GB）—— 全部是历史脚本产物
find tmp -name "*.db" -o -name "*.bak" | xargs -I{} sh -c 'echo "{}"' | head -5   # 先看清单
# 确认后执行（tmp/ 已 gitignore，删了不影响 git）
find tmp \( -name "*.db" -o -name "*.bak" \) -delete

# ② backups 只保留最近的 3 份，其余归档或删除
ls -lt backups/*.db* | tail -n +4
```
**建议顺带做**（防复发）：加一条 `.gitignore` 规则 + 一个 `tools/clean_tmp.py`，
按"mtime > 7 天且后缀 .db/.bak"自动清理；否则半年后还会堆回 7 GB。

### 2️⃣ 重复定义自检进 CI（P1-6）

在 `.github/workflows/ci.yml` 的静态哨兵段加：

```yaml
      - name: Guard 一线代码重复定义（P1-6）
        run: python tools/verify/audit_dup_defs.py
```
本地已验证可直接用：**269 文件 / 0 条重复 / exit 0**。

### 3️⃣ embedding 额度（P0-2 剩余）

- 阿里云百炼控制台为该模型**充值**，或**关闭「仅用免费额度」**开关；
- 充值后需**解除熔断**（类级`Embedder._QUOTA_BLOCK_UNTIL`，10 分钟 TTL）：
  重启进程，或调`Embedder.reset_quota_block()`；
- 随后跑一次重算，把已污染的 810 chunk 换回真向量：
  ```bash
  .venv/Scripts/python.exe tools/audit_embed_degradation.py --reembed
  ```

### 4️⃣ 前端展示 timing / OCR 明细

后端已就绪，前端缺展示：
- `pipeline_detail.timing`（parse/chunk/embed/insert 各自 ms + total）；
- `parse_meta.ocr.pages_total / pages_ocr / pages_pending / truncated`。

建议加在文档详情面板（`viewDocTrace`，`20-docs.js:856`附近已有状态行）。

### 5️⃣ P1-8 评测门禁

把 `tests/manual_verify/eval_intent_routing.py`（46 例）固化：
先连续跑 3 次取**基线**，再用"两次结果差 0"的断言接进 CI（防随机红绿，
与 MEMORY 里评测门禁那次的教训一致）。**阈值取基线 − 明显余量**，不追最优。

### 6️⃣ HyDE 降级（P1-2）

真向量模式下 HyDE 使 embedding 调用**翻倍**。两个选项：
- **保守**：只对前 N 块（如 50）生成 HyDE 问题，其余留空；
- **更优**：改**文档级 HyDE**（整篇生成一组假设问题，全文共用）——
  更贴近 Reverse HyDE 原论文意图（假设问题用于缩小查询空间，不是给每块各造一遍）。
**都必须实测召回损失**再上。
