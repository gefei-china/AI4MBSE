# 审核队列重复数据处理优化设计方案（对齐行业知识融合最佳实践）

> 版本：v1.0（2026-08-16）
> 背景：用户反馈「实体审核队列 / 关系审核队列」出现大量几乎完全一样的数据（多个「载荷」视图、多条「转发器 满足 → REQ-BC-001」），且均提示允许直接通过。经排查为**审核链路缺少重复数据的检测与拦截**。本文参考行业「知识融合在入库前 + HITL 审核 + 置信度分级快审」做法，输出优化设计方案。

---

## 1. 问题定义与现状缺口

### 1.1 现象

| 队列 | 现象 | 用户感知 |
|---|---|---|
| 实体审核队列 | 同名/同类型实体多条并存（多个「载荷」视图） | 队列全是重复项，仍需逐条审 |
| 关系审核队列 | 同一三元组（转发器 满足 → REQ-BC-001）多条并存 | 批量通过后图谱出现重复边 |
| 两者 | confidence≥0.85 普遍亮「高置信建议通过」，无任何重复提示 | 重复数据被误认为是可放心通过 |

### 1.2 根因（代码证据）

1. **入库前无关系消歧**：关系候选确认入库直接 `create_edge` 建边（[vector2graph.py](file:///c:/Users/gefei/WorkBuddy/2026-08-04-19-05-52/mbse_system/vector2graph.py#L421-L430)），`relations` 表无 `UNIQUE(source_id, relation_type, target_id)` 约束（[schema.py](file:///c:/Users/gefei/WorkBuddy/2026-08-04-19-05-52/mbse_system/database/schema.py#L131)），[create_edge](file:///c:/Users/gefei/WorkBuddy/2026-08-04-19-05-52/mbse_system/ontology_semantics.py#L329-L344) 仅校验端点与本体验证，不查重。
2. **审核队列无重复提示/拦截**：实体审核「高置信建议通过」只看 `confidence>=0.85`（[index.html](file:///c:/Users/gefei/WorkBuddy/2026-08-04-19-05-52/mbse_system/static/index.html#L5048-L5050)）；通过/批量通过仅 UPDATE status（[knowledge_repo.py](file:///c:/Users/gefei/WorkBuddy/2026-08-04-19-05-52/mbse_system/repositories/knowledge_repo.py#L103-L127)），列表查询（[list_relations_for_review](file:///c:/Users/gefei/WorkBuddy/2026-08-04-19-05-52/mbse_system/repositories/knowledge_repo.py#L208-L229)）无聚合去重。
3. **实体消歧位置偏后**：现有消歧（[entity_resolver.py](file:///c:/Users/gefei/WorkBuddy/2026-08-04-19-05-52/mbse_system/entity_resolver.py#L88-L165)）只针对**已入库实体**做事后清理，且**不覆盖关系**；实体审核队列（正式审核阶段）对同名实体不提示、不拦截。

## 2. 行业优秀做法对标

### 2.1 知识图谱构建标准流程（学术与工业共识）

```
数据接入 → 信息抽取(NER/RE/属性) → 知识融合(共指消解·实体对齐·属性对齐) → 知识加工(本体对齐·质量评估) → 存储 → 更新
                                    ↑ HITL 人工验证贯穿：机器生成候选 → 人工审核 → 入库
```

关键结论（对齐本文方案）：

1. **知识融合在入库前**：抽取候选 → 与已有图谱对齐（同名/同义/相似）→ 消歧决策 → 才入库。防止「先入库一堆重复、再清理」。本系统 P0-C 已对**实体候选**落地三态消歧（skip/align/create），但**关系候选缺失**（P0-A 缺口）。
2. **HITL 人机分工**：LLM 关系抽取准确率约 75–85%，图谱期望 95%+。机器负责吞吐与预判，人工负责最终裁决——所以「高置信建议通过」应保留，但**必须叠加重复/冲突检查**，不能只信置信度。
3. **置信度分级 + 阈值快审**：高置信（≥0.85）走快审通道批量过；中置信（0.6–0.85）人工抽查核；低置信（<0.6）重点复核。
4. **一致性评估**：行业标注平台（Labelbox）采用「POC 试标 → 一致性评估 → AI 预标 → 交叉复核 → 专家抽检仲裁」，用一致性指标（Cohen's kappa）量化审核质量。
5. **Provenance（溯源）是底线**：每个三元组携带 来源文档 / 模型版本 / 审核人 / 审核时间 / 置信度，合并/驳回全程留痕可追溯撤回。
6. **质量评估**：golden set + 精确率/召回率/F1，量化抽取质量，驱动模型与提示词迭代。

### 2.2 行业前端交互模式（审核工作台）

| 产品/方案 | 模式 | 可借鉴点 |
|---|---|---|
| 质检工作台（行业通用） | 待办优先 + 分区视图 + 批量/单条 | 已落地；本方案补充**重复簇标记** |
| Labelbox 审核闭环 | Review 队列独立角色 + 拒绝样本重新分配循环校正 | 低置信/驳回样本回流重抽（P1） |
| 数据血缘/资产治理台 | 全链路状态可视化，一眼看到卡在哪一环 | 已落地；本方案在审核队列内做**簇级进度** |
| 知识融合工具（实体对齐） | keep/dup 对 + 证据 + 三档阈值 | 已落地（entity_resolver）；本方案**扩展到关系** |

### 2.3 对本系统的适用结论

本系统主链路（抽取→确认→入库→溯源）完整，审核队列缺三件事：
① 关系候选入库前消歧（对齐实体 P0-C）；② 审核队列重复簇聚合提示与一键处理；③ 批量快审置信度门槛与审核质量反馈。

## 3. 目标数据流设计（对齐行业流程）

```
文档/SysML/AI生成 ──▶ 抽取（本体约束）──▶ v2g_candidates（实体+关系）
                                        │
                                        ▼
             ① 入库前消歧（P0-C 已有：实体三态）＋ 【新增】关系三元组去重提示（P0-A）
                                        ▼
             ② 确认入库（本体校验 + chunk 溯源）→ entities/relations(candidate)
                                        ▼
             ③ 审核队列（P0-B 重复簇聚合提示 + P0-C 一键合并 + P1-D 置信度分级快审）
                                        │
              ├─ 通过 → reviewed ──▶ 发布(release) ──▶ AI 消费
              ├─ 合并 → keep 保留 + dup deprecated（留痕可回滚）
              └─ 驳回 → deprecated（留痕）
                                        ▼
             ④ 质量反馈（P1-E golden set P/R/F1 · P2-F 一致性评估）
```

## 4. 优化方案落地清单（分优先级，落到具体文件）

### P0（流程完整性：重复数据在「入库前」与「审核中」两道拦截）

#### P0-A 关系候选确认入库消歧（对齐实体 P0-C 三态）

- **后端**：
  - `vector2graph.py` `confirm_candidates` 关系候选分支：确认前对已有 `relations(status!='deprecated')` 按 `(source_id, relation_type, target_id)` 精确匹配 + 名称 bigram 相似 ≥0.8 疑似匹配（复用 `_match_existing` 思路）；
  - 重复时置 `matching_status`/`match_rel_id`，由确认弹窗选 `dup_action`：`skip`（标记 rejected 留痕）/ `align`（不建新边，chunk 溯源指向已有边）/ `create`（默认强制新建）；
  - `v2g_candidates` 表加列 `rel_matching_status`/`rel_match_rel_id`（`_migrate_columns` 幂等加列）。
- **前端**（index.html 抽取治理中心）：确认弹窗对关系候选同样展示「⚠ 与已有关系重复：转发器 满足 → REQ-BC-001（REL-xx）」+ 三动作单选，批量/单条共用（复用 `v2gDupDialog`）。

#### P0-B 审核队列重复簇聚合提示（用户核心诉求：一眼看到重复）

- **后端**：
  - `knowledge_repo.py` 实体审核列表（`GET /api/knowledge/entities?status=candidate` 对应 repo 查询）增加聚合字段：`dup_count`/`dup_ids`——按 `(name, entity_type)` 分组，同簇成员数 >1 标记；
  - `list_relations_for_review` 增加 `dup_count`/`dup_ids`——按 `(source_id, relation_type, target_id)` 分组（Python 聚合，对齐现有做法）。
- **前端**（index.html）：
  - 实体/关系审核队列「建议」列扩展为：`高置信建议通过` + 重复簇标签 `⚠ 同簇 N 条`（橙色警示）；
  - 点击簇标签 → 详情面板列出同簇全部成员（keep 建议 = 置信度最高/字段最全者，对齐 entity_resolver 选 keep 策略）。

#### P0-C 关系去重合并（对齐 `merge_entities`，审核时一键处理）

- **后端**：
  - `entity_resolver.py` 新增 `merge_relation(conn, keep_id, dup_id, operator)`：dup 边属性/来源文档并入 keep（`properties` JSON 合并 + `source_doc` 追加），dup 边 `status='deprecated'` 留痕，写审计 + CommitRepo 打点（kind=merge）；
  - 新增接口 `POST /api/knowledge/graph/edges/merge`（body: keep_id, dup_id）；
  - 实体同名合并补充：审核队列详情支持「与此实体合并」→ 复用现有 `POST /api/knowledge/entities/{id}/merge`。
- **前端**（index.html）：
  - 关系审核队列操作列增加「🔀 合并」按钮（对重复簇 keep 建议项可见）→ confirmDialog 确认后调用 merge 接口；
  - 实体审核队列操作列增加「🔀 合并」（重复簇内）→ 复用实体 merge 接口。

### P1（体验与质量增强）

#### P1-D 批量快审置信度分级门槛（对齐行业「置信度分级 + 阈值快审」）

- 实体/关系**批量通过**时后端校验：勾选项置信度全部 ≥0.85 → 直接过（快审）；存在 0.6–0.85 → 弹窗提示「含 N 条中置信项，建议人工抽查」（前端确认后仍可过）；存在 <0.6 → 拦截并列出低置信项。
- 落地：`knowledge_service.py` `batch_review_entities` + `routers/knowledge.py` edges review 批量路径加校验；前端 `batchReview`/`batchRelReview` 消费返回的分级统计。

#### P1-E 审核质量反馈（对齐「质量评估」）

- 抽取治理中心批次卡增加 golden set 抽样评估：抽取结果与人工 golden 比对，输出 P/R/F1（复用 `batch_stats` 结构扩展）；审核通过率/驳回原因分布按批次展示（前端聚合，后端已有 audit）。

#### P1-F 驳回样本回流（对齐 Labelbox 拒绝样本循环校正）

- 驳回的关系/实体（deprecated）在抽取治理中心「只看被拒」中支持「重新抽取该 chunk」→ 生成新候选（复用 v2g 抽取管道，带原 reject_reason 上下文）。

### P2（远期）

- **P2-G 审核一致性评估**：同一批次抽样双人交叉复核，输出 Cohen's kappa；低一致性批次提示复审。
- **P2-H 关系质量评估**：golden set + 边级 P/R/F1（与 P1-E 合并为统一质量面板）。

## 6. 验收标准

1. 关系候选确认入库时若与已有关系重复（同三元组），确认弹窗出现重复警示 + 三动作（跳过/对齐/新建），选择 skip/align 后不产生新重复边。
2. 实体审核队列中同名同类型实体展示「⚠ 同簇 N 条」；关系审核队列中同三元组展示「⚠ 同簇 N 条」，点击可查看同簇成员与 keep 建议。
3. 重复簇内可一键合并：keep 保留（属性/来源合并），dup 置 deprecated 留痕，CommitRepo 打点，图谱联动刷新无重复边。
4. 批量通过含中置信/低置信项时，前端出现分级提示（0.6–0.85 建议抽查、<0.6 拦截）；全高置信一键快审。
5. 回归：抽取治理中心、实体审核、关系审核、消歧合并、发布门禁、图谱可视化均无回归（复用 `tests/manual_verify/verify_p0abc.py` 与 `verify_branch_v2.py` 回归）。
