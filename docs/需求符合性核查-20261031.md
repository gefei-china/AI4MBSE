### 0.2 三态 + ⓐ 判定定义

- **✅ 已满足**：代码有真实实现，且数据库中已有对应运行数据（被实际跑过）。
- **⚠️ 部分满足**：核心机制已实现，但覆盖/完整度不足，或仅部分子项达成。
- **❌ 未满足**：代码缺失或未接入，或数据库无任何数据且无可达入口。
- **ⓐ 机制在/数据空**：代码/端点存在，**但数据库对应表为空或近空**，功能在验收演示时无法走通 —— 判定上等同于"验收会被判未达成"，单列以提示风险。

### 0.3 一句话结论

**工程已建成一套功能广度覆盖甲方技术要求 80%+ 的 AI-MBSE 原型，但"能用"与"验收能演示"之间存在系统性鸿沟**：大量能力的"机制已写、数据未走"——典型如 `v2g_candidates` 351 条仅 6 条 confirmed、`entity_aliases`/`entity_dup_candidates`/`ontology_profiles`/`ontology_drafts` 全为 0、`sysml_versions` 108 条 `adopted` 全 0。加上 **3 个示范项目已不在库（BR-10/DC-3 落空）**、**§10 九类甲方格式交付物一份没有**、**信创/麒麟适配与 HA 99.9% 缺位**，是距离验收最远的四块。

## 12. 重点缺口深度说明（Top 10，按验收风险排序）

1. **ⓐ 示范项目缺失（BR-10 / DC-3，❌）**：`projects` 仅"默认项目"，旧 `satnet-broadband/narrowband/navigation` 已移除（`utils.py:57` 自证为"域固化残留"）。甲方硬性要求 3 个典型场景示范，**当前无任何可演示的示范模型数据**。优先级最高。

2. **ⓐ 入库/采纳全空（FR-MG-2/MG-5、BR-5、FR-KG-2/3/4/9/12，ⓐ）**：`sysml_versions.adopted` 108 行全 0；`v2g_candidates` 351→6 confirmed；`entity_aliases`/`entity_dup_candidates`/`ontology_profiles`/`ontology_drafts` 全 0。能力链路"代码通但数据死"——验收演示时无法展示"AI 生成→人确认→入库→知识库演进"的完整闭环。

3. **❌ §10 九类甲方格式交付物为零**：docs/ 全是内部设计文档，无一份需求规格说明书/设计报告/测试大纲细则报告/试运行报告/研制总结报告。这是形式验收的硬伤。

4. **❌ 信创/麒麟适配与 HA 99.9%（OpEnvR-1/3、§7.3）**：Dockerfile 通用 Debian 镜像，无麒麟/统信/飞腾/龙芯适配；无主备/容灾设计。两项均为★不容负偏离。

5. **⚠️ 身份认证与隔离（FR-UR-1/2/3）**：OAuth2 SSO 代码真实但默认 local；LDAP 仅标签无实现；`X-User-Id` 可自报使隔离可绕过。甲方 IAM 集成未落地。

6. **❌ 外部接口对接（ExtInfR-DD-1 / MS-1 / Oth-1）**：甲方技术管理系统 HTTP/REST 取数未做（data_sources 无 api 类型）；MagicDraw 2022x 无专用适配；甲方文档模型双向转换插件未集成。

7. **⚠️ 训练/推理数据私有化（DC-1 / §11.1）**：默认 LLM 指向 DeepSeek 公网，需配置内部地址方合规；缺开源许可证审查记录。

8. **ⓐ 校验/规范化无数据（FR-VC-1、BR-8、FR-MG-6）**：`shacl_findings=0`，规则校验与"多维度打分"停留在提示词层，无可量化产出。

9. **⚠️ 智能路由与生命周期（ArcR-5、FR-KG-8）**：图谱优先→向量降级路由已有记录（1929），但生命周期状态枚举不全、双向一致性仅体检级。

10. **⚠️ 反馈数据集未形成闭环（FR-HIL-2、DC-2）**：`feedback=8` 仅落库，无导出/微调链路，无法支撑"反馈→优化"承诺。
