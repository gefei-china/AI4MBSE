## 归档 = 移动，不是删除

- 全部通过 `git mv` 语义提交，历史里可完整追溯（`git log --follow <file>`）。
- 清单存档：`_archived_20261006.txt`（本目录）。
- 需要查历史方案时：`git show HEAD~1:docs/<文件名>`，或直接看 `archive/2026-Q3/`。

## 后续维护建议

1. **新文档别再堆在 `docs/` 根目录**：过程性记录直接写进 `archive/YYYY-QN/`，
   只有"当前有效的基线/规范"才留根目录。
2. 根目录文档被引用 ≥2 次时，它就是**事实上的基线**——改名或移动前先看引用。
3. 每季度做一次本归档流程（引用分层 + 零引用归档），避免根目录再次膨胀。
