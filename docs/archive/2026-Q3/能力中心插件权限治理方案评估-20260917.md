# 能力中心插件权限治理方案评估

> 评估对象提案：个人侧由个人管理；市场数据由专门管理人员管理；个人不应有启用/停用/卸载的权力，只有安装入口；其他管理入口向管理人员提供。
> 评估基线：`plugin_system/store.py` + `routers/plugins.py`（截至 2026-09-17，P1-6/P1-7/P1-8 已落地）
> 日期：2026-09-17

---

## 一、结论先行

**方案方向正确，但按现在的表述直接落地会误伤两个无辜能力，同时漏掉三个真正的越权漏洞。**

- ✅ 正确的部分：市场数据（status / scope / manifest / grant）确实应收归管理人员，当前代码在这条线上有 3 个"个人可越权动市场"的漏洞，比提案担心的更严重。
- ⚠️ 需要修正的部分：**个人级启停（installed-enabled）和个人级卸载不碰市场数据**，收走它们解决不了提案想解决的问题，反而制造新问题。建议保留，理由见 §3。
- 🔑 关键认知：P1-7 解耦后系统已有三个正交维度，"启用/停用/卸载"在不同维度上语义完全不同，方案必须按维度拆开评估，不能一刀切。

| 维度 | 存储位置 | 语义 | 影响范围 |
|---|---|---|---|
| status（可用性） | `plugins.status` | published/disabled/… | 全局 |
| scope（可见性） | `plugins.scope` | personal/pending_public/public | 全局 |
| 个人使用开关 | `plugin_installs.enabled` | 我个人用不用 | **仅本人** |

提案里"个人不应该有启用、停用、卸载的权力"——如果指的是前两个维度，**现状已经基本如此**（还有漏洞，见 §4）；如果指的是第三个维度，**反对收走**（见 §3）。

---

## 二、方案中"现状已经满足"的部分（无需开发）

1. **公共插件的全局启停**：`set_enabled` 对 `scope='public'` 已要求 admin 或作者（store.py L657）——但"作者"应移除，见 §4-1。
2. **上架审核**：`review_share` 仅 `is_admin` 可操作（store.py L559）。
3. **授权分配（grant）**：router 层 `require_permission("ai_studio", "publish")`（plugins.py L336）。
4. **待审队列 / 审核策略设置**：均挂 publish 权限。
5. **内置能力不可卸载**：`uninstall` 已硬拒绝（store.py L634），并正确引导用"停用"。
6. **审计日志**：create/install/enable/disable/share/review/grant 等动作均已写 `plugin_audit_logs`，管理人员可追溯。

## 三、方案中"建议不要收走"的部分

### 3.1 个人级启停（`PUT /{pid}/installed-enabled`）—— 保留

这条是 2026-09-16/17 一批修复（P1-6）专门建出来的能力，收走它等于回退：

1. **它是纯个人语义**：只写 `plugin_installs.enabled`，不动 `plugins.status/scope`，对市场数据零影响。提案要防的"个人动市场数据"在这里根本不发生。
2. **运行时已依赖它**：`consumable_plugin_ids` 的 `explicit_off` 否决逻辑（本人显式停用 → 优先于一切）已接入 AI 消费判定。收走后判定链路要改。
3. **收走的实际后果**：内置能力（系统级安装）用户只能"装着但不想让 AI 碰"却无处可关——这正是 P1-6 之前"管理死角"问题的复刻。噪音能力、隐私顾虑场景都需要个人停用。
4. **折中可选**：若产品上坚持"个人只有安装"的干净界面，可以 **UI 层收敛、后端保留**——市场卡片只留「安装」，个人停用入口收进"我的能力-已安装"管理区。API 不删，权限模型不破坏。

### 3.2 个人级卸载（`POST /{pid}/uninstall`）—— 保留

- 现实现只删"我名下的安装记录"（store.py L636），并把内置能力硬拒之门外。它已经是"个人副本管理"，不是市场数据管理。
- 收走卸载会产生"误装关不掉"的支持负担，且破坏 `install_count` 的计数闭环（装了不能退）。
- 结论：**卸载就是安装的逆操作，跟着安装权走**。个人有安装入口，就必须有卸载入口。

## 四、方案真正该管、但当前代码有漏洞的部分（落地必补）

这才是"市场数据由管理人员管理"的核心战场，现有代码有 4 处个人可越权动市场：

### 4-1 作者可全局启停已上架插件（最严重）

`set_enabled`（store.py L657-661）：`scope='public'` 时 `adm or is_author` 均可操作。
**后果**：作者把能力上架后，可随时 `status→disabled` 全局下架，波及所有已安装用户，且走同步桥直接切断 AI 运行时调用。
**改法**：public 分支去掉 `is_author`，仅 `is_admin`。作者想下架走"撤回上架"，但撤回也要收权（见 4-2）。

### 4-2 作者可单方面撤回上架

`withdraw_share`（store.py L574-589）：`_is_owner`（作者或管理员）即可 `public → personal`。
**后果**：市场条目消失，所有已安装用户的消费判定随之失效（scope 不再是 public，取决于运行时按 status 还是 scope 判定，至少市场侧立即不可见）。
**改法**：二选一——
- A（贴合本提案）：撤回上架仅管理员可操作；作者发起的撤回转为"下架申请"，管理员裁决。
- B（折中）：作者可撤回，但已安装用户保留可用（需要消费判定改为"安装时快照"），实现成本高，不建议。

### 4-3 作者可编辑/删除已上架能力，绕过审核直改市场

- `update_plugin`（store.py L303）：作者可直改 `published + public` 能力的 manifest——等于向全市场推送新版本，审核流被绕过。
- `soft_delete`（store.py L718）：作者可删除已上架能力 → `status='removed'` → 同步桥切断所有用户的运行时调用。**作者一个人动了一行，全市场的能力消失。**
**改法**：
- `scope='public'` 时，编辑应产生"待审版本"（新版本进 pending，审核通过才切 current_version），或至少降级为：已上架能力作者只能改 `scope='personal'` 之后再改内容。
- `soft_delete` 增加 guard：`scope='public'` 时仅管理员可删；作者删除先自动撤回上架。

### 4-4 管理人员角色口径需要独立

当前 `is_admin = admin 域权限非空 或 ai_studio 含 publish`（store.py L73-86）。这个口径把**能力创作者（publish）**和**市场治理者**焊在一起：设计师角色能审核上架、能 grant、能全局启停——他们正是"创作个人能力的个人"，不符合"市场数据由专门管理人员管理"。
**改法**：新增独立权限点（如 `ai_studio:market_admin`），市场治理动作（审核/全局启停/grant/强制下架/审计查询）统一挂它；`publish` 只保留"创建/发布自用/申请上架"。`is_admin` 拆成 `is_admin`（系统管理）与 `is_market_admin`（市场治理）两个判定，DTO 的 `can_review_share` 等标记随之改挂后者。

## 五、建议的权限矩阵（落地目标态）

| 动作 | 普通用户 | 能力作者 | 市场管理员（market_admin） |
|---|---|---|---|
| 浏览市场（grant 过滤） | ✓ | ✓ | ✓ |
| 安装 | ✓ | ✓ | ✓ |
| 个人启停（installed-enabled，仅影响自己） | ✓ | ✓ | ✓ |
| 卸载自己的安装副本（内置除外） | ✓ | ✓ | ✓ |
| 创建 / 编辑 / 发布自建能力（personal） | — | ✓ | ✓ |
| 申请上架（share） | — | ✓ | ✓ |
| 审核上架 / 驳回 | — | — | ✓ |
| 撤回上架（public → personal） | — | 申请制（见 4-2） | ✓ 直操 |
| 全局启停（status，影响所有人） | — | — | ✓ |
| 编辑已上架能力 | — | 产生待审版本 | ✓ 直改 |
| 删除已上架能力 | — | — | ✓（作者删需先过撤回） |
| grant 授权分配 | — | — | ✓ |
| 审计日志查询 | — | — | ✓ |

## 七、一句话判断

提案的**治理目标**（市场数据归管理员）是对的，而且现状漏洞比提案预想的还多两处（4-1、4-3 必须补）；但**手段**上"收走个人启停/卸载"打错了靶子——那两个操作本来就只动个人副本。正确的切法是：**按 P1-7 的三维模型切权，status/scope 收归市场管理员，plugin_installs 留给个人。**
