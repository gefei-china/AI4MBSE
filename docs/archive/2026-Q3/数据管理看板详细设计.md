# 数据管理看板（Web 端仪表盘）整合设计方案

> 版本：v2.0（整合版） ｜ 日期：2026-08-12 ｜ 状态：待评审
> 适用范围：AI4MBSE · 以客户需求「数据管理看板」为准，整合「知识预览」能力 → 统一的知识工程师工作台
> 变更说明：v1.0 将「看板」与「预览」作为两套体系对立设计；v2.0 依米爸决策，**能力合并、以数据看板需求为准**，预览成为看板内的内置视图。

---

## 1. 设计决策（结论先行）

| # | 决策 | 说明 |
| - | - | - |
| D-1 | **以客户需求「数据管理看板」为准** | 客户红线（浏览/搜索/编辑/变更闭环）是主体，一切能力向看板收敛 |
| D-2 | **知识预览并入看板** | 「命中预览」「产物预览」「AI 建模 RAG 消费」不再作为独立体系，降级为看板内的**内置视图** |
| D-3 | **看板 = 知识库统一工作台** | 知识库控制台 5 Tab（浏览/管道/审核/本体/图谱）+ 命中预览 + 产物预览 + 变更闭环，全部整合为一个页面体系 |
| D-4 | **AI 建模页保留**（设计师工作台） | 面向设计师的 AI 建模对话不迁移；其产物通过看板「产物中心」统一归档与治理 |
| D-5 | **变更闭环复用分支管理** | 以现有 `branches` / `merge_requests` 状态机为评审载体（已实现 fork/冲突/合并语义），不重复造轮子 |

## 2. 整合前后对比

| 维度 | 整合前（v1.0 / 现状） | 整合后（v2.0） |
| - | - | - |
| 产品形态 | 看板（新建）+ 预览（现状）两套入口 | **一个「数据管理看板」**，预览是其中 Tab/面板 |
| 知识工程师入口 | 知识库控制台 5 Tab + 命中预览面板 + 分支管理页 | 看板 6 Tab 全包（含检索/预览/变更/评审） |
| 检索调试 | 命中预览面板（kb-a） | 看板 Tab2「数据浏览」内嵌检索结果面板（混合/向量切换保留） |
| 产物查看 | AI 建模页右侧 preview-panel | 看板 Tab7「产物中心」+ AI 建模页保留快捷预览 |
| 数据治理 | 编辑直接写库（无闭环） | 编辑入篮 → 变更申请 → 评审 → 合并（红线闭环） |
| 导航 | 知识库控制台 / 分支管理 / 审批管理 / 报告中心 散落 | 主导航「数据看板」收纳知识治理全部能力（其余保留入口） |

## 3. 统一信息架构（看板 6 + 1 Tab）

```
主导航：📊 数据看板（新） · 💬 AI 建模（保留） · 其他系统页
┌────────────────────────────────────────────────────────────────┐
│ 数据看板（pg-dashboard）                                        │
│  Tab1 📊 总览仪表盘      KPI + 待办 + 最近变更 + 引擎状态         │
│  Tab2 🔍 数据浏览        [整合命中预览] 实体/关系/文档三视图       │
│                          + 混合检索 + 检索结果面板 + 表格内联编辑  │
│  Tab3 🕸 图谱视图        [整合图谱可视化] SVG 力导向图 + 编辑入篮   │
│  Tab4 📄 文档与分块      [整合文档管道] 上传/追溯/分块浏览          │
│                          + 命中预览（分块检索调试）               │
│  Tab5 🧺 我的变更        草稿篮 + 我提交的变更申请                  │
│  Tab6 ⏳ 待我评审        [整合分支合并] 评审队列 + diff + 冲突解决  │
│  Tab7 🗂 产物中心        [整合产物预览] AI 建模产物归档/预览/导入图谱│
└────────────────────────────────────────────────────────────────┘
```

**关键：预览能力不再是独立页面，而是看板的内置视图/面板。**

| 原能力 | 新位置 |
| - | - |
| 命中预览（kb-a 检索调试） | Tab2 检索结果面板 + Tab4 分块命中预览 |
| 产物预览（AI 建模 preview-panel） | Tab7 产物中心（AI 建模页保留快捷入口） |
| 向量→图谱转化（v2g） | Tab3 图谱视图（抽取候选确认并入编辑入篮） |
| 标注审核 / 实体消歧 | Tab2 数据浏览（审核队列并入变更评审） |
| 本体管理 | Tab3 图谱视图（类型层维护 + 本体校验） |
| 文档管道（上传/追溯） | Tab4 文档与分块 |
| 分支管理 / 合并请求 | Tab6 评审（作为变更闭环载体） |

## 4. 核心闭环（不变，红线）

```
编辑入篮（写个人分支 kb/{user}）→ 变更草稿篮 → 变更申请
  → 评审（diff + 冲突解决 + 本体校验）→ 合并入 dev/main → 可选 release 快照
分支：rejected(驳回可重提) / withdrawn(撤回) / conflicts(冲突待解决)
写保护：dev/main / release 服务端强制只读（扩展 _release_guard）
```

## 5. 数据模型（新增表）

```sql
CREATE TABLE IF NOT EXISTS dashboard_change_requests (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    change_no TEXT NOT NULL UNIQUE,
    title TEXT NOT NULL,
    description TEXT DEFAULT '',
    status TEXT DEFAULT 'draft',
    source_branch TEXT NOT NULL,
    target_branch TEXT DEFAULT 'dev/main',
    project_id TEXT DEFAULT '',
    op_count INTEGER DEFAULT 0,
    merge_request_id INTEGER DEFAULT 0,
    created_by TEXT DEFAULT '',
    reviewer TEXT DEFAULT '',
    reviewed_at TEXT DEFAULT '',
    merged_at TEXT DEFAULT '',
    created_at TEXT DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS dashboard_edit_ops (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    change_id INTEGER NOT NULL REFERENCES dashboard_change_requests(id) ON DELETE CASCADE,
    op_type TEXT NOT NULL,
    target_type TEXT NOT NULL,
    target_id TEXT NOT NULL,
    before_json TEXT DEFAULT '{}',
    after_json TEXT DEFAULT '{}',
    status TEXT DEFAULT 'pending',
    applied_at TEXT DEFAULT ''
);
-- 扩展 graph_edit_logs 加 change_no（追溯）
```

复用：`branches` / `merge_requests` / `entities` / `relations` / `documents` / `document_chunks` / `ontology_types`。

## 6. API 设计（dashboard 域 + 复用）

| 域 | 端点 | 说明 |
| - | - | - |
| 只读 | `GET /api/dashboard/stats` | 总览 KPI |
| | `GET /api/knowledge/entities?branch=` / `GET /api/knowledge/graph` / `POST /api/knowledge/retrieve` | 复用现有 |
| 编辑 | `POST /api/dashboard/edits` | 编辑入篮（写个人分支 + 本体校验 + 审计） |
| | `GET /api/dashboard/draft` / `DELETE /api/dashboard/draft/{op_id}` | 草稿篮管理 |
| 变更 | `POST /api/dashboard/changes` | 提交变更申请（打包 edit_ops → merge_request） |
| | `GET /api/dashboard/changes?mine=1` / `GET /api/dashboard/changes/{id}` | 申请列表/详情（含 diff） |
| | `POST /api/dashboard/changes/{id}/withdraw` | 撤回 |
| 评审 | `GET /api/dashboard/reviews` | 待评审队列 |
| | `POST /api/dashboard/changes/{id}/resolve` | 冲突解决（复用 resolutions） |
| | `POST /api/dashboard/changes/{id}/approve` / `reject` | 通过（合并）/ 驳回 |
| 产物 | `GET /api/artifacts?conversation_id=` / `POST /api/knowledge/sysml/import` | 复用：产物列表 + 一键导入图谱 |

权限：知识工程师（编辑/提交）· 评审人（评审）· 管理员（合并/配置）。

## 9. 风险与对策

| 风险 | 对策 |
| - | - |
| 整合改动面大（5 Tab 迁移） | 组件化提取（PreviewPanel / SearchResultPanel / GraphEditor），旧入口重定向过渡 |
| 个人分支数据膨胀 | 合并后个人分支可删除（现有 delete_branch 语义）；检索默认主版本 |
| 并发编辑覆盖 | 乐观锁（updated_at）+ 冲突检测进评审门禁 |
| 旧图谱 API 直写 dev/main | 服务端主版本 guard 统一拦截（不以 UI 为准） |
