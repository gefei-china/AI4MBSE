# 工程模型分析报告模板

- 文档版本：v1.0
- 适用场景：MBSE 工程模型（SysML v1/v2）的系统性分析评估
- 使用方式：复制本模板，按各维度提示填充分析内容

---

## 分析维度总览

| # | 维度 | 核心问题 | 输出形式 |
|---|---|---|---|
| 1 | 模型结构 | 模型的组织方式和层级关系是否清晰合理 | 包结构树 + 统计表 |
| 2 | 需求追溯 | 需求是否完整覆盖到设计元素，有无断裂 | 追溯矩阵 + 断链清单 |
| 3 | 架构与行为 | 结构定义和行为定义是否一致、完整 | BDD/IBD/STM/ACT 对照表 |
| 4 | 接口与交互 | 端口/接口/连接是否定义完整、方向正确 | 接口表 + 连接拓扑图 |
| 5 | 一致性与完整性 | 有无缺失元素、悬空引用、命名冲突 | 问题清单（按严重度排序） |
| 6 | 复杂度与耦合 | 模型复杂度是否可控、模块间耦合是否合理 | 指标表 + 热力图 |
| 7 | 标准合规性 | 是否符合 SysML/领域标准规范 | 合规检查表 + 偏差项 |
| 8 | 风险与设计余量 | 技术风险点、设计余量是否充足 | 风险登记册 |
| 9 | 变更影响 | 关键变更的影响传播路径 | 影响传播图 + 受影响清单 |
| 10 | 验证与确认 | 模型是否经过充分验证，覆盖率如何 | V&V 矩阵 + 缺口清单 |

### 3 多维分析

#### 3.1 模型结构维度

**分析目标**：评估模型的组织方式、包层级、模块化程度是否合理。

**分析要点**：
- 包结构树是否按功能/子系统/层级清晰划分
- 是否有"巨型包"（单包内元素 >50）
- 嵌套深度是否合理（建议 ≤4 层）
- 是否有跨包的循环依赖

**输出格式**：

```
[顶层包]
├── [子包1]（N 个元素）
│   ├── [子包1.1]（N 个元素）
│   └── [子包1.2]（N 个元素）
└── [子包2]（N 个元素）
```

| 检查项 | 结果 | 备注 |
|---|---|---|
| 包层级清晰度 | [通过/警告/不通过] | |
| 模块化程度 | [通过/警告/不通过] | |
| 嵌套深度 | [最大深度 N] | |
| 循环依赖 | [无/有（列出）] | |
| 巨型包 | [无/有（列出）] | |

---

#### 3.2 需求追溯维度

**分析目标**：验证需求是否完整覆盖到设计元素，追溯链路有无断裂。

**分析要点**：
- 顶层需求是否都有对应的 Block/部件/用例
- satisfy 关系是否完整（无悬空需求、无无源设计）
- derive 关系是否合理（子需求是否被正确派生）
- verify 关系是否覆盖（每个需求是否有验证案例）

**输出格式 — 追溯矩阵**：

| 需求 ID | 需求名称 | satisfy→Block | verify→案例 | 状态 |
|---|---|---|---|---|
| REQ-001 | [需求描述] | [Block 名] | [验证案例] | 完整 |
| REQ-002 | [需求描述] | — | — | **断链** |

**断链清单**：

| 类型 | ID | 名称 | 缺失环节 |
|---|---|---|---|
| 无 satisfy 的需求 | REQ-xxx | | |
| 无 verify 的需求 | REQ-xxx | | |
| 无源的 Block | Block-xxx | | |

---

#### 3.3 架构与行为维度

**分析目标**：评估结构定义（BDD/IBD）与行为定义（STM/ACT/UC）的一致性和完整性。

**分析要点**：
- 每个 Block 是否有对应的行为定义（STM/ACT）
- BDD 中的组合/聚合关系是否在 IBD 中体现为连接
- 状态机是否覆盖所有关键操作场景
- 活动图是否有完整的输入/输出流和控制流
- 用例是否与 Block 关联（参与者 → 用例 → Block）

**输出格式 — 视图对照表**：

| Block | BDD | IBD | STM | ACT | UC | 完整度 |
|---|---|---|---|---|---|---|
| [Block 名] | 有 | 有 | 有 | 有 | — | 100% |
| [Block 名] | 有 | 无 | 无 | 无 | — | 25% |

---

#### 3.4 接口与交互维度

**分析目标**：评估端口、接口、连接的定义完整性和方向正确性。

**分析要点**：
- 端口是否都定义了类型（interface/port spec）
- 连接是否两端都有端口、方向是否正确（provider/consumer）
- 是否有未连接的端口（悬空端口）
- 接口定义是否包含流类型、方向（in/out/inout）
- Item Flow 是否与接口定义一致

**输出格式 — 接口清单**：

| 端口/接口名 | 类型 | 方向 | 流类型 | 连接对端 | 状态 |
|---|---|---|---|---|---|
| [端口名] | proxy port | inout | [Flow 类型] | [对端端口] | 完整 |
| [端口名] | — | — | — | — | **悬空** |

---

#### 3.5 一致性与完整性维度

**分析目标**：发现缺失元素、悬空引用、命名冲突、语法/语义错误。

**分析要点**：
- 是否有未定义类型的元素（类型引用不存在）
- 是否有悬空引用（指向已删除的元素）
- 命名是否一致（同一概念是否用了多个名称）
- 约束表达式是否语法正确
- 多视图间的命名/类型是否一致

**输出格式 — 问题清单（按严重度排序）**：

| # | 严重度 | 类型 | 位置 | 描述 | 建议 |
|---|---|---|---|---|---|
| 1 | 阻断 | 悬空引用 | [包/元素] | [描述] | [修复建议] |
| 2 | 严重 | 命名冲突 | [包/元素] | [描述] | [修复建议] |
| 3 | 警告 | 缺失定义 | [包/元素] | [描述] | [修复建议] |
| 4 | 提示 | 命名规范 | [包/元素] | [描述] | [修复建议] |

---

#### 3.6 复杂度与耦合维度

**分析目标**：量化模型的复杂度和模块间耦合度，评估可维护性。

**分析要点**：
- 元素扇入/扇出（被引用数/引用数）
- 模块间依赖密度（跨包关系数 / 总关系数）
- 最大嵌套深度
- 约束复杂度（约束表达式长度/嵌套层数）
- 继承深度（generalization 层级）

**输出格式 — 复杂度指标表**：

| 指标 | 值 | 阈值 | 状态 |
|---|---|---|---|
| 总元素数 | [N] | — | — |
| 平均扇出 | [N] | ≤5 | [通过/超标] |
| 最大扇出 | [N]（[元素名]） | ≤10 | [通过/超标] |
| 跨包依赖率 | [N%] | ≤30% | [通过/超标] |
| 最大嵌套深度 | [N] | ≤4 | [通过/超标] |
| 继承深度 | [N] | ≤5 | [通过/超标] |
| 约束平均长度 | [N] 字符 | — | — |

**高扇出元素清单（扇出 >5）**：

| 元素 | 扇出数 | 被引用数 | 备注 |
|---|---|---|---|
| [元素名] | [N] | [N] | [是否可拆分] |

#### 3.7 标准合规性维度

**分析目标**：评估模型是否符合 SysML v2 规范和领域标准。

**分析要点**：
- SysML v2 关键字/语法是否正确
- 元素类型是否合法（part/item/port/requirement/use case/action/state…）
- 包层级是否符合规范（package → subpackage）
- 语义是否正确（specialization/generalization 方向、feature 定义位置）
- 领域标准合规（如航天领域：ECSS-E-ST-10C；汽车：ASPICE；通用：ISO/IEC/IEEE 15288）

**输出格式 — 合规检查表**：

| 检查项 | 标准 | 结果 | 偏差 |
|---|---|---|---|
| SysML 语法 | v2 规范 | [通过/不通过] | |
| 包层级规范 | v2 §6 | [通过/不通过] | |
| 端口定义规范 | v2 §7.12 | [通过/不通过] | |
| 需求定义规范 | v2 §7.7 | [通过/不通过] | |
| 命名规范 | [项目规范] | [通过/不通过] | |
| 领域标准 | [标准号] | [通过/不通过] | |

---

#### 3.8 风险与设计余量维度

**分析目标**：识别技术风险点，评估设计余量是否充足。

**分析要点**：
- 关键参数是否有设计余量（如功率余量、质量余量、链路余量）
- 单点故障（SPOF）识别——是否有冗余设计
- 接口兼容性风险——异构接口是否验证过
- 约束冲突——是否有相互矛盾的约束
- 未验证假设——模型中哪些假设尚未通过试验/仿真确认

**输出格式 — 风险登记册**：

| # | 风险描述 | 类别 | 严重度 | 概率 | 当前余量 | 建议措施 |
|---|---|---|---|---|---|---|
| 1 | [描述] | 技术参数 | 高 | 中 | [余量值] | [措施] |
| 2 | [描述] | 单点故障 | 严重 | 低 | 无冗余 | [措施] |

#### 3.9 变更影响维度

**分析目标**：分析关键变更的传播路径和受影响范围。

**分析要点**：
- 选取关键变更节点（高频修改/核心接口/关键需求）
- 沿 satisfy/derive/allocate/connect/flow 关系传播
- 计算影响半径（直接/间接/全链路）
- 识别变更敏感节点（变更会波及大量元素的节点）

**输出格式 — 影响传播表**：

| 变更节点 | 变更类型 | 直接影响 | 间接影响（2 跳） | 全链路影响 | 影响元素总数 |
|---|---|---|---|---|---|

#### 3.10 验证与确认维度

**分析目标**：评估模型的验证覆盖率和确认状态。

**分析要点**：
- 需求验证覆盖率（有 verify 关系的需求数 / 总需求数）
- 测试案例与需求的对应完整性
- 仿真/分析的覆盖范围
- 设计评审状态（是否经过同行评审）
- 未关闭的验证项

**输出格式 — V&V 矩阵**：

| 需求 ID | 验证方法 | 验证案例 | 验证状态 | 备注 |
|---|---|---|---|---|

| REQ-002 | 分析 | — | **未验证** | |
| REQ-003 | 评审 | [评审记录] | 通过 | |

**V&V 覆盖率统计**：

| 指标 | 值 |
|---|---|

## 使用说明

1. **复制模板**：将本文件复制为具体工程的分析报告
2. **按维度填充**：10 个维度不必全部展开，根据工程阶段和重点选取相关维度
   - 概念设计阶段：侧重 3.1 结构、3.2 需求追溯、3.7 合规
   - 初步设计阶段：侧重 3.3 架构行为、3.4 接口、3.6 复杂度
   - 详细设计阶段：侧重 3.5 一致性、3.8 风险、3.10 V&V
   - 变更阶段：侧重 3.9 变更影响
3. **表格可裁剪**：表行列数按实际情况增减，保留表头结构
4. **图示可替换**：包结构树可用实际截图或导出的 SVG 替换文本树
5. **严重度定义**：阻断（阻断流程）/严重（影响正确性）/警告（影响质量）/提示（改进建议）
