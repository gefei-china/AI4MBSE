# 知识状态机收口说明（2026-09-10）

> 米爸提问：「进入图库的数据是经过确认后的，为啥还存在这么多状态」——本文明确流转逻辑，并说明本次收口改动。

## 一、状态机（收口后）

```
【数据整理侧 · kb-b】                【图库侧 · 图谱工作区】
文档抽取
   ↓
raw_chunk（原始块，管道中间态）        手动新增实体/关系
   ↓ 用户确认候选                        ↓
candidate（候选，待审核）──────→      reviewed（已入图 = 已确认）
   ↓ 审核队列 confirm                    ↓ 合并淘汰/驳回
reviewed（入图）                    deprecated（软删留痕）
   ↓ reject / 合并淘汰
deprecated（软删留痕）
```

**核心原则：入图即确认。** 图谱工作区画布只显示 `reviewed`；`candidate` 在「数据整理·审核队列」确认后才入图；`raw_chunk` 是抽取管道中间态，从不属于图库；`deprecated` 软删留痕、永不出现在画布。

## 二、四个状态的归属界面

| 状态 | 含义 | 在哪里可见 |
|---|---|---|
| `raw_chunk` | 抽取原始块（未确认） | 数据整理管道内部（不进图库） |
| `candidate` | 候选（已确认待审核） | 数据整理·审核队列（不进画布） |
| `reviewed` | 已入图（已确认） | **图谱工作区（画布/树/详情/导出）** |
| `deprecated` | 驳回/合并淘汰（软删留痕） | 不可见（仅数据库留痕） |

## 三、本次收口改动

| 层 | 改动 |
|---|---|
| 数据层 | `graph_entities`：`all` 语义 = candidate+reviewed，`raw_chunk` 永不进图库；`graph_relations` 默认仅 reviewed |
| 数据层 | 图库内手动创建实体（GraphStore.create_node）：**创建即确认**（直接 reviewed，reviewed_by=创建人）——此前绕审核队列，与手动建关系（本就直接 reviewed）不一致 |
| 前端 | `loadGraph` 固定拉 `status=reviewed`；状态不可切换 |
| 前端 | 状态展示全删：树状态色点、详情状态徽章、画布内审核通过/驳回按钮（画布内不再有 candidate，按钮成死代码）——审核动作唯一入口 = 数据整理·审核队列 |
| 前端 | 成熟度统计卡（候选/已入图计数）改为纯展示，不再点击切换画布 |

## 四、为什么保留状态字段

抽取管道（文档 → 原始块 → 候选 → 确认入图）需要中间态支撑人机协作：AI/规则抽取的结果不能直接信任，必须经人确认。状态是**管道的进度标记**，不是图库的展示属性——本次收口后，图库侧用户看不到任何状态噪音。
