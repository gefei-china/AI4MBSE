## 0. 结论先行

**一句话**：本工程已经具备决策智能架构的全部零件（图谱事实源 / SHACL 与 survivorship 规则 / 融合闸打分 / LLM 推理 / 人在环五站），
**缺的不是引入一个新模型，而是把"打分"升级为"带置信与理由的决策建议"，并用已裁决数据训练校准模型、逐步提高自动化率**。
引入点共 5 个环节，按三阶段落地；第一阶段（纯建议展示）零风险 1~2 天，第三阶段可顺带补上需求书里真正的"决策模型"条款
**FR-MG-6 多方案打分**（★，上轮判未实现）。

**为什么是"建议制"而不是"自动决策"**：需求 7.4(e) 要求审计可追溯、FR-KG-15 要求人工评审——治理域的裁决必须人签字；
决策模型的角色是**把人从"逐条判断"解放为"复核建议"**，并通过裁决数据飞轮逐步收敛自动化边界。

## 1. 标杆调研：决策智能的四个共识

### 1.1 混合决策架构（Hybrid Decisioning）——纯 LLM 决策不可靠

2025-2026 行业共识（InRule / Salesforce Atlas / Agentic 综述）：可靠的决策系统是五层混合——

| 层 | 角色 | 本工程对应 |
|---|---|---|
| 业务规则引擎（BRE） | 确定性护栏与合规强制 | SHACL 本体约束 + 融合闸三阈值 + 发布门禁（未评审禁入 release）✅ 已有 |
| 传统 ML | 预测/打分/异常检测 | 融合闸四路相似度打分（vec/fuzzy/…）✅ 雏形已有 |
| LLM 推理 | 上下文理解、证据综合、解释生成 | DeepSeek（RAG 问答）✅ 已有，但只用于问答，未进治理裁决 |
| 知识图谱 | 结构化事实源与约束（"LLM 是推理层，图谱是事实源"） | L1 分支化图模型 + lineage ✅ 已有 |
| Agentic 编排 | 协调以上各层 | 无（远期） |

### 1.2 知识架构决定决策上限（Intelligence Warehouse 白皮书）

缺结构化知识层的生产决策系统四大失败模式：**幻觉实体 38% / 错公式 44% / 缺决策规则 72% / 权限错误 81%**；
补齐三层（业务本体 → 编码化指标 → 可执行决策规则）后生产环境决策准确率 62~73% → **98%**。
本工程对应：本体（ontology_types 52 个）✓、survivorship 规则**散在代码里未产品化** ⚠️、决策规则**未结构化** ⚠️。

### 1.3 人在环飞轮（Collaborative Learning Loop）

AI 给证据与建议 → 人复核收敛 → **裁决结果回喂训练**。本工程天然具备飞轮数据：
融合闸四路分数 + 灰区裁决结果（entity_merges 8 条起步，会持续增长）——**这是训练校准模型的免费标注**。

### 1.4 风险受控数据飞轮（CMES 2026）

企业级 LLM 决策系统的关键不是生成能力，而是"推理输出转为可观测风险信号并回喂"——
本工程 neg 域评测的 `false_graph_confident=1`（1 例图谱假自信）正是需要这种风险信号回喂的场景。

## 2. 引入环节：在哪、做什么、什么模型、什么价值

| # | 环节 | 做什么 | 模型/方法 | 价值 | 风险 |
|---|---|---|---|---|---|
| 1 | **抽取审核**（第①站） | 候选行输出「AI 建议：确认/挂靠/驳回 + 置信 + 理由」三列（融合闸分数已有，补建议列与理由生成）；高置信（≥0.92 已有 auto_merge 通道）之外，把 0.80~0.92 灰带给出倾向性建议 | 规则（已有阈值）+ LLM 证据摘要（一句话：与哪个已有实体相似、相似在哪） | 348 条积压的教训：人工逐条不可扩展。按融合闸历史分布，高置信自动 + 灰带建议可减人工 **~70%** | 低（建议制，人签字） |
| 2 | **重复消歧**（第②站） | 合并建议卡片补「AI 建议：合并/独立 + 置信」；证据摘要由 LLM 从四路分数 + 属性对比生成（现在是裸分数，人要自己解读） | 四路分数加权（LightGBM，用 entity_merges 已裁决数据训练）+ LLM 解释 | 每条裁决从"看分数猜"到"看建议复核"；一致性提升（同人不同时裁决方差下降） | 低（同上） |
| 3 | **属性融合**（第③站） | survivorship 规则（来源可靠性/新近度）产品化为「系统建议值 + 依据」——现在规则在代码里，人看不到依据 | 规则产品化 + LLM 组织依据文案 | 属性融合站至今零运转（无矛盾值场景），规则显性化后场景出现即可用 | 低 |
| 4 | **MR 发布评审**（FR-KG-15） | approve 前输出「AI 评审摘要」：变更面（added/modified/removed 已有）+ 风险提示（删除了哪些被引用实体、未评审实体、跨分支影响）+ 建议 | LLM（DeepSeek）+ 图查询（影响面用现有 diff/dependency 接口） | 评审人从"翻 diff"到"读摘要抽查"；对标 GitLab AI summary；留痕进时间线（机制昨天已建） | 中（摘要错漏需免责声明：仅供参考） |
| 5 | **多方案打分**（FR-MG-6 ★ 需求缺口） | MBSE 方案权衡：图谱承载方案（候选配置）+ 指标（需求满足度/质量属性权重）+ 评分模型输出**排序与敏感度**，人做最终决策——需求书里真正的"决策模型"条款 | 加权评分模型（TOPSIS/加权求和，指标来自图谱属性）+ LLM 生成权衡报告 | **直接补 ★ 硬缺口**；MBSE 决策支持是甲方"辅助设计"叙事的核心卖点 | 中（指标权重需甲方确认；首版做透明加权不做黑盒） |

**不引入**：GNN 图推理（数据量不够，184 实体撑不起）、全自动决策直通（7.4(e) 审计与 FR-KG-15 人工评审是需求硬约束）。

## 3. 模型选型与数据基础

| 决策点 | 首选 | 备选 | 训练/配置数据 |
|---|---|---|---|
| 消歧/抽取建议置信 | LightGBM（四路分数 + 实体类型 + 来源特征） | 加权规则（冷启动） | entity_merges + 灰区裁决记录（**8 条起步太少** → 先规则，攒 ≥50 条后训练） |
| 证据/理由生成 | DeepSeek（已有 provider，零新增成本） | 本地小模型（信创要求时） | prompt 模板 + 图查询上下文 |
| 发布评审摘要 | DeepSeek + diff/dependency 接口输出 | — | 无需训练 |
| FR-MG-6 方案评分 | 加权求和/TOPSIS（透明可解释，甲方可审权重） | AHP | 指标定义需与甲方对齐 |

**关键约束**：信创（OpEnvR）远景下模型必须可替换——所有决策模型调用走 provider 抽象（与 LLM provider 同模式），不绑死单一模型。

## 4. 分期实施路线

| 阶段 | 内容 | 工作量 | 前置 |
|---|---|---|---|
| **P0 建议展示** | 环节 1/2 的「AI 建议+置信+理由」列（规则版，零训练）；裁决采纳率埋点（飞轮数据起点） | 1~2 天 | 无 |
| **P1 评审辅助** | 环节 4 MR AI 评审摘要 + 时间线留痕（复用昨天建的 resolve/approve 留痕机制） | 1 天 | P0 埋点 |
| **P2 校准模型** | entity_merges ≥50 条后训练 LightGBM 置信模型，替换加权规则；决策建议自动化率按准确率逐步放开 | 2~3 天 + 持续 | 飞轮数据 |
| **P3 FR-MG-6** | 多方案打分原型（图谱方案建模 + 加权评分 + 权衡报告），直接补 ★ 缺口 | 3~5 天 | 指标定义与甲方对齐 |

**验收叙事价值**：FR-KG-10/FR-HIL（人机协同审核）从"人工工具"升级为"AI 辅助决策"；FR-MG-6 从未实现变原型；
7.4(e) 审计因"建议-裁决-采纳率"全留痕而更完整。

## 5. 风险与护栏

1. **错建议污染**：全部建议制起步；自动化率只按**分域实测准确率**放开（neg 域 false_graph_confident 教训：假自信必须被评测捕获）
2. **可解释性**：每条建议必须带证据与理由（给 7.4(e) 审计供料），禁止裸置信度
3. **冷启动**：标注不足期用规则版（阈值+survivorship），不硬训小样本模型
4. **信创**：模型调用全走 provider 抽象，LLM 可切本地部署（与 OpEnvR-1/3 路线一致）
5. **范围控制**：本轮只做治理域与 FR-MG-6，不做 RAG 问答的决策化改造（已有基础，另行立项）
