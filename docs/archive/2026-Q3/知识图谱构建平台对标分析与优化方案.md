## 一、v2.0 方案核心主张解读

v2.0 相对 v1.0 的三个结构性修正：

| 修正点 | v1.0 | v2.0 | 本质 |
|---|---|---|---|
| **主流程** | 文件管理→向量化→抽取→融合→审核→入图（单向） | **本体建模前置（Step 0）+ 评估回环收尾（Step 6）** | 无本体约束的抽取是"无的放矢"；无评估的审核是"过滤"不是"度量" |
| **融合次序** | 归一在前、消歧在后 | **表面归一 → 实体消歧/链接 → 跨源对齐合并 → 冲突消解** | "表面归一"（格式层）与"身份归一"（语义层）不可混淆；不先消歧（确定身份）就无法正确对齐 |
| **向量化** | 必经环节 | **降级为可选增强层**（消歧相似度辅助 + 语义检索） | 纯 KG 构建管线中向量化不是必经环节，避免 GPU/存储成本无理由前置 |

v2.0 全流程：**0 本体建模 → 1 文件管理 → 2 知识抽取（受 Schema 约束，NER/属性/关系/事件/指代消解）→ 3 知识融合（归一→消歧→对齐→冲突消解）→ 4 审核（自动初筛/人工抽检/专家终审）→ 5 入图入库（MERGE/Upsert/索引/溯源）→ 6 评估回环（Golden Set/指标看板/反馈回流）**，另加可选增强层（向量化/RAG）。

## 四、优化实施方案（P0 → P2）

> 实施原则：不动已对齐主链路（本体前置/消歧前移/审核/回流/向量化增强层全部保留），按 v2.0 补全缺失环节，全部沿用现有验证范式（tests/ 接口用例 + playwright 前端闭环）。

### P0-1 冲突消解机制（融合第四步，G1）

**目标**：对同一实体/同一三元组的矛盾事实提供「检测 → 加权裁决 → 人工确认 → 留痕」闭环。

- **冲突检测**（`entity_resolver.py` 新增 `conflict_detect(conn, scope)`）：
  - 实体级：同一实体（同名/已消歧合并组）的属性冲突（同 key 不同 value，非空且不相等的属性对）；
  - 关系级：同一三元组 (source, relation_type, target) 的属性冲突；同一对实体的互斥关系（如 CONFLICTS/优于/劣于 并存——v2.0 §2.4 案例）；
  - 输出候选冲突对 `{left, right, attr_key, v_left, v_right, evidence}`，写入新表 `knowledge_conflicts`（左/右引用 + 字段 + 两值 + 各置信度/来源/时间 + 裁决状态 pending/resolved/ignored + 裁决结果 + 裁决人/时间/依据）。
- **加权裁决**（`entity_resolver.py` 新增 `conflict_adjudicate`）：
  - 分值 = 可信度(confidence) × 0.5 + 时效性(recent) × 0.3 + 权威性(source_type/来源权重) × 0.2（v2.0 §2.4 加权思想，参数表放 `core/config.py` 可调）；
  - 分值差 > 阈值（默认 0.15）→ 自动建议采纳高分侧，标记"建议"供人工确认；分值差 ≤ 阈值 → 待人工；
  - 人工确认动作：采纳左 / 采纳右 / 保留两者（标 ignored）；裁决后对实体属性执行更新或保留，留痕 audit（`conflict_adjudicate`）。
- **前端**：标注审核 kb-b 新增「🔀 冲突消解」tab（或并入消歧合并 tab 的分区）——冲突列表（实体/三元组 + 两侧值 + 证据 + 建议徽章）+ 采纳/保留操作 + 已裁决历史。复用现有 panel/ph/pb/tag 风格与 #lbx 确认。
- **验证**：`tools/verify_conflict.py`（造冲突对 → 检测命中 → 加权建议正确 → 人工采纳留痕 → audit 记录）+ playwright 前端闭环。

### P0-2 抽取后表面归一前置（G2）

**目标**：v2.0 §2.4 第一步——提及表面归一是格式层操作，应在抽取后立即执行，不涉及身份判断。

- **归一化器**（`vector2graph.py` 新增 `_normalize_mention(name)`，复用 [entity_resolver.py](file:///c:/Users/gefei/WorkBuddy/2026-08-04-19-05-52/mbse_system/entity_resolver.py#L18-L25) `normalize_name` 全角→半角/去空白/去尾注/小写，新增）：
  - 格式统一：去除"先生/女士/尊敬"等敬语、去除尾部版本尾注（已有 `(?:改进型|优化型|方案[一二三123]|v\d+|原型|候选)$`）；
  - 别名映射：查询 glossary（术语归一化表）与既有实体 `properties.aliases`，命中 → 候选名称替换为标准名，同时保留 `original_name` 溯源字段；
  - 落库：`v2g_candidates` 新增 `normalized_name` 列，`extract_candidates` 每个候选写入，供消歧/确认复用（confirm 时以 normalized_name 做名称定位）。
- **兼容**：不改变 confirm 后实体名（实体名以 normalized_name 为准，原文存 properties.original_name），与现有消歧/合并/审核链路无缝衔接。
- **验证**：`verify_conflict.py` 附带用例（"马云先生"/"Jack Ma" 归一映射 → 候选名统一 + original_name 保留）+ 现有 v2g 回归。

### P0-3 重叠/跨 chunk 三元组去重（G3）

**目标**：v2.0 §2.2 重叠 Chunk 去重策略——chunking 90 字符重叠导致同一三元组多次抽取，抽取后去重。

- **去重器**（`vector2graph.py` 新增 `_dedup_candidates(nodes, edges)`，在 `extract_candidates` 落库前执行）：
  - 实体候选：`normalized_name + entity_type` Hash 去重，重复保留置信度最高者，其余并入 evidence（候选级，与现有 `seen_names` 机制升级）；
  - 关系候选：三元组 `(source_normalized, relation_type, target_normalized)` Hash 去重；Hash 不同但语义相似（Embedding 余弦 > 0.95，bigram 兜底）判重，保留最高置信度并记录溯源（v2.0 §2.2 语义相似度双层）。
- **验证**：构造带 90 字符重叠的文档 → 抽取候选去重计数正确 + 溯源保留；现有 v2g 回归。

### P1-1 指代消解/回指消解（G4）

**目标**：v2.0 §2.2 指代消解——代词（"他/它/该"）与回指短语（"该公司/上述机构/前述协议"）在抽取前替换为具体实体。

- **实现**（`vector2graph.py` 新增 `_resolve_coref(text, entity_hits)` 预处理，在抽取 prompt 前执行）：
  - 先跑一轮实体识别得到候选实体清单（现有抽取能力），对文本中代词/回指短语做 LLM 替换（Mock 规则兜底：句内回指最近实体名）；
  - 仅用于抽取输入，不修改原文与溯源（source_frag 仍指向原文）。
- **验证**：`verify_coref.py`（代词/回指句 → 替换后抽取三元组无"他"类无效实体）+ v2g 回归。

### P1-2 评估指标看板 + P1-3 Golden Set 分层建立（G5/G6）

- **后端**：

### P2-1 LLM 辅助本体蓝图（G9）

## 六、明确不做 / 观察项

- **事件抽取 EKG（G10）**：MBSE 领域已有 变更影响分析/验证活动/建模流程 等语义，事件节点价值需结合客户场景评估后再定，不做通用 EKG 承诺。

- **图片 OCR / API/DB 直连接入**：文件管理已覆盖主流格式，OCR 依赖外部能力，观察客户需求再补。
- **图库升级 Neo4j/Nebula**：SQLite + GraphStore 抽象已覆盖私有化工程平台场景（复用 docs/本体管理模块调研与优化方案.md §7 结论）。
- **LabelStudio 等外部标注工具集成**：自研审核 UI 已具备三层审核能力，不引入外部依赖。
