# 本体新增表单评估报告：基于 Protégé 与行业优秀案例

> 评估对象：mbse_system「本体模型 → ＋新建」滑窗表单（`onttype` modal：entity / relation / attribute 三合一）
> 评估基准：Protégé Desktop / WebProtégé / TopBraid Composer / Palantir Ontology / GraphDB / Stardog / Anzo / MagicDraw-Cameo(SysML Profile)
> 日期：2026-08-31 ｜ 结论：**整体优于 Protégé 原生表单，核心字段对齐度 ~85%，存在 3 项 P0 缺口**

---

## 一、结论（先行）

1. **当前表单模式比 Protégé 更易用**：Protégé 新建时只有 Name 一个字段，其余全靠 Description 分栏（SubClass Of / Domain / Range / Characteristics...）——面向本体专家；本产品把工程约束（必填/唯一/白名单/基数）直接收进表单，符合目标用户（系统工程师）心智。
2. **字段语义与 OWL/Protégé 对齐度 ~85%**：名称↔IRI fragment、父类型↔SubClass Of、源/目标↔Domain/Range、必填↔minCardinality 1、唯一↔Functional、白名单↔oneOf。
3. **3 项 P0 缺口**（建议本轮实施）：
   - ① 关系类型缺「关系特征 Characteristics」（Protégé 核心字段，MBSE 中"包含/部署"的传递性极常用）
   - ② 基数粒度粗（仅 1:1/1:N/N:1/N:M），缺 min..max 自定义（SysML multiplicity 语义）
   - ③ 属性行数据类型不全（缺 boolean / integer / 对象引用 ref）
4. **2 项产品独有优势**：三合一表单（entity/relation/attribute 同页切换）、属性动态行拖拽排序+必填标记 —— 优于纯本体工具，建议保留。

## 三、行业案例对照评估

| 基准 | 新建范式 | 与本产品对照 | 结论 |
|------|----------|-------------|------|
| **Protégé Desktop**（OWL 标准） | 仅 Name → Description 分栏（SubClass/Equivalent/Disjoint/Domain/Range/**Characteristics**/Inverse） | 核心语义全覆盖，但 **Characteristics（Transitive/Symmetric/Functional/Inverse Functional）未入表单**（仅编辑态 Description 有 chips） | ⚠️ 缺 P0-① |
| **WebProtégé** | 仅 label | 本产品更工程化、更重 | ✅ 合理 |
| **TopBraid Composer** | Name + SuperClass + Comment 表单 | 同构，本产品多出约束字段 | ✅ |
| **Palantir Ontology / GraphDB / Stardog / Anzo**（企业图平台） | 类=名称+描述+父类；属性=名称+**数据类型+基数+必填+唯一+枚举** | 本产品**已覆盖**（属性行 type/required + 白名单） | ✅ 对齐 |
| **MagicDraw/Cameo SysML Profile** | Stereotype 属性=名称+类型+**基数+默认值**+可见性 | 缺"默认值/可见性"，MBSE 本体场景非必需 | ⚪ 可后置 |
| 本产品独有 | 三合一表单 + 属性行拖拽 + 父子继承提示 | — | ⭐ 建议保留 |

## 四、优化方案（按优先级，明确字段）

### P0（建议本轮实施）

**P0-① 关系特征 Characteristics（对齐 Protégé 核心字段）**
- 位置：关系类型表单，`ot-domain-row` 之后新增「关系特征」区块
- 控件：复选框组（≤4 项，MBSE 常用子集）
- 字段定义：
  | 选项 | 中文 | OWL 对应 | MBSE 示例 |
  |------|------|----------|-----------|
  | `functional` | 函数式（一对一） | FunctionalProperty | 每个部件唯一归属一个分系统 |
  | `inverse_functional` | 逆函数式 | InverseFunctionalProperty | 系统唯一编号 |
  | `transitive` | 传递 | TransitiveProperty | "包含"（分系统包含部件，部件包含零件） |
  | `symmetric` | 对称 | SymmetricProperty | "互连" |
- 存储：`constraints.characteristics: ["transitive","functional"]`
- 对应编辑态 Description 已有 `ontCharChips(cons)` 渲染，表单保存后自动互通 ✅

**P0-② 基数粒度升级（min..max）**
- 位置：`ot-cardinality-row`，下拉保留 4 个快捷项 + 新增「自定义 min..max」
- 字段定义：快捷项 `1:1`→`1..1`、`1:N`→`1..*`、`N:1`→`*..1`、`N:M`→`*..*`；自定义格式 `min..max`（`*` 表示无限），如 `0..*`、`0..1`、`2..*`
- 存储：`constraints.cardinality = "0..*"`（兼容存量旧格式 1:1 等，解析时映射）
- 与 SysML multiplicity（0..* / 1..1）习惯一致

**P0-③ 属性行数据类型扩展**
- 位置：属性动态行 `pr-t` 下拉，现有 `string/date/enum/decimal/text` 基础上新增：
  | 值 | 显示 | 对应 |
  |----|------|------|
  | `integer` | 整数 | xsd:integer |
  | `boolean` | 布尔 | xsd:boolean |
  | `ref` | 引用实体（对象引用） | owl:ObjectProperty 语义，选择时联动已存在实体类型下拉 |
- `ref` 类型：属性行出现第二级下拉「目标实体类型」（复用 `populateEntityTypeSelects` 数据源），存储 `{type:"ref", ref_type:"载荷"}`

### P1（建议下一轮）

| # | 优化项 | 字段定义 |
|---|--------|----------|
| P1-1 | 字段 Protégé 术语对照 | label 加注："父类型（SubClass Of）""必填属性（min 1）""唯一属性（Functional）""源类型 FROM（Domain）"，降低术语断层 |

- 根因：图谱节点/边 `onclick` 调用 `selectOntType()` 无参 → 函数内强制 `ontView = classes/props` → `ontSyncViewPanes()` 隐藏图谱画布

- 边界：`loadOntology` 重载（新增/编辑后）在图谱视图下保持图谱；离开图谱自动清理浮层；`ontGotoType`（实例图谱→本体类型）仍按原语义跳编辑视图
- 验证：Playwright 5/5 断言（点击节点不跳转/浮层出现/到类型编辑切视图+浮层清理/重进无残留/无页面错误）
