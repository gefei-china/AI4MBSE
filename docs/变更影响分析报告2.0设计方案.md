# 变更影响分析报告 2.0 设计方案

> 版本：v1.0（2026-09-15）
> 调研范围：剑桥 CPM/变更传播学派（Clarkson/Eckert/Jarratt）、Wiegers 影响分析模板（Jama Software 采纳的工业事实标准）、IBM Rhapsody Gateway、Jama Connect 交互设计
> 关联文档：《变更影响分析报告 2.0》前端实现、《本体变更实例影响分析与自动迁移方案.md》
> 前置：变更类型感知传播矩阵（rename/value/interface/attribute/delete，见会话讨论 2026-09-15）

---

## 1. 调研结论（六条，均有出处）

| # | 结论 | 来源 | 对本设计的意义 |
|---|------|------|---------------|
| R1 | **影响分析有三面向**：理解影响 → 识别受影响元素 → 估算工作量/进度/成本；报告最终服务于 CCB 的批准/驳回决策 | Wiegers, *Software Requirements*（Jama 官方博客采纳） | 现有实现只有前半面向；报告必须补工作量估算与决策建议 |
| R2 | **标准报告模板**（工业事实标准）：CR 编号/标题/描述/分析人/日期 + 优先级估计（Benefit/Penalty/Cost/Risk 1-9 → Calculated Priority）+ 工作量表（含 lost effort）+ 受影响需求/任务/计划清单 + 决策栏 | Wiegers Impact Analysis Report Template | 直接作为静态报告（形态 B）的信息架构骨架 |
| R3 | **CPM 组合风险**：每条直接依赖挂 likelihood × impact 两维，全路径枚举（DFS，环截断）合并出任意两元素间的组合风险（direct+indirect）；路径深度经验上限 **3-4 步**（Pasqual & de Weck 航空实证：传播极少超 4 步、从未超 5 步） | Clarkson et al. 2004, Change Prediction Method | 现有 BFS 只记首达（单路径）；升级为路径枚举 + 概率合并，深度默认 3 有实证支撑 |
| R4 | **可视化三谱系互补**：风险矩阵（全局一览，Change Risk Plot：格=组合风险）｜传播网络图（路径探索：分层/放射传播树/鱼眼）｜受影响清单（成本/工作量明细）——任何单一视图都丢信息 | Hamraz et al. 2022 综述（Res Eng Design） | 报告主视图三视图切换；静态报告三者并列 |
| R5 | **元素关键度三分类**：Absorber（吸收>产生）/ Carrier（传递）/ Multiplier（放大>吸收）——告诉评审"哪些元素是变更放大器"，比单纯评分更有决策价值 | Eckert et al. 2004（航空案例） | 新增元素关键度画像章节 |
| R6 | **Jama 交互模式**：变更请求底部面板，直接关联高亮 + 下游按"分隔度（degree of separation）"标注 | Jama Connect 帮助文档 | 仪表板下游节点按深度标注分隔度（已有 depth 字段，表述对齐） |

## 2. 现状差距（对照 R1-R6）

| 维度 | 现状 | 差距 |
|------|------|------|
| 影响计算 | BFS 单路径首达，权重=关系类型×层衰减 | 缺 R3 的路径枚举与组合风险合并；影响度只有"传播强度"没有"风险"语义（likelihood×impact 两维） |
| 变更语义 | 无变更类型（上轮已设计矩阵，未实施） | R1/R3 要求变更类型定 likelihood |
| 报告结构 | 模板话术"变更描述"、无工作量/重测/决策栏 | 缺 R1/R2 的面向二、三与决策导向 |
| 可视化 | 拓扑图 + 简易热力列表 | 缺 R4 的 CPM 风险矩阵与三视图切换 |
| 关键度 | 无 | 缺 R5 |
| 归档 | 会话产物（已对齐） | 静态报告导出需对齐新结构 |

## 3. 报告信息架构（2.0）

**双形态**：形态 A 交互仪表板（分析时用，会话内预览面板）+ 形态 B 静态评审报告（归档/导出，CCB 用）。信息架构同源，渲染不同。

### 3.1 八层信息架构（静态报告顺序 = 仪表板模块）

| 层 | 内容 | 对标 |
|----|------|------|
| ① 报告头 | CR 编号（CIA-日期-序号）/ 标题 / **变更类型** / 变更描述 / 分析人 / 日期 / 关联分析记录 id | R2 模板头部 |
| ② 执行摘要 | 影响面计数（直接/间接/深度/覆盖率）+ 组合风险 Top3 + **决策建议**（批准 / 有条件批准（附条件）/ 建议细化后再议） | R1 决策导向 |
| ③ 变更上下文 | 变更内容（类型化描述）+ 沙箱预演 diff 摘要（如有） | R1 |
| ④ 风险矩阵 | 行=变更发起，列=受影响，格=组合风险热力（对标 Change Risk Plot）+ 传播深度分布 | R4 |
| ⑤ 传播路径明细 | 逐路径 from→…→to（含各步 likelihood），按组合风险降序 | R3 路径枚举 |
| ⑥ 受影响清单 + 关键度画像 | 按领域/类型分组清单；每元素标注 Absorber/Carrier/Multiplier | R5 |
| ⑦ 重测与工作量 | 需重测验证活动清单（沿 验证 关系抽取）+ 工作量估算表（Wiegers 任务清单裁剪版，行可编辑） | R1 面向三 |
| ⑧ 证据附录 + 决策栏 | 混合溯源证据 / 引用扫描结果（rename）/ CCB 决策签署栏（批准人/日期/意见） | R2 模板尾部 |

**rename 特殊形态**：④⑤ 替换为「引用更新清单」（0 结构影响声明 + 命中的需求文本/文档/词典/代码引用清单），复用上轮设计的 `scan_name_references`。

### 3.2 决策建议生成规则（② 层，规则化可解释）

```
if 高影响元素数=0 且 覆盖率<30%          → 建议「批准」（低风险变更）
elif 覆盖率≥60% 或 存在 Multiplier 受影响 → 建议「有条件批准」+ 条件（先沙箱预演 / 先补验证）
elif change_type=delete 且 触达需求层    → 建议「细化后再议」（附缺失信息清单）
else                                    → 「提交 CCB 评审」+ 风险 Top3
```
规则可解释、可配置（阈值进 settings），不做黑盒打分。

## 4. 页面布局设计

### 4.1 形态 A · 交互仪表板（会话内预览面板 / 大屏查看器升级）

```
┌──────────────────────────────────────────────────────────┐
│ 报告头条：CIA-20260915-001 · 类型:value · 描述(截断) · 分析人 │
├──────────────────────────────────────────────────────────┤
│ KPI 条：直接11 间接29 深度2 覆盖率74% 组合风险Top3 决策建议   │
├───────────────────────────────┬──────────────────────────┤
│ 主视图（tab 切换，60%）        │ 上下文侧栏（40%）          │
│ [传播网络图][风险矩阵][清单]    │ · 选中元素详情            │
│ 网络图：分层/放射布局切换       │   （影响度/路径数/画像）   │
│ 矩阵：行×列热力，点格→路径高亮  │ · 关键度画像分布          │
│ 清单：分组排序，勾选→重测清单   │ · 混合溯源证据 / 引用扫描  │
│ 缩放/拖拽/自动布局（已有）      │                          │
├───────────────────────────────┴──────────────────────────┤
│ 折叠区：传播路径明细 ｜ 重测清单 ｜ 工作量估算表              │
│ 操作条：💾保存为会话产物 🛠模拟预演 📄导出评审报告            │
└──────────────────────────────────────────────────────────┘
```

交互逻辑：三视图共享选中状态——点矩阵格 → 网络图高亮该路径 + 侧栏显示路径明细；点网络图节点 → 矩阵对应行/列高亮 + 侧栏元素详情。

### 4.2 形态 B · 静态评审报告（归档 artifact + 导出 md/pdf）

单栏纵向、打印友好；顺序 = 3.1 八层；矩阵用静态热力表；路径明细为表格；⑧ 尾部签署栏。导出复用 `report_generator`（md/pdf 管道已有）。

## 5. 实现逻辑（映射到现有代码）

### 5.1 引擎升级：CPM-lite（`services/impact_engine.py`）

```python
def analyze_graph_v2(nodes, edges, source, depth=3, direction="both",
                     change_type="attribute", change_desc="") -> dict:
    """在 analyze_graph 基础上升级：
    ① 变更类型传播矩阵：权重 = REL_WEIGHT[r] × CHANGE_MATRIX[change_type][rel_class]
       rel_class 四类：structure(组合/包含/泛化/分配) | requirement(满足/验证/追溯)
                       | flow(流/依赖/连接) | reference(引用/关联)
    ② 路径枚举：DFS 全路径（限深 4，环截断——Pasqual 实证），每路径 likelihood
       = ∏(边权重)，组合概率合并 P = 1 - ∏(1 - P_path)（CPM 合并公式）
    ③ 输出新增：
       risk_matrix: [{from, to, combined, direct, indirect, paths:[...]}]
       path_list:   [{path:[node...], likelihood, impact}]（按组合降序 Top 50）
       element_profile: {id: {out_w, in_w, profile: absorber|carrier|multiplier}}
       change: {type, desc}
    保留原 impact_nodes/edges 字段（向后兼容前端）。"""
```

- **向后兼容策略**：v2 为新函数，`analyze_graph` 保留（沙箱 before/after 继续用旧口径），会话主分析（`_card_impact`）切换到 v2。
- 关系类映射复用 REL_WEIGHT 键（中英文同表），未知类型归 reference。

### 5.2 变更类型矩阵（settings 可配）

```python
CHANGE_MATRIX = {  # 默认值，settings 表 key=impact_change_matrix 可覆盖
  "rename":    {"structure": 0.0, "requirement": 0.0, "flow": 0.0, "reference": 0.0},
  "value":     {"structure": 0.3, "requirement": 1.0, "flow": 0.5, "reference": 0.0},
  "interface": {"structure": 0.4, "requirement": 0.3, "flow": 1.0, "reference": 0.0},
  "attribute": {"structure": 0.8, "requirement": 0.5, "flow": 0.5, "reference": 0.2},
  "delete":    {"structure": 1.0, "requirement": 1.0, "flow": 1.0, "reference": 0.4},
}
```

### 5.3 引用扫描器（rename 专用，`scan_name_references`）

```python
def scan_name_references(conn, old_name: str, limit=50) -> dict:
    """四路扫描：① entities.properties 文本 LIKE ② document_chunks 内容命中
    ③ glossary 词条 ④ artifacts(kind=code) 代码注释。
    返回 {requirements:[], docs:[], glossary:[], code:[]}，供引用更新清单渲染。"""
```

### 5.4 入口与数据流

```
用户输入（自然语言变更描述）
  → cards._card_impact：LLM 抽取 {change_source, change_type, change_desc}
    （关键词兜底：改名/重命名→rename；删除→delete；参数/值/预算→value；接口/端口→interface）
  → analyze_graph_v2 → attach_evidence → 决策建议（规则引擎）
  → card（新增 change/risk_matrix/path_list/element_profile/decisions 字段）
  → 前端仪表板渲染（形态 A）
  → 「保存为会话产物」→ artifact（meta.sections 八层结构 + meta.graph）
  → 「导出评审报告」→ report_generator pdf/md（形态 B）
```

- 模拟面板 changes 增加变更类型列；simulate 的 modify 改为按矩阵权重传播（替代 ×1.3）。
- 无变更描述/类型 → 报告头标注「结构敏感性分析（未指定变更内容）」，决策建议降级为"提交 CCB 前请补充变更内容"。

### 5.5 决策建议与重测清单

- 决策建议：3.2 规则引擎（纯规则，可解释，阈值 settings 可调）。
- 重测清单：受影响元素中 `entity_type=验证活动` 直接列出；沿「验证」关系反向找验证对象；勾选后写入报告 ⑦。
- 工作量估算：Wiegers 任务清单裁剪为 MBSE 场景 8 行（模型修改/需求文本更新/接口调整/重测执行/文档同步/评审/发布/其他），行数由受影响类型分布预填，数值人工编辑，**不做自动估算**（R1 要求的是结构化清单，不是伪精确）。

## 7. 验证口径

1. rename 分析：输出"0 结构影响 + N 处引用更新清单"（N 与 sqlite 直查一致）；
2. value 分析：传播沿 满足/验证 链，组合风险 ≥ 单路径 likelihood，路径深度 ≤4；
3. 决策建议：构造三个场景（低风险/高覆盖/删除触达需求）命中三条规则；
4. 形态 B 报告：八层齐全，导出 md/pdf 可打开；
5. 向后兼容：沙箱 simulate 结果字段不变，旧卡片可渲染。
