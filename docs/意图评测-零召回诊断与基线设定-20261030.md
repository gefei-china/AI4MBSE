# 意图评测零召回诊断与基线设定（2026-10-30）

## 1. 现象

银标集（silver）三个意图召回为 0：

| 意图 | 银标召回 | 路由器实际预测 |
|---|---|---|
| `system_mgmt` | 0 / 16 | `chat`(11) / `model_release`(2) / `review`(2) / `knowledge_qa`(1) |
| `view_expansion` | 0 / 12 | `design`(10) / `chat`(1) / `architecture_skeleton`(1) |
| `model_validation_repair` | 0 / 5 | `review`(4) / `chat`(1) |

银标 macro-F1 仅 **0.2724**，远低于 gold(0.8397) / synth(0.4785)，且这三类在混淆矩阵里「预测列永远不含自身标签」——即路由器**从不输出该标签**，而非「输出错了」。

## 2. 诊断（是标注协议缺陷，不是路由器回归）

1. **阶段意图被当顶层意图打标**（`view_expansion` / `model_validation_repair`）
   `agent/intent.py` 的 `_stage_note` 明确把 `architecture_skeleton / view_expansion / model_validation_repair / trace_verification / change_safety_gate / model_release` 定义为「MBSE 建模流水线的**阶段**意图」，并指令分类器：「未明确点名某阶段时，选粗类 `design` / `review`」。
   银标器（`_intent_silver_label.py`）用 **active sub-agent 名**当候选目录，把子 Agent `view_expansion` / `model_validation_repair` 当成了顶层意图。路由器按设计把「生成 BDD 视图」折回 `design`、`修复并校验` 折回 `review`——**路由器的粗类预测其实是对的**，0 召回是 taxonomy 不匹配造出的假回归。

2. **disabled Agent + 工程查询误标**（`system_mgmt`）
   `agents` 表里 `system_mgmt` 的 `status='disabled'`。那 16 条银标样本实为「查询工程列表 / 查 projectId / 获取分支 / 拉取 mcp 工具清单」等**工程/MCP 查询**，根本不是系统管理（用户/审计/权限）。双视图标注器仍把它们判成 `system_mgmt`（重跑双视图一致标注，16/16 仍判 `system_mgmt`——证实是标注器对「平台管理」的宽口径，与路由器窄口径「用户/账号/审计」分歧）。

3. **对照证明路由器没问题**
   - gold 的 `system_mgmt` = **2/2**（语义层命中，`conf 1.0 / 0.949`）⇒ 路由器能产出 `system_mgmt`。
   - synth 的 `system_mgmt` = **13/19** ⇒ `system_mgmt` 是合法意图，问题只在 silver 误标。
   - 这 16 条样本属「路由器无对应意图、退回 chat/model_release」的**产品意图目录缺口**，非本门禁范围。

## 3. 修复

- `tools/intent_eval_snapshot.py`：新增 `INTENT_EQUIV`（阶段意图→粗类）与 `NON_ROUTING_INTENTS`（`system_mgmt`）；评分前对 `want`/`got` 做**粒度等价归一**；`system_mgmt` 仅从 silver 剔除（gold 保留其合法标签）；透传 `n_raw`（采集量，含剔除样本）。
- `tools/_intent_silver_label.py`：标注候选改用**粗类目录**，阶段意图折叠、disabled Agent 不入候选，杜绝复发（与 eval 的 `INTENT_EQUIV` 同源，单点真理）。
- `tools/verify/verify_intent_eval_ci.py`：规模闸 A1/A2 改用 `n_raw`——剔除样本仍计入「采集量」，避免阈值被排除动作误伤；修 E1 合成报告缺 `env.llm_ok` 导致自证 FAIL 的回归。
- 重跑跑批器（复用 412 条已缓存预测，**0 额外 LLM 调用**），落 `docs/评测/nightly/latest-intent-report.json`。

## 5. 残留与后续

1. 16 条 `system_mgmt` 银标样本属「工程/MCP 查询」领域，目前无对应意图（路由器退回 chat/model_release）。属产品意图目录缺口：建议要么补一个 `project_query` / `tool_invoke` 意图，要么确认这些本就该走 chat。本门禁已剔除，不影响回归判据。
2. 细粒度「阶段意图是否真被点名」精度不在本门禁范围（粒度等价归一并了），如需单独立项补指标。
3. 建议 1–6 至此全部落地（1 interrupted 自愈 / 2 failure_kind / 4 basis 回查 / 5 上下文利用率 / 6 配置面 / 3 意图评测基线）。
