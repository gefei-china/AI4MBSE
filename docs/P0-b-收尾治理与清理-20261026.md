### 两条关键澄清（避免下一个人重复踩）

1. **`capabilities` 受 23 词硬枚举约束**（`agent/registry.py::_CAPABILITIES_ENUM`）：非枚举词落库
   **静默丢弃** ⇒ 真库 caps 与 `data/modeling_nodes.json` 的 caps 不同是**正常形态**（规划里
   "SysML v2 视图展开"这类描述性词根本存不进去）⇒ **不要**按规划覆盖真库；视图专属词不在枚举内
   ⇒ 负载感知打分器对视图域**天然不区分**（实测 top-1 是 `report_generation` 0.20，
   `view_expansion` 0.00）⇒ 视图域靠**意图路由**（`view_expansion` 的 `intent_keywords`）。
2. **标定用例必须是"改述"**：照抄能力词 ⇒ 词表层直接给 1.0/0.8 ⇒ bigram 层不承重 ⇒
   **变异自证空转**（变异体照样全中）。本次第一版重标定就踩了：现行 9/9 但变异体仍 9/9
   ⇒ 自证失效；改述后现行 8/8、变异体 0/8。

## 二、两处"门禁污染仓库 / 时间炸弹"（本轮顺手挖出并根治）

### ① 变异门禁原地改产品文件 ⇒ 变异体被提交进仓库（已清除 + 加防）

`tools/verify/verify_p1_project_attribution_mutate.py` 为做变异自证，会**原地改写产品源文件**
（备份 `tmp/_mut_bak_p1/`，跑完再还原；还原逻辑本身是对的：`try/finally` + 逐字节校验）。
**运行窗口内，产品文件就是坏的。** 10-26 实测：全量回归正在跑该门禁时执行 `git add -A && git commit`
⇒ 把 `routers/sysml_versions.py` 的**变异体**（少了 `v.project_id` 优先的 COALESCE）提交进仓库
——**diff 只有一行 SQL，提交看起来完全正常，语义却是错的**。

处置：
- 新增门禁 `tools/verify/verify_no_mutation_residue.py`
  - A1 签名检查：判据**直接取变异门禁自己的 `MUTATIONS` 列表**（import 无副作用）⇒ 定义改了自动跟着改；
  - A2 已知自注入目标的注释块必须**恰好一份**；
  - A3 通用**滑窗**扫描"同一产品文件内 5 行注释窗口重复出现"（相邻副本也抓得到；
    第一版按"最大注释段"比对会漏检相邻副本，已用真实注入实证修正）。
  - 三条检查均用**真实注入**实证能判红（非空转门禁）。
- 本地 `.git/hooks/pre-commit` 拦提交（实测拦截成功）；ci.yml 在变异门禁之后接上该门禁。
- 纪律：**门禁运行期间禁止 `git add -A` / `commit -a`**。

### ② 门禁"自愈"改产品文件 ⇒ `workflows/refine.py` 注释积到 6 份（复发三次）

`verify_quality_review_wiring.py` 的自愈判断写的是 `if "plan_eval 计数" not in r_src:`，
而注入文本里**根本没有这个连续串**（注入的是 `plan_eval` + 换行 + `#   计数很低`）
⇒ 判断永远成立 ⇒ **每跑一次门禁插一份**（HEAD 里已积 6 份 + 6 个野生 `@staticmethod`）。
历史上人工清过两次（`2db6064`「判据自身有洞」、`13b049c`「清掉第二份」）——**两次都只清文件、
没修根因**。⚠️ 10-25 记的"ENOSPC 期间被重复插入 4 遍"**归因是错的**，真因是门禁自注入。

处置：门禁**只判不改**（缺/多都判红并给补法）；`refine.py` 清理回**恰好一份**（保留人工修订版
"13 次真评审 / 11-14 条有真分数"，删掉门禁注入的陈旧副本），清理后与 `13b049c` **逐字节一致**。

### ③ 门禁合成数据写死日期 ⇒ 时间炸弹

`verify_misevolution.py` 的 C2 合成数据时间戳写死 `"2026-10-19 10:00:00"`，而指标走**默认窗口**
（`window_days=7` ⇒ cutoff = now-7d）⇒ 跨过 `10-19 10:00 + 7d` 之后那批数据**滑出窗口**，
C8c 期望的 65% 变 100%（10-25 还绿、10-26 必红，**与任何改动无关，纯时间到了**）。

处置：① 合成时间戳改**相对 now**（-2h / -1h）；② C8c 期望值改为**同库现算**（失败数/总数×100），
不再拿魔法常数 65.0 当期望；③ 新增"窗口内分母=200"前置断言 ⇒ 万一口径再变，报错直接说
"合成数据滑出窗口（分母=N）"。结果 **92/2 → 95/0**。
