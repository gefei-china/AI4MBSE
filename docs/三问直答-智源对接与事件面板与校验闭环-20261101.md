## 问题三：SysML 校验失败 → 自动修复闭环

### 结论先说：**闭环的每一环都已存在，本次做的是"串起来 + 设判据"**

| 环 | 既有能力 | 本次新增 |
|---|---|---|
| 校验 | `sysml_v2_validate` → `verdict`(pass/report/block/unavailable) + 三路计数 + `n_hard` | 校验**失败时自动发事件**（钩子在 `sysml_check_tools._validate` 末尾，默认关） |
| 事件 | — | `core/events/sources_sysml.py`：Trigger ID 由**代码哈希**派生 ⇒ 同代码天然去重 |
| 修复 | `sysml_v2_autofix`：规则级改写 + **每改一条重跑校验、硬错增加则回滚该条** | handler `autofix_sysml`（`core/events/executor.py`）|
| 判据 | autofix 返回 `before/after` 的 `verdict` 与 `n_hard` | 判成功 = `after.n_hard ≤ before.n_hard` **且** `after.verdict ≠ block` |
| 回执 | — | 工单 done + `result` 存 before/after/rules/rolled_back/unfixable |

### 闭环代码路径

```
建模产出 SysML v2 代码
      ↓ sysml_v2_validate → verdict=block（硬错）
      ↓ 钩子（events.sysml_source_enabled=true 时）
ev_triggers（external_id = model + sha256(code)  ← 同一段失败代码只记一条）
      ↓ 准入（系统事件豁免白名单）+ precheck（代码非空且未超长）
ev_workitems（action=autofix_sysml，mode 快照）
      ↓ 来源切 execute 后，execute-pending
executor._h_autofix_sysml
      ├─ 取 payload.code（不读文件）
      ├─ sysml_v2_autofix → 逐条规则改写 + 自校验回滚
      └─ 判据：after.n_hard ≤ before.n_hard 且 after.verdict ≠ block
            ├─ 通过 ⇒ 工单 done，返回 fixed_code（**不落盘**）
            └─ 不通过 ⇒ 工单 failed，如实报"未修复项 + unfixable"
```

### 三条边界（原样继承既有约束，不越线）

| 边界 | 内容 | 为什么 |
|---|---|---|
| **只修语法等价** | `connector...from...to`→`connect A to B`、关键字等价、可见性前缀补全 | 这几类是**语义等价**的写法差异 |
| **涉及建模意图的绝不改写** | 类型族(part/port/item 混用)、`satisfy` 引用谁、`subject` 与 `satisfy` 二选一、`first...if` 缺条件 ⇒ 只报告 | 原文：「自动改写、尤其『改到校验通过为止』会**掩盖真实建模缺陷**」 |
| **不落盘** | 返回 `fixed_code` 但不写回模型文件 | 落盘不可逆；写回哪一版是**建模决策**，要人确认 |

### 端到端实测数据（真实 checker.jar，非模拟）

```
① 放开 sysml_check 到 execute         ok=True  registry_synced=True
② 发校验失败事件（硬错 3 条）          admitted  mode=execute
③ execute-pending 批量执行            ok=True  elapsed=10648ms
   before = {verdict: block, n_hard: 3, n_error: 3}
   after  = {verdict: pass,  n_hard: 0, n_error: 0}   ← 硬错清零，verdict 转 pass
   applied_rules = [R02_connector_to_connect]
   rolled_back   = []                                  ← 无回滚，说明改写有效
④ 工单终态                            done
```

**修复前后代码对比（实测产出）**：

```sysml
// 修复前（block/3 硬错）
connector c from a to b;
// 修复后（pass/0）
connect a to b;
```

### 为什么默认关闭（重要）

校验在 **AI 建模主链路高频执行**。若无条件发事件：
一次会话几十次失败 ⇒ 台账被灌满 ⇒ 与"少占用人的注意力"直接冲突；
且大多数失败是"LLM 下一轮自己就修好了"，不需要人/工单介入。

⇒ `events.sysml_source_enabled=False` 默认关；开启后仍靠代码哈希天然去重。

## 本轮实测抓到的 3 个真实缺陷（都已修）

| # | 缺陷 | 症状（看起来像） | 真因 |
|---|---|---|---|
| 1 | **建单只判"该不该做"，不判"能不能做"** | 面板里出现一堆必然失败的工单 | 空代码/超长代码也 admitted ⇒ 加 `precheck` |
| 2 | **`set_mode` 重建 spec 时漏带 `precheck`** | 切模式后防护**静默失效** | 重建 SourceSpec 时字段没复制全 |
| 3 | **无 hash 路由** | `#ops` 打开后所有 panel 停在"加载中"，像"功能没生效" | 本工程不用 hash 路由，必须显式 `go('ops')` |

> 第 3 条最典型：**症状与"面板没做"完全一致**，实际是**验证方式错了**。
> 这与用户记忆里「连续 4 轮栽在验证器上」同族 —— 先怀疑验证器，再判断实现。
